### 第 32 章复习要点（用户表示"有点忘了"）

按七关结构带用户复习 Hugging Face 生态：

- **一句话模型**：Hub 像仓库，模型 ID 是坐标，`SentenceTransformer` 把模型加载成本地对象，`encode()` 才是真正把文字变成向量的动作。
- **第一关最小链路**：`MODEL_ID`(str) → `SentenceTransformer(MODEL_ID, device=...)` → `model`(实例) → `model.encode()` → `embedding`(ndarray)。四个对象别搞混：模型 ID 是字符串、类是模板、实例是可推理对象、embedding 是向量。
- **下载缓存 vs 模型对象**：首次运行下载权重存磁盘缓存，之后不下载但仍要把权重读进内存；缓存跨进程在磁盘，模型对象只在当前进程内存里。
- **第二关三包分工**：`huggingface_hub` 找文件、`transformers` 提供底层模型组件、`sentence-transformers` 提供句向量高级接口。
- **第三关项目封装**（`app/embedding.py`）六件工程问题：用哪个模型、哪个设备跑、失败回退、避免重复加载（`_model` 缓存）、区分文档/查询（查询加 BGE 指令）、接 LangChain。
- **第四关迁移向量库**：改模型/预处理/归一化后必须重建索引；一致性不止"同一个模型"，还要记录模型 ID、revision、维度、预处理、归一化策略。
- **第五/六/七关**：本地调用 vs 远程调用（InferenceClient/TEI 走 HTTP）；批量输入 `(2, 768)`；独立练习 `get_embeddings_demo(texts) -> list[list[float]]`（仍未完成，属于第 32 章收尾待办）。
- **六个常见坑**：把模型 ID 当对象、以为安装包=下载模型、以为有缓存就不用加载、建库查询不同模型、以为 Hub 一定联网推理、随手开 `trust_remote_code=True`。

### 池化具体做法（用户"忘了池化怎么做的"）

- 池化要解决的问题：Transformer 给**每个 token** 各生成一条隐藏向量，但向量数据库要"一段话 = 1 条向量"，需要把多条压成 1 条。
- Mean Pooling = 逐列求平均：`([1,2]+[3,4]+[5,6])/3 = [9,12]/3 = [3,4]`。对应位置相加、再除以个数；维度不变（768 维还是 768 维）。
- 三种池化：Mean（逐维平均）、CLS（取 `[CLS]` 位置向量）、Max（逐维取最大）。BGE 模型实际用 **CLS**，不是 Mean。
- 项目里池化被 `SentenceTransformer` 封装好了，只调 `encode()` 即可。

### 锁的作用（用户问"创建锁是做什么的"）

- `_load_lock = threading.Lock()` 防止 FastAPI 多请求并发时**同时加载两份模型**。
- 双重检查（double-checked locking）：锁外第一次 `if _model is not None` 走快速路径；锁内第二次检查防止两个请求都通过锁外检查后重复加载。
- 用 `with _load_lock:` 进入临界区，同一时刻只有一个线程加载模型。

### 校验 02 文档数学推导（用户要求"检查对吗"）

- 结论：`([1,2]+[3,4]+[5,6])/3 = [9,12]/3 = [3,4]` **正确**；整篇 `02_从数字到平均池化.md` 数学无算错。
- 但发现两处概念性问题（读本机模型配置确认）：
  1. **BGE 实际用 CLS 池化，不是 Mean Pooling**。本机 `bge-small-zh-v1.5` 和 `bge-base-zh-v1.5` 的 `1_Pooling/config.json` 都显示 `pooling_mode_cls_token=True`、`pooling_mode_mean_tokens=False`。02 文档通篇讲 Mean，需补一句说明。
  2. **维度 768 只对 demo（bge-base）成立，生产用 bge-small 是 512**。`app/embedding.py` 的 `DEFAULT_EMBEDDING_MODEL = "BAAI/bge-small-zh-v1.5"`（512 维），而 demo 用 `bge-base-zh-v1.5`（768 维）。用户打印生产向量 shape 得到 `(512,)` 不是 bug。

### token 隐藏向量维度 vs 最终句向量维度（用户提问）

- 结论：BGE 模型里**完全一致**（small=512、base=768，且 `modules.json` 只有 Transformer→Pooling→Normalize 三层，无投影层）。
- 原理：池化只压缩**行数**（token 数 n→1），不改变**列数**（维度 d 不变）。`20×768 → 1×768`。
- 前提：池化后没加投影层（Dense）。若加投影层，768 可能压到 256，就不一致。判断方法：对比 `config.json` 的 `hidden_size` 和 `1_Pooling/config.json` 的 `word_embedding_dimension`，两者相等即一致。

### 平均池化数学符号（用户要求归档到 ai学习应用数学）

讲解并归档了符号的读音/意义/作用：

- 主公式 `v[j] = (1/n)·Σᵢ H[i][j]` 的符号：`H`、`H[i][j]`、`i`、`j`、`n`、`d`、`v`/`v[j]`、`Σ`、`Σᵢ`、`(1/n)`、`·`。
- 矩阵形状记号：`H ∈ R^(n×d)`、`∈`、`R`、`R^(n×d)`。
- 带掩码公式 `v = Σᵢ(maskᵢ·hᵢ)/Σᵢ maskᵢ` 的符号：`maskᵢ`、`hᵢ`、`maskᵢ·hᵢ`、`Σᵢ maskᵢ`。
- 下标口诀：`H[token][维度]` 行在前列在后；`Σᵢ` 只对 i 求和、j 固定，即"逐列求平均"。
