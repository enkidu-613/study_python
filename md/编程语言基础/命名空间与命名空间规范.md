# 命名空间与命名空间规范

> 2026-09-01 整理

## 一、什么是命名空间

**命名空间 = 一块"专属地盘"**，把相关的变量、函数、类圈在里面。外面想用它，得带上"前缀"指名道姓，就像收快递要写"XX小区 XX栋 XX室"。

没有命名空间会出什么事？两个模块都定义了 `Utils.format()`，后加载的覆盖先加载的，程序直接出 bug——这就是"全局命名空间污染"。有了命名空间，名字被隔离在各自的"房间"里，互不干扰：

- 没有命名空间：模块 A 的 `Utils` 和模块 B 的 `Utils` 在全局打架，互相覆盖
- 有命名空间：`StringUtils.format()` 和 `DateUtils.format()` 各住各家，同名也不冲突

## 二、各语言中的实现

不同语言里的叫法不一样，但思想完全相同：

| 语言 | 命名空间的实现 | 例子 |
|------|--------------|------|
| TypeScript | `namespace` / ES Module | `namespace Utils {}` |
| Python | 模块 / 包 | `import os.path` → `os.path.join()` |
| Java | `package` | `com.google.gson.Gson` |
| XML | `xmlns` | `<xsd:schema xmlns:xsd="...">` |
| C++ | `namespace` | `std::cout` |

## 三、命名空间规范（常见约定）

### 1. 用域名倒写做顶层前缀（Java / XML 圈最典型）

```java
package com.enkiud.utils;   // enkiud.com 倒过来写，全球唯一
```

### 2. 分层组织，从大到小

```python
# 项目名.模块名.子模块
from app.services.user import get_user
```

### 3. 避免裸用全局变量

能放进命名空间/模块的，不要散在全局：

```typescript
// ❌ 散落全局
function format() {}

// ✅ 圈进命名空间
namespace DateUtils { export function format() {} }
```

### 4. 命名规则

- 顶层用公司/项目/域名（PascalCase 或全小写），层级越深越具体
- 不要起 `common`、`utils` 这种一摸一样的名字，导致两个库撞车

### 5. 嵌套别太深

一般 2~3 层封顶，`a.b.c.d.e.f()` 这种链路说明设计有问题。

## 💡 一句话总结

命名空间就是给代码"上户口"——每人一个门牌号，同名不同户互不打架；命名空间规范就是"怎么写门牌号"的统一格式。
