## 1. 先看一个你已经会的程序

Language: Python · Why: 复用已经学过的语言，观察数据表示；这里不是重新选择项目技术栈。

把下面内容写进练习目录的 `representation.py`，运行 `poetry run python representation.py`：

```python
number = 13
text = "中"
encoded = text.encode("utf-8")

print(number)
print(format(number, "08b"))
print(len(text))
print(list(encoded))
print(len(encoded))
```

输出：

```text
13
00001101
1
[228, 184, 173]
3
```

你已经会变量和 `print`。这里新认识两个调用：

- `format(number, "08b")` 是 Python 内置函数调用，返回二进制文本；`b` 指二进制，`08` 要求最少八位、不足时补零。它没有把原变量换成另一种数。
- `text.encode("utf-8")` 是字符串的方法调用，返回 `bytes` 对象，即按 UTF-8 编码得到的字节序列。`list(encoded)` 展示各字节的整数值。

从上到下，先得到整数，再生成它的二进制写法；再把一个字符编码成三个字节。**字符数与字节数不是一回事。** 此例中的一个字符占三个 UTF-8 字节，不代表每个字符都占三个字节。

一个 bit（位）只能取 0 或 1；一个 byte（字节）通常指八位。`00001101` 的值是 `8 + 4 + 1 = 13`。ASCII、Unicode、UTF-8 分别涉及字符编码标准或编码方式，不是三种不同的“字体”。本轮先分清数、字符、编码后的字节，不背完整码表。

[改] 把 `text` 换成 `A`，先预测两次 `len`，再运行。输出都为 1；改回 `中` 又成为 1 和 3。不要用汉字例子的规律猜所有输入。

原课程从数据表示与问题求解进入程序设计，参考 [Week 0](https://cs50.harvard.edu/x/weeks/0/)。这就是你会写 Python 之后仍值得学 CS50x 的原因之一：同一个值如何表示，会影响文件、网络和程序之间怎样交换它。

## 2. 为什么要接触 C

你不必把职业方向改成 C。C 会让你直接面对编译、固定类型、数组和内存地址，而 Python 替你处理了其中很多细节。

Language: C · Why: 本节解释官方课程里的编译和类型，Python 不能替代这个观察；无需为这一个例子更换主项目语言。

将下面保存为 `sum.c`：

```c
#include <stdio.h>

int add(int left, int right)
{
    return left + right;
}

int main(void)
{
    int result = add(2, 3);
    printf("%i\n", result);
    return 0;
}
```

在官方 [cs50.dev](https://cs50.dev/) 环境可以跟随课程使用 `make sum`，再运行 `./sum`。本机如果已有 C 编译器，可以改用：

```bash
cc -std=c11 -Wall -Wextra sum.c -o sum
./sum
```

第一条将源文件编译为当前目录中的 `sum` 程序，第二条才执行；预期输出 `5`。`-o sum` 指定输出名，`-Wall -Wextra` 打开常用警告；命令失败后不要继续把旧产物当作新结果。

本机没有编译器或遇到 Xcode 许可提示时，先使用官方环境，不为热身盲目安装一套工具。官方环境登录、网络访问和课程专用工具是否可用，需要你实际确认。

按执行顺序看代码：

1. 编译器读取 `#include <stdio.h>`，取得标准输入输出库的声明，知道如何检查 `printf` 的调用。
2. 系统启动程序，经运行时进入 `main`。`int main(void)` 表示本例入口不接收参数，返回整数状态。
3. `main` 调用 `add(2, 3)`，参数是两个 `int`；函数返回 `5`。
4. `result` 保存返回值，`printf` 按 `%i` 显示整数；`\n` 换行。
5. `return 0` 表示本次程序正常结束，不是输出字符 `0`。

`int` 在这里是 C 的整数类型，不是 Python 的 `int()` 转换调用。源代码、编译后的程序、程序运行时的进程，是不同的东西。关于 C、编译与类型的官方范围见 [Week 1](https://cs50.harvard.edu/x/weeks/1/)。

## 3. 内存为什么值得学

再看 `address.c`，只在完成上一节后运行：

```c
#include <stdio.h>

int main(void)
{
    int document_id = 1;
    int *selected = &document_id;
    *selected = 42;
    printf("%i\n", document_id);
    return 0;
}
```

编译命令将输入名与输出名分别换成 `address.c`、`address`，再执行 `./address`，输出 `42`。

- `document_id` 是一个整数变量。
- `&document_id` 取得这个变量的地址。
- `int *selected` 声明一个指向整数的指针变量，初始化时保存该地址。指针是一种保存地址的值，不是另一个完整整数副本。
- 赋值语句里的 `*selected` 访问该地址处的整数，所以改变的是 `document_id`。

声明中的 `*` 与表达式里的 `*` 用法不同。这里先识别“取得地址”和“通过地址访问”两步，不要求现在掌握动态内存分配。

它也不意味着 Python 的每个变量都能照搬成 C 指针操作。两个语言的对象、类型和内存管理规则不同，不能因为代码看起来像就套用。

[追踪] 将最后的赋值改为 `document_id = 8;`，不执行原来的 `*selected = 42;`。最后打印 `*selected` 会是多少？运行核对它仍在访问同一个整数位置。

官方 [Week 4](https://cs50.harvard.edu/x/weeks/4/) 会继续讲地址、动态分配、错误访问和文件；[Week 5](https://cs50.harvard.edu/x/weeks/5/) 再用内存组织数据结构。不要用这两个小实验替代那两周的练习。

## 5. 每周实际做什么

1. 打开当周页面，先看本周主题和官方 Notes。Lecture 是主课，Section 和 Shorts 可帮助拆解卡住的细节。
2. 选择一段课堂代码，运行、追踪、改变一个条件，再解释结果。
3. 进入该页链接的 Problem Set（问题集），按题目给出的环境和要求独立实现。不只阅读别人的解答。
4. 出错时记下最小失败输入、预期结果、实际结果和修改理由。修好后重跑正常及失败情况。
5. 能解释关键步骤后再进入下一周；看完视频本身不是通过证据。

这是对官方“Lecture → Section/Shorts → Problem Set”路线的中文使用说明；正式提交还需遵守[学术诚信规则](https://cs50.harvard.edu/x/honesty/)。本篇小实验不是任何问题集的标准答案。

已经会 Python、SQL 或前端时，可以少花时间看重复语法，但仍要完成与理解目标匹配的练习。C 的新语法暂时慢一点很正常；卡在语法不代表你此前的 Python 不会了。

## 7. 到这里你可以怎么检查自己

- 不看代码，解释 `13`、二进制文本、一个中文字符、UTF-8 字节分别是什么。
- 指出 `sum.c → 编译 → sum → 运行进程 → 输出` 每步发生什么。
- 说出指针实验为什么输出 42，并说明为什么不能把它直接等同于 Python 变量赋值。
- 给出一项你会用 Python 写、但还想通过 CS50x 理解内部机制的问题。

这些只证明本篇导学理解，不代表整个 CS50x 已学完。
