# 04 算法：查找、排序与复杂度

> 前置：完成 03 章；会读 Python 的列表、循环、条件、函数和字典。
> 本章产物：能解释文档目录中一次查找要检查多少条记录，并用可复现的计数比较查找方案。

## 先看问题

目录当前是一个 Python 列表。用户要按标题找到文档：

```python
documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]
```

如果目标在最后，程序需要逐条看过前面的记录。记录变成一百万条时，代码仍然正确，但工作量可能明显变大。我们先数“看了几条”，再谈时间复杂度；这里不需要先会高等数学。

## 线性查找：逐条检查

下面是完整程序。保存为 `examples/cs-foundations/04_search_sort.py`。

```python
documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]


def linear_find_by_title(items, wanted_title):
    """返回 (找到的记录或 None, 检查记录数)。"""
    checks = 0
    for item in items:
        checks += 1
        if item["title"] == wanted_title:
            return item, checks
    return None, checks


for title in ("HTTP", "Missing"):
    result, checks = linear_find_by_title(documents, title)
    print(f"{title}: {result}; checks={checks}")
```

从仓库根目录运行：

```bash
cd examples/cs-foundations
poetry run python 04_search_sort.py
```

已激活独立 Python 环境时，也可以运行 `python 04_search_sort.py`。
本程序只读内存中的固定数据，不访问网络或真实业务库。

预期输出：

```text
HTTP: {'id': 2, 'title': 'HTTP', 'owner_id': 7}; checks=2
Missing: None; checks=3
```

### 一步一步追踪

1. `for item in items` 先把第一条记录交给循环变量 `item`。
2. `checks += 1` 在比较前计数，所以计数正好表示检查了几条。
3. Python 字符串相等比较确认标题不匹配后，循环取下一条。
4. 第二条的标题是 `HTTP`，函数立即返回该字典和数字 `2`。
5. `Missing` 不匹配任何标题；循环结束，函数返回 `None` 和 `3`。

`None` 是 Python 表示“这里没有对象/结果”的特殊值。调用者检查返回的 `result`，就知道是否找到；第二个返回值是本程序自己记录的比较次数，不是 Python 自动提供的性能指标。

若命中位置不同，检查次数会不同；若目标不存在，必须检查全部 `n` 条。这里的 `n` 专指列表中记录的数量。最多检查 `n` 次，所以工作量随着记录数大致成正比，记为 **O(n)**（读作“大 O 的 n”）。`O(...)` 是规模增长的简写，不是秒数，也不承诺机器运行时间。

## 先排序，再二分查找

如果标题已经按字母顺序排列，可以检查中间项：目标较小，就只保留左半边；目标较大，就只保留右半边。每次检查都把候选范围约减半。这称为**二分查找**（binary search）。

它依赖一个关键前提：传入的数据已经按同一个标题规则排好序。若对未排序列表直接二分，程序可能漏掉明明存在的项目。

下面的实现每轮检查一个中间位置，用 `low` 和 `high` 表示仍可能包含答案的闭区间。返回值同样是“记录或 `None`，检查次数”。保存为同目录下独立的 `04_binary_search.py`，用 `poetry run python 04_binary_search.py` 运行，不要与前一个完整程序直接拼接：

```python
documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]


def binary_find_by_title(sorted_items, wanted_title):
    low = 0
    high = len(sorted_items) - 1
    checks = 0

    while low <= high:
        middle = (low + high) // 2
        item = sorted_items[middle]
        checks += 1

        if item["title"] == wanted_title:
            return item, checks
        if item["title"] < wanted_title:
            low = middle + 1
        else:
            high = middle - 1

    return None, checks


by_title = sorted(documents, key=lambda item: item["title"])
for title in ("HTTP", "Missing"):
    result, checks = binary_find_by_title(by_title, title)
    print(f"{title}: {result}; checks={checks}")
```

输出：

```text
HTTP: {'id': 2, 'title': 'HTTP', 'owner_id': 7}; checks=2
Missing: None; checks=2
```

### 追踪一个未命中

排序后的标题依次为 `HTTP`、`Python`、`SQL`。

1. 查找 `Missing`，先看中间项 `Python`。`Missing` 按字符串顺序小于它，丢弃中间项及右半边，令 `high = 0`。
2. 剩余区间只有 `HTTP`，再比较一次；`Missing` 大于 `HTTP`，令 `low = 1`，区间变空。
3. `low` 大于 `high`，循环结束，返回 `(None, 2)`。

这里排序用的是 Python 内置函数 `sorted()`：输入是可迭代对象（本例为列表），`key=` 指定每条记录用什么值排序，返回一份新列表，原来的 `documents` 不会因此改顺序。`lambda item: item["title"]` 是一个接收记录、返回标题的小函数；它是 `sorted()` 调用的排序键函数。

Python 官方保证 `sorted()` 稳定：排序键相同的记录，相对顺序仍保持原样。比如两份文档标题相同，这个性质不替你决定哪份“正确”，也不会自动去重。

排序不是免费的。比较 `sorted()` 加二分查找的总工作量，包括排序，典型规模增长是 **O(n log n)**；只对已经排好序的数据做二分，查找工作量才是 **O(log n)**。若只查一次，先排序可能比直接线性查找更费事；若目录保持有序并反复查找，排序成本可由多次查找分摊。这里的排序阶数描述的是常见比较排序的增长量级，不是对每种输入的精确比较次数承诺。

## 复杂度只记够用的几种

`O(1)` 表示操作次数大致不随 `n` 增长，例如访问非空列表中已知下标 `items[0]`；`O(n)` 表示随记录数成正比，例如完整线性查找；`O(log n)` 表示每次将候选规模缩小固定比例，例如二分查找。本章计数单位是“检查一条记录”，先把标题长度视为固定；若标题本身也越来越长，一次字符串比较的成本也要单独考虑。

另外两个常见量级：`O(n log n)` 常见于比较排序；`O(n²)` 常见于对每一条记录都再扫描全部记录的双重循环。它们都描述规模变大时工作量如何增长，不直接代表耗时。

| 记录数 n | O(1) | O(log n) 的直观量级 | O(n) | O(n log n) 的直观量级 | O(n²) |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 10 | 约 1 | 约 4 次减半 | 10 | 约 33 | 100 |
| 1,000 | 约 1 | 约 10 次减半 | 1,000 | 约 10,000 | 1,000,000 |
| 1,000,000 | 约 1 | 约 20 次减半 | 1,000,000 | 约 20,000,000 | 1,000,000,000,000 |

表中是帮助比较增长趋势的约数，不是精确执行步数。`log₂(n)` 可以先理解为“规模大约能连续减半多少轮”：一百万约等于 2 连乘 20 次，所以缩小到很少的候选项只需约 20 轮。不要求先背对数公式。

精确的中点检查次数还取决于取整、是否命中和最后一个候选项；例如本实现对 8 条记录的某些查询会检查 4 个中点，并不能把“减半轮数”直接当严格上限。本章用实际 `checks` 验证，先抓住增长速度，不在这里展开数学证明。

## 用字典按键查找

若需求是“给定唯一 id 找记录”，可以把 id 映射到记录：

下面是独立的 `04_dictionary_lookup.py`，仍明确拒绝重复 ID：

```python
documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]

documents_by_id = {}
for item in documents:
    if item["id"] in documents_by_id:
        raise ValueError(f"重复文档 id: {item['id']}")
    documents_by_id[item["id"]] = item
result = documents_by_id.get(2)
print(result)
```

运行 `poetry run python 04_dictionary_lookup.py`，输出 `{'id': 2, 'title': 'HTTP', 'owner_id': 7}`。`dict` 是 Python 内置字典类型；这里的循环逐条读 `documents`，用 `id` 作键、整条记录作值。`get(2)` 是字典实例的方法，调用者是 `documents_by_id`；输入键 `2`，返回对应记录，键不存在时默认返回 `None`。与 `documents_by_id[2]` 不同，后者缺少键会抛出 `KeyError`。

字典按键查找通常具有平均 **O(1)** 的表现，并非所有输入都绝对一步完成；多个键映射到同一查找位置的哈希冲突等因素会增加成本。建立字典本身还要遍历输入并占用额外内存，新增键时也可能发生扩容，不要把这些维护成本混同于一次查找。字典也不适合直接按标题找多条重复记录，除非你先定义好“一个标题对应多条记录”的值结构。

## 计数比计时更适合本章

用秒表测很小的函数容易被电脑负载、缓存、解释器启动和计时精度影响。同一段程序重复运行，数字可能变化。上面的 `checks` 数的是算法执行的关键比较次数，给定输入就会得到相同结果，因此很适合验证“输入规模增加时，算法多做了什么”。

计数不代表真实耗时：比较字符串和比较整数成本可能不同，内存缓存与系统负载也会影响运行速度。需要优化实际应用时，先定义代表性输入，再用计时和性能分析工具测量；本章只判断增长趋势。

## 失败和边界

线性查找可处理任意顺序；找不到时检查全部项目并返回 `None`。空列表会返回 `(None, 0)`。

二分查找的空列表也能安全返回 `(None, 0)`，但它要求已排序。常见错误是排序用 `title`，比较时却用另一个字段，或排序后又修改标题；这都会破坏前提。

如果标题重复，当前二分函数返回其中任意一个匹配项，不保证第一个或最后一个。遇到重复输入时，必须先定义契约（例如返回所有匹配项，或返回最小 id），再实现和验证；不能假设二分自动解决重复值。

`sorted()` 的 `key` 应返回相互可比较的值。若同一键里混有无法比较的类型，排序会报错；先统一数据类型或明确缺失值规则。

### 独立做：重复标题的目录查询

业务需求：实现 `find_all_by_title(items, wanted_title)`，返回所有标题匹配的记录以及比较次数。输入数据使用本章固定目录，并另加一条重复标题记录。

允许使用：列表、循环、条件、函数、`sorted(..., key=...)` 和本章的显式二分区间。不要调用 `bisect`，也不要用第三方库。

运行命令仍是从仓库根目录先 `cd examples/cs-foundations`，再用 `poetry run python 文件名.py`；独立已激活环境可用 `python 文件名.py`。

验收标准：两个重复标题都返回；不存在的标题返回空列表；结果顺序符合你写在函数说明中的约定；计数可重复；传入未排序输入时，你的函数仍按契约工作（可自行在函数内排序，并说明排序成本）。

失败时先检查：区间是否覆盖重复项；找到一项后是否继续查找；计数是在比较前还是比较后；排序键和查找比较规则是否一致。
