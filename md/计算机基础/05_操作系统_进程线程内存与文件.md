# 05 操作系统：进程、线程、内存与文件

> 前置：03 章的 Python 程序基础；04 章的文档目录示例。
> 本章产物：能区分程序、进程和线程，观察父子进程、共享变量与文件读写的边界。

## 从一次目录查询开始

想象我们运行一个程序，读取文档目录、按标题找记录，然后把结果保存下来。目录在 Python 代码里看起来像列表和字典，但运行时它们占用内存；程序正在运行时，操作系统为它安排执行。若我们另启动一个 Python 程序，那不是同一个正在运行的执行实例。

固定业务数据仍是：

```python
documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]
```

## 程序、进程和 PID

把 Python 文件保存为 `examples/cs-foundations/05_processes_threads_files.py`。这段完整程序用标准库 `subprocess` 创建一个子进程，再收集它写到标准输出的文字：

```python
import os
import subprocess
import sys

parent_value = "父进程的普通变量"
child_code = (
    "import os; "
    "parent_value = '子进程自己的普通变量'; "
    "print(f'child pid={os.getpid()} value={parent_value}')"
)

print(f"parent pid={os.getpid()} value={parent_value}")
completed = subprocess.run(
    [sys.executable, "-c", child_code],
    capture_output=True,
    text=True,
    check=True,
)
print(completed.stdout.strip())
print(f"parent still has: {parent_value}")
```

从仓库根目录运行：

```bash
cd examples/cs-foundations
poetry run python 05_processes_threads_files.py
```

已激活独立 Python 环境时，也可运行 `python 05_processes_threads_files.py`。程序只在本机启动一个短暂的 Python 子进程，不访问网络，也不更改业务数据。

输出形状如下；PID 是操作系统分配的数字，每次运行会变：

```text
parent pid=41001 value=父进程的普通变量
child pid=41002 value=子进程自己的普通变量
parent still has: 父进程的普通变量
```

### 跟着创建过程走

1. `os.getpid()` 是从标准库 `os` 导入的函数；当前 Python 进程调用它，返回当前进程标识符（PID）。
2. `subprocess` 是 Python 标准库，用来启动和管理其他程序。`subprocess.run()` 是它的函数；本例把当前解释器路径 `sys.executable`、`-c` 和一段代码作为参数，启动另一个 Python 进程并等待它结束。
3. 子进程运行自己的代码、得到自己的 PID，并打印自己的 `parent_value`。
4. `capture_output=True` 让 `run()` 捕获子进程输出；`text=True` 将输出作为文本；`check=True` 在子进程以错误状态退出时抛出异常。
5. `run()` 返回一个 `CompletedProcess` 实例，赋给 `completed`；其 `stdout` 属性是子进程捕获的标准输出。
6. 父进程的普通变量仍是原来的字符串。子进程变量同名，但不是一个可以互相改动的共享变量。

**程序**是写下来的指令；**进程**是程序被操作系统启动后的一次运行。PID 是操作系统用于识别进程的数字，不是永久用户 ID，也不应拿来当业务文档编号。一个程序可以被启动多次，每次运行都有各自的进程身份和运行状态。

上述标准库 API 的任务边界：`subprocess.run()` 适合启动一个外部命令并等待结果；它不等于 Python 函数调用，也不自动共享父进程变量。若只需调用同一程序内的函数，直接调用函数更简单；若需要同进程里多个执行路径协作，再考虑线程。

## 线程：同一进程里的多个执行路径

**线程**是进程中的执行路径。一个进程可以有多个线程；它们共享该进程的地址空间，也就是同一进程里可访问的对象和变量。共享有用，但同时改同一个值时需要协调。

`threading` 是 Python 标准库。本例从中导入 `Thread`（线程对象的类）和 `Lock`（创建互斥锁对象的入口：Python 3.12 中为工厂函数，3.13 起为类）。两种版本都可用 `Lock()` 得到锁对象。主线程创建两个 `Thread` 实例，`start()` 启动其目标函数；`join()` 让主线程等待对应线程结束。锁用于保证一次只有一个线程进入更新共享值的那几行。

把以下完整代码单独保存为 `05_threads.py`，放在同一练习目录：

```python
from threading import Lock, Thread

counter = 0
counter_lock = Lock()


def add_many_times():
    global counter
    for _ in range(10_000):
        with counter_lock:
            counter += 1


workers = [Thread(target=add_many_times) for _ in range(2)]
for worker in workers:
    worker.start()
for worker in workers:
    worker.join()

print(counter)
```

输出：

```text
20000
```

这段代码中 `counter` 只有一个，共享给两个线程。`Lock()` 创建锁实例；`with counter_lock` 进入锁保护区，代码块结束时释放锁，即使块中途抛异常也会退出保护区。`counter += 1` 是读取、计算、再写回的一组操作；不应假定多线程下这组操作天然不可分割。锁让每次更新完整完成后，另一个线程才能执行更新。

`global counter` 告诉函数要重新绑定模块级的 `counter` 名称；它不会创建新的共享变量。两条线程调用同一个 `add_many_times` 函数，输入不含参数，结果通过更新共享变量呈现。主线程对每个线程调用 `join()`，之后读取最终值。

删掉 `with counter_lock` 后，这个短例子可能仍然打印 20000；也可能因运行环境、执行时序和实现差异而出现丢失更新。**不要把非确定性竞态写成必现演示。**锁的价值是明确保护共享状态，而不是保证未加锁的短代码每次都错。

## 同步、异步、并行不是同一回事

**同步**：调用方在当前步骤等待结果后再继续。`subprocess.run()` 是此类接口：它等待子进程结束。

**异步**：发起可能等待的工作后，程序可以先处理其他事情，之后再接收完成结果。Python `asyncio` 通过 `async`/`await` 提供一种异步编程接口；它不自动意味着用了多个 CPU 核心。本章只需要分清词义，不实现异步目录服务。

**并行**：多个执行路径在同一时刻真正同时运行，通常需要多个处理核心或合适的运行时支持。并发表示一段时间内有多个工作在推进，未必同一瞬间执行。

在常规 **CPython**（Python 的一种常见实现）构建中，全局解释器锁 GIL 限制同一解释器一次只有一个线程执行 Python 字节码；线程在等待文件、网络等 I/O 时仍可能让其他线程推进。因此，线程常用于同时等待多个 I/O 操作，但不能简单承诺纯 Python 计算会因多线程而在多核上并行加速。

这是实现和构建配置相关的说明，不是所有 Python 实现的永恒规则。CPython 从 3.13 起提供可选的 free-threaded（无 GIL）构建；扩展模块也可能影响运行时是否启用 GIL。课程面向 Python 3.12+，故不把 GIL 当作线程安全锁，也不据此给所有 Python 版本下绝对结论。无论 GIL 如何，共享可变数据时都应按明确的同步规则编程。

## 内存和赋值

进程运行时，局部变量、列表、字典、函数等 Python 对象会由运行时管理并占用内存。进程退出后，这些普通内存状态不会自动成为下次启动时可读的文件或数据库记录。

赋值通常是让另一个变量名指向同一个对象，不是复制对象：

```python
documents = [{"id": 1, "title": "Python", "owner_id": 7}]
alias = documents
alias[0]["title"] = "Changed"
print(documents[0]["title"])
```

输出：

```text
Changed
```

`alias = documents` 后两个名字引用同一个列表，所以通过 `alias` 改元素，`documents` 看到相同变化。需要复制时要明确选择复制方式，并考虑嵌套对象；本章不展开复制策略。

Python 变量不是 C 语言指针的同义词。可以用“名字关联到对象”理解赋值，但不要把 Python 对象生命周期、地址和引用规则硬套成 C 指针操作。本章不要求手动分配或释放内存。

## 文件：把数据留到进程之外

**内存不是持久化存储。**要让简单文本在程序退出后仍可读取，可以写入文件。下面用标准库 `tempfile` 创建临时目录，用 `pathlib.Path` 表示路径并读写文件。临时目录在程序结束时清理，所以实验安全、自含，不在项目目录留下数据文件。

`TemporaryDirectory` 是 `tempfile` 模块提供的上下文管理器类；它创建临时目录，`with` 块结束时清理目录。`Path` 是 `pathlib` 的路径类；`write_text()` 和 `read_text()` 是路径实例方法，分别写入文本和读回文本。它们接收文本内容/编码，写入返回写入字符数，读回返回字符串。

保存为 `05_files.py`：

```python
from pathlib import Path
from tempfile import TemporaryDirectory

documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]

with TemporaryDirectory() as temporary_folder:
    output_path = Path(temporary_folder) / "directory.txt"
    lines = [f"{item['id']}\t{item['title']}\t{item['owner_id']}" for item in documents]
    output_path.write_text("\n".join(lines), encoding="utf-8")

    print(output_path.name)
    print(output_path.read_text(encoding="utf-8"))
```

输出：

```text
directory.txt
1	Python	7
2	HTTP	7
3	SQL	9
```

运行方式仍从仓库根目录开始：`cd examples/cs-foundations`，再运行 `poetry run python 05_files.py`；独立激活环境运行 `python 05_files.py`。这段程序只写临时目录，离开 `with` 块后该目录会被清理。

### 路径、文件描述符和权限

路径是定位文件系统对象的名称，例如 `reports/directory.txt`。`Path` 帮助组合和操作路径，但路径不等于文件内容，也不保证路径一定存在或调用者一定有权限。

操作系统用文件描述符（file descriptor，文件描述符）等机制跟踪已打开文件。`Path.read_text()` 和 `write_text()` 帮我们完成打开、读写、关闭等常见步骤，不要求本章直接操作底层描述符。文件权限决定当前用户能否读取、写入或进入目录；出现 `PermissionError` 时，应检查路径、所属用户和必要权限，找合适的可写目录，而不是盲目提升权限。

对手动打开的文件，使用 `with open(path, ...) as file:` 可在代码块结束时关闭文件。关闭文件是资源管理，不代表“任何东西都自动写进永久存储”：仍要执行写入；系统故障、硬件缓存、文件系统和应用自身的持久化策略也会影响何时数据真正落盘。`write_text()` 完成调用后可以读回验证，但这不是断电持久性保证。

进程意外终止时，未完成的 Python 变量会丢失；已经写入的文件内容则取决于写入和系统状态，不能简单说“进程一死文件必然没保存”，也不能承诺刚写的数据绝对已落盘。数据库事务、同步策略与崩溃恢复属于后续内容。

## 安全边界和常见误区

- 不要用 `sudo` 绕过文件权限问题；先确认目标目录和运行用户。
- 不要用 `chmod 777` 把所有用户的读写执行权限都打开；按最小必要权限处理。
- 不要用 `killall` 结束一类进程；辨认具体 PID 和程序，并先了解影响。
- 子进程不是线程：普通 Python 变量不会因为同名而自动互通。
- 线程共享进程内对象；需要一致的共享状态时，要保护读写过程，而不是期待时序碰巧正确。
- 文件路径不是内容；内存中的对象也不会因为变量名叫 `documents` 就自动保存。

### 独立做：保存一次目录查询结果

编写 `05_directory_snapshot.py`：在固定的三条目录数据中筛出 `owner_id == 7` 的记录，将 `id` 与 `title` 写入临时文本文件，然后读回并打印。要求保留纯 Python 函数完成筛选；只用标准库 `pathlib` 与 `tempfile` 做文件操作。

验收：输出只含 Python 和 HTTP 两条；在 `with` 块内能读回刚写入的内容；退出块后临时目录清理；程序不启动外部服务、不连网、不修改真实业务库。不要加入子进程或多线程，它们不是完成这个需求所需的工具。

失败时先检查：筛选条件是否比较了 `owner_id`；写入与读回是否使用同一路径；文件编码是否一致；打印动作是否发生在临时目录清理前。
