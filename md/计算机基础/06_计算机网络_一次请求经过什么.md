## 本章目标

你已经会用 Python、FastAPI 和 RAG，但“发出一个请求”背后的网络步骤可能还没有连起来。本章把一次读取知识文档的请求从地址一路追到服务器响应。

贯穿数据固定为：

```text
documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]
```

本章会搭一个只监听本机的教学 HTTP 服务器，客户端读取 `/documents/1`，再请求一个不存在的路径。它不连接公网、不改真实业务数据、不调用 API，也不做身份认证。

读完应能解释：URL 中域名、IP 和端口的关系；浏览器或程序怎样通过 DNS、路由、TCP、TLS（若为 HTTPS）到达服务；HTTP 请求和响应是什么；为什么超时不等于服务端没处理。

## 先看一条真实可跑的本地链路

将下面完整代码保存为 `examples/cs-foundations/network_request.py`。它只用 Python 标准库，适用于 Python 3.12 及以上版本。

```python
import json
import re
import threading
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from urllib.error import HTTPError
from urllib.request import urlopen

DOCUMENTS = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]


class DocumentHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        match = re.fullmatch(r"/documents/(\d+)", self.path)
        document_id = int(match.group(1)) if match else None
        document = next(
            (item for item in DOCUMENTS if item["id"] == document_id), None
        )

        if document is None:
            status = 404
            payload = {"error": "document_not_found"}
        else:
            status = 200
            payload = document

        body = json.dumps(payload).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, format, *args):
        pass


server = ThreadingHTTPServer(("127.0.0.1", 0), DocumentHandler)
server_thread = threading.Thread(target=server.serve_forever)
server_thread.start()

try:
    base_url = f"http://127.0.0.1:{server.server_port}"

    with urlopen(f"{base_url}/documents/1", timeout=3) as response:
        document = json.loads(response.read().decode("utf-8"))
        print(f"GET /documents/1 -> {response.status}: {document['title']}")

    try:
        with urlopen(f"{base_url}/documents/999", timeout=3) as response:
            response.read()
    except HTTPError as error:
        with error:
            error_body = json.loads(error.read().decode("utf-8"))
            print(f"GET /documents/999 -> {error.code}: {error_body['error']}")
finally:
    server.shutdown()
    server.server_close()
    server_thread.join()
```

在仓库根目录执行：

```bash
cd examples/cs-foundations
poetry run python network_request.py
```

如果你已经激活了独立 Python 环境，也可以在该目录运行 `python network_request.py`。练习目录已提供说明文件；`network_request.py` 由你按上面完整例子创建。

精确输出：

```text
GET /documents/1 -> 200: Python
GET /documents/999 -> 404: document_not_found
```

## 逐步追踪：谁调用谁

### 1. 服务端先在本机开门

`http.server` 是 Python 标准库模块，不需安装。这里从中取得 `BaseHTTPRequestHandler` 和 `ThreadingHTTPServer`：前者是处理 HTTP 请求的基类，后者创建一个用线程处理请求的服务器实例。

`DocumentHandler` 是我们定义的类。服务器收到连接后创建处理器；处理器继承的基类逻辑解析请求行和头部，再按 HTTP 方法名调用它的 `do_GET()`。这个方法不是我们直接调用的。基类把请求路径放在实例属性 `self.path` 中。

`server = ThreadingHTTPServer(("127.0.0.1", 0), DocumentHandler)` 创建服务器对象。地址 `127.0.0.1` 是本机回环地址，只能从当前机器访问；端口 `0` 让操作系统选择可用端口，实际端口随后可从 `server.server_port` 读取。这里用随机可用端口，避免占用固定端口或和其他服务冲突。

`server.serve_forever()` 会持续接收连接，所以放进 `threading.Thread` 创建的线程中。主线程仍可运行客户端代码。`threading.Thread` 是标准库类；我们创建 `server_thread` 实例并调用它的 `start()`，让目标函数在另一个线程里执行。

最后用 `try/finally` 收尾：`shutdown()` 请求服务循环停止，`server_close()` 关闭监听套接字，`join()` 等服务器线程结束。即使客户端部分抛出错误，清理步骤仍会运行。

### 2. 客户端发 GET，服务端挑数据

`urllib.request` 是 Python 标准库中的 URL 请求接口。`urlopen(url, timeout=3)` 创建并发起请求，返回响应对象；`with` 在离开代码块时关闭响应对象。这里的输入是本机 URL，返回对象提供状态码、响应头和响应内容。

请求路径 `/documents/1` 到达处理器后，正则表达式检查路径是否符合 `/documents/数字`。随后 `next(..., None)` 从固定列表中找 `id` 相同的字典；找不到就得到 `None`。这段只是教学数据查找，不是数据库查询。

找到记录时返回 HTTP 状态 `200`，找不到时返回 `404`。`payload` 是将要传回客户端的 Python 字典。`json.dumps(payload)` 把字典转成 JSON 文本，`.encode("utf-8")` 再变成网络可写入的字节。

处理器通过 `send_response()` 写状态行，通过 `send_header()` 写响应头，`end_headers()` 标记响应头结束，最后 `self.wfile.write(body)` 写响应正文。`Content-Length` 是正文的字节数，不是 Python 字符数。

客户端调用 `response.read()` 取得字节，`decode("utf-8")` 把字节还原成文本，`json.loads(...)` 再把 JSON 文本解析成 Python 字典。数据流是：

```text
Python 字典 -> JSON 文本 -> UTF-8 字节 -> HTTP 响应
HTTP 响应字节 -> UTF-8 文本 -> Python 字典
```

这些工具都来自标准库：`json` 负责 Python 值与 JSON 文本互转；`re` 负责检查路径形状；`threading` 管理本例服务器线程。它们不提供 FastAPI 路由、数据库、登录或加密能力。

对于本例的 `404` 响应，`urlopen()` 的默认处理会抛出 `HTTPError`；不是只要非 `200` 都会抛异常，例如成功的 `202` 仍可正常读取。第二个请求用 `except HTTPError` 单独读取错误响应；`HTTPError` 来自 `urllib.error`，它既表示 HTTP 错误响应，也带有状态码和可读取的响应正文。`with error:` 在读取后关闭错误响应，和成功响应一样管理资源。

### 3. URL、域名、IP、端口各自负责什么

示例地址形如 `http://127.0.0.1:54321/documents/1`：

- `http` 是协议方案，说明客户端按 HTTP 组织请求；HTTPS 通常写成 `https`。
- `127.0.0.1` 是 IP 地址。IP 用于标识网络中的目标地址；此处它特指本机。
- `54321` 是端口。端口让同一台机器上的不同网络服务区分各自接收的连接。
- `/documents/1` 是路径，告诉 HTTP 服务端要访问哪个资源。

真实公网 URL 常写域名，例如 `https://docs.example.org:443/documents/1`。域名是便于人记忆的名称，不是路由器直接转发的目标地址。客户端通常先通过 DNS（域名系统）查询域名对应的 IP 地址；DNS 查询可能命中缓存，也可能经过递归解析服务，因此不保证每次请求都会现场访问权威 DNS。

得到目标 IP 后，网络设备根据路由信息把数据包逐步转发到目标网络。路由器不需要理解你的 Python 字典或文档标题；它根据网络层地址选择下一段路径。实际路径、设备数量和运营商网络会变化，本章本机例子没有经过公网 DNS 或公网路由。

### 4. TCP、TLS 与 HTTP 的关系

对于常见的 HTTP/1.1 和 HTTP/2 HTTPS 连接，客户端通常先建立 TCP 连接，再进行 TLS 握手，协商加密参数并验证服务器证书，然后在加密通道内发送 HTTP 请求。TLS 保护传输内容的机密性和完整性，并帮助客户端确认连接的服务器身份；它不验证当前登录用户是否有权读取某份文档。

TCP 提供有序、可靠的字节流传输，并处理丢失数据的重传等工作。它不理解 `GET`、`404` 或 JSON。HTTP 定义请求和响应的语义；它不负责路由器如何选择网络路径。

这条“TCP 上的 HTTP”不是所有版本永远不变的规则：HTTP/3 使用 QUIC，而 QUIC 基于 UDP，不是 TCP。此处解释的是常见 HTTP/1.1、HTTP/2 的 HTTPS 路径，不拿本机 HTTP 小实验冒充 TLS 演示。

## 别把三种“状态”混在一起

**连接**是客户端与服务器之间传输数据的通道。一个连接上可以发生一个或多个 HTTP 请求；HTTP/1.1 可复用连接，HTTP/2 还可在单个连接上并行传输多个流。连接不是用户登录状态。

**请求**是一次具体的 HTTP 操作，含方法、路径、头部，有时还含正文。`GET /documents/1` 是一次请求。HTTP 状态码描述服务器对这次 HTTP 请求的处理结果。

**业务状态**是应用自身的规则结果，例如用户未登录、登录但没有权限、文档被归档、搜索没有结果。它要由应用明确表达，不能只看 TCP 连接是否建立。

常见 HTTP 状态码：

| 状态码 | 常见含义 | 不应误读成 |
| --- | --- | --- |
| `200` | 请求成功，响应正文通常含结果 | 用户永远有权访问此数据 |
| `201` | 请求成功并创建了资源 | 所有 POST 都应该返回 201 |
| `400` | 请求格式或参数有问题 | 服务器内部一定崩溃 |
| `401` | 缺少有效认证凭据，或凭据无效 | 已登录用户权限不足 |
| `403` | 服务器理解请求，但拒绝授权 | 没有登录（常用语义通常不是这个） |
| `404` | 目标资源不存在，或服务端选择不透露其存在 | 网络没连上 |
| `500` | 服务端处理时发生未预期错误 | 客户端输入一定错误 |

具体 API 可以定义更细的响应约定。HTTP 状态码和业务错误码可以同时存在：例如用 `403` 表示拒绝访问，正文再返回 `{"error": "document_forbidden"}`。不要把“HTTP 成功”误认为“业务操作成功”，也不要把业务失败都塞进 `200`。

## 超时不等于没有发生

客户端等待响应超过设定时间，会得到超时错误。但请求可能尚未到达服务端，也可能已经到达、已经写入数据，只是响应在返回途中丢失或客户端等得不够久。客户端无法仅凭超时判断服务端有没有完成操作。

所以对 `POST` 这类可能创建或扣款的操作，不要遇到超时就盲目重试，否则可能重复创建或重复扣款。可靠设计通常需要幂等键、可查询的操作编号、重复请求去重或明确的状态查询策略；这些是后续 API 设计内容，本章先记住：**超时表示客户端没及时收到结果，不证明服务端没处理。**

`GET` 按 HTTP 语义应当是安全且幂等的，但真实服务仍可能有日志、计数等副作用。重试策略要结合接口契约、错误类型、重试次数和退避等待，不能只按方法名机械决定。

## 跟写与观察

在 `DocumentHandler.do_GET()` 中做两处改动，每次先预测输出再运行：

1. 把成功路径状态改成 `202`，观察客户端状态行怎样变化。随后恢复为 `200`。
2. 将不存在的错误正文改为 `{"error": "missing"}`，确认服务端正文、客户端解析出的字典和打印值来自同一处数据。

再将请求改成 `/documents/nope`。正则不匹配时，`document_id` 会是 `None`，程序应走 404 分支，而不是在转换整数时崩溃。

注意：本例的 `log_message()` 覆盖了框架默认日志方法并不打印内容，只为让精确输出保持两行。生产程序通常需要有用的访问日志；不要把“隐藏日志”当作安全措施。

## 独立练习

在同一个文件中新增 `GET /health` 路径，返回状态码 `200` 和 JSON `{"status": "ok"}`；原有文档路径与 404 行为必须保持不变。

验收标准：

- 重复运行程序均能正常启动并退出；退出时服务器线程已关闭。
- 客户端访问 `/health` 能解析为 Python 字典 `{"status": "ok"}`。
- `/documents/1` 仍返回 `Python`，未知文档仍产生 404。
- 不绑定公网地址、不安装第三方包、不访问外网。

定位提示：先检查路径匹配顺序。把 `/health` 当成文档 ID 去解析会失败；为健康检查安排独立分支即可。这里不提供完整独立答案，请自己完成后对照验收。

## 本章边界与四条检查

本章学到从 URL 到 HTTP 响应的常见链路、状态码、请求与连接的区别，以及超时的含义。不学 DNS 报文、路由协议、TCP 拥塞控制、TLS 密码学细节、HTTP/2 帧、HTTP/3 实现或生产 Web 服务部署；后续再逐层补。

四条理解检查：

1. `https://host:443/documents/1` 中，域名、IP、端口、路径分别解决什么问题？
2. 为什么 TCP 建连成功并不等于用户已登录或有权访问文档？
3. 客户端超时后，为什么不能断言服务端没有处理 POST？
4. 本地例子中谁调用 `do_GET()`？客户端如何从响应字节得到 Python 字典？

## 小结与衔接

一句话：DNS 帮客户端找到目标地址，网络负责送达，传输层提供通道，HTTP 约定请求与响应，业务层决定具体结果；每层的成功不替代下一层的判断。
