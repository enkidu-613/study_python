## 1. 先看完整程序

把下面代码保存为 `examples/cs50x/01_catalog.c`。这是完整程序：一个文件、必要头文件、函数原型、函数定义和 `main` 都齐全。

```c
#include <stdio.h>

const int OWNER_ID = 7;

int is_known_id(int id);
void print_topic(int id);

int main(void)
{
    int python_id = 1;
    int http_id = 2;
    int sql_id = 3;
    int requested_id = 2;
    int match_count = 0;

    printf("Knowledge catalog\n");
    printf("IDs: %i, %i, %i\n", python_id, http_id, sql_id);

    if (is_known_id(requested_id))
    {
        print_topic(requested_id);
        match_count = match_count + 1;
    }
    else
    {
        printf("No matching topic\n");
    }

    for (int id = python_id; id <= sql_id; id = id + 1)
    {
        printf("Checked id %i\n", id);
    }

    int average_owner = (OWNER_ID + OWNER_ID + 9) / 3;
    double approximate = 0.1 + 0.2;

    printf("Matches: %i\n", match_count);
    printf("Integer average: %i\n", average_owner);
    printf("0.1 + 0.2 approximately: %.17f\n", approximate);
    return 0;
}

int is_known_id(int id)
{
    return id == 1 || id == 2 || id == 3;
}

void print_topic(int id)
{
    if (id == 1)
    {
        printf("id 1: Python, owner %i\n", OWNER_ID);
    }
    else if (id == 2)
    {
        printf("id 2: HTTP, owner %i\n", OWNER_ID);
    }
    else
    {
        printf("id 3: SQL, owner 9\n");
    }
}
```

在仓库根目录运行：

```bash
cd examples/cs50x
cc -std=c11 -Wall -Wextra 01_catalog.c -o 01_catalog
./01_catalog
```

预期主要输出如下。最后一行展示当前常见 IEEE 754 `double` 平台的结果；浮点显示细节是平台相关的，不要把它当所有 C 实现的逐字输出保证。

```text
Knowledge catalog
IDs: 1, 2, 3
id 2: HTTP, owner 7
Checked id 1
Checked id 2
Checked id 3
Matches: 1
Integer average: 7
0.1 + 0.2 approximately: 0.30000000000000004
```

## 2. 从 `main` 追到输出

### 文件、头文件、函数和入口

`#include <stdio.h>` 请求编译环境提供标准输入输出声明；这里需要 `printf` 的声明。尖括号形式通常用于标准/系统头文件。**头文件（header）**提供函数等接口的声明，不是把整个标准库源码复制进程序。

`main` 是 hosted C 程序的入口函数。`int main(void)` 中 `int` 是返回类型，`void` 表示不接收参数；函数体在花括号内。运行到 `return 0;` 时，程序向操作系统报告成功结束。`main` 里的局部变量属于该函数调用，后面讲作用域。

`printf` 是标准 I/O 库中的函数，声明来自 `<stdio.h>`。它接收格式字符串和与占位符对应的值，把格式化文本写到标准输出。`%i` 对应 `int`，`%f` 对 `printf` 用于 `double`，`%.17f` 指定小数显示 17 位；格式占位符与实参类型不匹配会导致未定义行为，编译器警告要认真看。

反斜线开头的转义序列可在字符串中表达特殊字符：`\n` 是换行，`\t` 是制表，`\\` 是反斜线本身，`\"` 是双引号。它们不是“两个要打印的普通字符”；例如程序里的 `"Knowledge catalog\n"` 输出后会换到下一行。

注释（comment）是写给人的说明，编译时不会作为普通语句执行。单行注释形如 `// 这里只解释不明显的业务决定`；跨行注释可写成 `/* 多行说明 */`。注释应解释原因或约束，不要把代码逐字翻译成中文。

语法高亮（syntax highlighting）是编辑器依照语法把关键字、字符串、注释等显示成不同颜色的辅助功能；颜色不改变程序语义，也不能代替编译器检查。图形用户界面 GUI 由窗口、按钮等可视控件构成；命令行界面 CLI 则通过终端输入命令和查看文本结果。CS50 的 `cs50.dev` 提供预配置的 Linux 开发环境；本课程例子使用本机终端和 C 编译器，操作系统不同可能造成工具选项差异。Linux 不是 C 语法，而是提供编译器、文件系统和命令行等运行环境的一类操作系统。

### 声明、类型与赋值

`int requested_id = 2;` 一句同时做三件事：声明名为 `requested_id` 的变量；指定它的类型为整数 `int`；将初始值 2 存进去。`=` 在这里是赋值，不是数学等号；比较相等写 `==`。

- `int` 表示整数。范围受实现限制；可用 `<limits.h>` 的 `INT_MAX` 查看本机上限。
- `long` 也是有符号整数类型，至少能表示 `int` 的范围，具体宽度由实现决定；常见 `printf` 格式是 `%ld`，`unsigned long` 用 `%lu`。
- `char` 的大小恰为一个 C 字节（至少 8 位），常用来存一个字符编码单元或原始字节；普通 `char` 本身的有符号性由实现决定。`printf` 用 `%c` 按字符输出；它不是 C 字符串类型。
- `float` 是单精度浮点类型，适合近似小数；`double` 通常提供更高精度。`printf` 用 `%f` 输出 `double`，而传给可变参数函数的 `float` 会先提升为 `double`，所以也用 `%f`。`long double` 对应 `%Lf`。
- `double` 表示近似浮点数，适合需小数的近似运算；它不是任意精度实数。
- `const int OWNER_ID = 7;` 表示本作用域中不允许通过该名字修改值。它不是自动成为 C 的编译期宏，但可避免误改常量。
- `void` 用作“不接收参数”或“不返回值”的说明；这里 `print_topic` 不返回结果。

常见 `printf` 格式符速查（格式符必须与实参的类型相符）：

| 类型/用途 | 格式符 | 例子 |
| --- | --- | --- |
| `int` 十进制整数 | `%i` 或 `%d` | `printf("%i", requested_id);` |
| `long` 整数 | `%ld` | `printf("%ld", a_long);` |
| `char` 字符 | `%c` | `printf("%c", letter);` |
| `float` / `double` 小数输出 | `%f` | `printf("%f", (double) ratio);` |
| `long double` | `%Lf` | `printf("%Lf", a_long_double);` |
| `size_t` 大小值 | `%zu` | `printf("%zu", length);` |
| C 字符串 | `%s` | `printf("%s", text);` |

表格中的 `a_long` 等是示意变量名，不是新增可运行代码。`printf` 是可变参数函数，格式字符串不会自动把任意类型安全地转换成目标类型；错配可能导致未定义行为。后续 02 章会在 `size_t` 的实际数组长度中使用 `%zu`。

**变量（variable）**是有名字、有类型、有生命周期和值的存储位置。命名可读性属于正确维护的一部分：`requested_id` 比 `x` 更容易和需求对应。

### 表达式与逻辑

`id == 1 || id == 2 || id == 3` 是布尔条件：`==` 比较是否相等，`||` 表示“或”，结果为真或假。`&&` 是“并且”，`!` 是“非”。C11 有内建整数类型 `_Bool`；包含 `<stdbool.h>` 后，宏 `bool` 展开为 `_Bool`，`true` 和 `false` 分别展开为 1 和 0。本例函数接口选择返回 `int`，条件表达式仍可直接用于 `if`。C 的条件规则把 0 当假、非 0 当真。

函数 `is_known_id` 的 `return id == ...;` 把条件结果交还调用者。函数调用 `is_known_id(requested_id)` 将 `requested_id` 当前的整数值复制给形参 `id`；此函数不修改调用者的变量。C 的参数一律按值传递，包括指针参数：若参数是指针，复制到形参的是地址值，不是调用者的指针变量本身。如何通过指针影响所指对象留到内存章节。

算术运算包括 `+ - * / %`。整数除法会丢弃小数部分：`(7 + 7 + 9) / 3` 先得整数和 23，再以整数除法得到 7。因此输出 `Integer average: 7`。把整数改成浮点数会改变除法规则，但浮点结果仍可能只是近似值。

比较运算符可按两组记：`<`、`<=`、`>`、`>=` 比大小；`==`、`!=` 比相等/不等。它们生成可用于 `if` 或循环条件的真假结果。注意 `=` 是赋值，`==` 才是相等比较。

整数 `%` 是取余数：`17 % 5` 得 2，`18 % 3` 得 0，因此常用 `number % 2 == 0` 判断偶数；除数为 0 时行为未定义，必须先排除。对整数除法，商向 0 截断；当 `b` 非 0 且商可表示时，数学上满足 `a = (a / b) * b + a % b`。负数余数的符号规则可能让它和数学里的“正模数”直觉不同。浮点数不用 `%`，需使用 `<math.h>` 的 `fmod` 等函数。

增加、递减的常见形式是 `count = count + 1`、`count++`、`count += 1`。本章用显式赋值便于追踪。整数溢出需要小心：对有符号整数做超出可表示范围的算术，在 C 中属于未定义行为；不能期待它必定“绕回负数”。无符号整数按模运算规则回绕，但这也不自动意味着业务结果正确。进行金额/计数计算时要先判断范围。

### 条件与循环

`if (...) { ... } else { ... }` 根据条件真假选择一个分支。`else if` 可接更多互斥情况。本程序中 ID 为 2，所以 `is_known_id` 返回真，执行 `print_topic`，然后计数从 0 变成 1；`else` 分支跳过。

`for (int id = python_id; id <= sql_id; id = id + 1)` 分成初始化、继续条件、每轮更新三部分：

1. 初始化 `id=1`，只做一次。
2. 检查 `id<=3`；真则进入循环体。
3. 打印当前 ID，然后更新 `id=id+1`。
4. 当 id 成为 4，条件为假，循环结束。

循环是把重复步骤写一次并指定停止条件。若停止条件永远为真，会变成无限循环；边界上的 `<=` 和 `<` 不同，后续数组章节会详细验证索引范围。

### `while` 与 `do-while`：检查时机不同

下面是另一个完整小程序，专门把两种循环的执行次数摆出来。保存为 `examples/cs50x/01_while.c`，在仓库根目录运行：

```c
#include <stdio.h>

int main(void)
{
    int while_count = 0;
    while (while_count < 0)
    {
        printf("while body\n");
        while_count++;
    }
    printf("while iterations: %i\n", while_count);

    int do_count = 0;
    do
    {
        printf("do-while body\n");
        do_count++;
    }
    while (do_count < 0);
    printf("do-while iterations: %i\n", do_count);

    return 0;
}
```

```bash
cd examples/cs50x
cc -std=c11 -Wall -Wextra 01_while.c -o 01_while
./01_while
```

预期输出：

```text
while iterations: 0
do-while body
do-while iterations: 1
```

`while` 先检查条件，再决定是否进循环体，所以初值 0 面对 `0 < 0` 为假时执行 0 次。`do-while` 先执行一次循环体，再检查条件，因此即使条件一开始为假也至少执行 1 次；语法末尾需要分号。它适合“先做一次，再决定是否继续”的流程。若把两个条件改成 `< 3`，对应循环体各会执行 3 次。

### 函数、参数、返回值、原型与作用域

函数把命名的一段工作集中起来。声明 `int is_known_id(int id);` 是**函数原型（prototype）**：在函数定义出现前告诉编译器函数名、返回类型和参数类型。于是 `main` 可以先调用它，定义放在文件后面。原型末尾分号；定义有函数体，不以分号结束。

`is_known_id` 接收 `int` 并返回 `int`。这里 `return` 表达式为 0 或 1；C11 有 `_Bool` 和 `<stdbool.h>` 提供的 `bool` 宏，本例为保持最小标准头文件使用 `int` 返回条件结果。`print_topic` 的返回类型是 `void`，其作用是打印而不是把主题字符串交给调用者。

**作用域（scope）**是一个名字可被直接使用的代码范围。`requested_id`、`match_count` 在 `main` 花括号内声明；`id` 形参只在各自函数中有效。`for` 中声明的 `id` 在循环语句范围内使用。全局 `OWNER_ID` 在文件级可见；全局状态会被更多函数共享，因此真实项目通常应限制其数量。

参数与返回值形成接口：调用者传入 `requested_id` 的值；函数接收自己的 `id`；返回真假值；调用者据此决定分支。调用 `print_topic` 则传入数值，函数自身输出文字。后续若需要把修改结果带回去，返回值或指针等机制会比“以为参数自动回写”更准确。

## 3. 正确性、设计、风格

- **正确性（correctness）**：对定义好的输入，结果符合需求。先明确编号 1–3 的输出，再检查边界值 0、4 和所有合法编号。
- **设计（design）**：代码是否拆成合适职责，重复和耦合是否合理。`is_known_id` 只回答编号存在与否，`print_topic` 负责输出；它们比把所有逻辑挤进 `main` 更容易单独阅读。
- **风格（style）**：缩进、命名、空白和注释是否让人容易读。编译器通常不在意缩进，但读者和维护者在意。

在 CS50 环境，官方经常用 `check50`、`style50` 等工具检查作业；本地这里不安装它们。我们用严格编译警告与手工测试数据作为本章检查。通过一次编译并不能证明逻辑正确；测试几个输入也不能证明所有可能都正确。

### 整数除法与浮点误差

本程序的平均值一行值得停下来：两个整数相加后仍为整数，除以 3 仍是整数除法。想要近似小数，应让运算在浮点类型中进行，例如把其中一个操作数转换为 `double`；但“使用浮点数”也不代表精确十进制。许多小数（如 0.1）无法用有限二进制小数精确表示，所以 `0.1 + 0.2` 常显示为接近 0.3 的值。

比较浮点结果时，通常检查两者差值是否小于按业务选择的容差，而不是直接写 `a == b`。钱款等需要固定小数位的业务常用整数最小单位（如分）或专门十进制定点方案；不能随手把二进制浮点当精确金额。

## 4. 编译与库：源代码怎样变成可运行程序

**源代码（source code）**是人写的 C 文本。编译器把它处理成目标平台能执行的机器代码，实际构建还可能包含预处理、编译、汇编和链接等阶段；完整流水线在第 02 章细拆。本章使用编译驱动程序 `cc`，它会根据参数调用工具链。

命令 `cc -std=c11 -Wall -Wextra 01_catalog.c -o 01_catalog` 中：`-std=c11` 要求采用 C11 语言模式；`-Wall -Wextra` 开启常见警告（名称中的 `Wall` 不表示所有警告）；输入是源文件；`-o` 指定输出程序名。随后 `./01_catalog` 才是运行已经构建好的程序。

`printf` 属于 C 标准库，链接器会把所需实现与程序连接；在常见系统中标准库通常由驱动器自动处理。没有必要把 `stdio.h` 当成整个库本身。C 标准库与 CS50 提供的 `cs50.h` 也不同。

**手册页（manual page，man page）**是系统提供的函数/命令参考。Linux 常见终端可用 `man 3 printf` 查看 `printf` 的库函数说明，`3` 是手册章节之一；不同系统的手册安装情况、章节编号和内容可能不同。阅读时先找参数、返回值、错误和格式符，不需要从头背整页。

### 本机 C 与 CS50 环境不能混用

本课程的本机示例只用标准 C，不依赖 `cs50.h`。官方 CS50 环境额外提供 `cs50.h`，其中有 `get_int`、`get_string` 等课程辅助接口，并为环境配置了 `make` 等便利工具。若在本机没有安装对应库，含 `#include <cs50.h>` 的程序会找不到头文件或链接实现；这不是 C 标准库自带能力。反过来，本机的 `cc` 命令不应被描述成等价于 CS50 环境里的所有配置。

## 5. 跟写与验证

先在纸上预测：把 `requested_id` 从 2 改为 8，会打印什么？计数是多少？循环打印哪些 ID？再做小改动：

1. 改成 `requested_id = 8`，预期显示 `No matching topic`，`Matches: 0`，循环仍输出 1、2、3。
2. 改成 `requested_id = 1`，预期显示 Python。
3. 把 `id <= sql_id` 改为 `id < sql_id`，观察最后一个 `Checked id 3` 消失；还原后再继续。
4. 把 `average_owner` 的表达式改为 `7 / 2`，预测整数结果是 3，而不是 3.5。

这几步分别验证分支、循环边界和类型规则。每次只改一处，运行后把“预测”和“实际”并排记录；若不一致，沿变量变化找出差异。

## 6. 独立练习：目录摘要

写一个完整 C 程序，固定记录仍是 Python/HTTP/SQL，owner 分别 7、7、9。**要求**：打印三条记录；统计 owner 7 的记录数；计算主题 ID 从 1 到 3 的整数平均值；再将 ID 2 单独判断并打印“网络主题”。

**预期**：共打印 3 条记录；owner 7 数量为 2；ID 平均值为 2；ID 2 分支被执行。请自己确定函数边界，至少写一个返回 `int` 的函数，并为它提供原型。

**边界与验收**：不要将两个不同含义的变量都命名 `count`；整数平均的余数会被丢弃；使用 `-Wall -Wextra` 编译，目标是没有警告。暂时禁止数组和用户输入，因为它们属于后续章节。定位提示：先检查 `if` 的条件，再手算表达式中的类型和整除。

## 常见坑

- 把 `=` 当比较。赋值用 `=`，相等比较用 `==`。
- 漏掉函数原型或把定义写在调用之后却没有声明，导致编译诊断。
- `printf` 的格式符和实参类型不匹配；让编译器警告保持开启。
- 认为 `int` 在所有平台有固定宽度，或有符号溢出一定回绕。C 的范围依实现，有符号溢出不可依赖。
- 以为 `7 / 2` 得 3.5。两个整数运算会进行整数除法。
- 以为 `double` 是精确小数。它只能近似表示许多十进制小数。
- 把“能编译”当成“逻辑正确”。编译器不会替你确认业务需求。
- 把 CS50 的 `get_int`、`get_string`、`make` 当成标准 C 默认存在。本课第一、二章本机示例刻意不依赖这些工具。

## 课后压缩

- 心智模型：C 程序从 `main` 开始，用有类型的值通过表达式、分支、循环和函数变换，再由库函数输出。
