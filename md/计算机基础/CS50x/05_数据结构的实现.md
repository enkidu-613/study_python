## 本章学什么

数据结构不是某个魔法容器，而是“数据在内存中怎么排、怎么连、操作要付什么代价”的选择。本章从固定数组增长的限制出发，实现动态扩容、栈、队列、链表、二元搜索树、链表法哈希表和 Trie。程序都用 C，核心结构不是 Python `dict` 或其他现成容器。

## 1. 固定数组：连续、快速，但容量先定

C 数组的元素连续放置，所以知道索引便能直接算出对应元素位置。读写 `items[i]` 是 `O(1)`；但一般固定长度数组不能在执行期间自动增长。若每次新增记录都要“扩大”，就得找一块更大的连续区域、把旧元素搬过去、再更新指针。

### 动态数组与 `realloc`

**动态数组（dynamic array）**是“元素连续存放，但容量可在需要时重新配置”的管理策略，不是 C 的内建容器。常用两个数字追踪它：`size` 是已有元素数；`capacity` 是目前可容纳数。只有 `size == capacity` 时扩容。

下面完整程序容量从 2 开始，满了就翻倍。文件名 `grow_array.c`：

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    size_t size = 0;
    size_t capacity = 2;
    int *items = malloc(capacity * sizeof(*items));
    if (items == NULL)
    {
        fprintf(stderr, "initial allocation failed\n");
        return 1;
    }

    const int incoming[] = {7, 9, 21, 4, 12};
    const size_t incoming_count = sizeof(incoming) / sizeof(incoming[0]);
    for (size_t i = 0; i < incoming_count; i++)
    {
        if (size == capacity)
        {
            if (capacity > SIZE_MAX / 2 / sizeof(*items))
            {
                fprintf(stderr, "requested capacity is too large\n");
                free(items);
                return 1;
            }
            size_t new_capacity = capacity * 2;
            int *grown = realloc(items, new_capacity * sizeof(*items));
            if (grown == NULL)
            {
                fprintf(stderr, "could not grow array\n");
                free(items);
                return 1;
            }
            items = grown;
            capacity = new_capacity;
            printf("capacity=%zu\n", capacity);
        }
        items[size] = incoming[i];
        size++;
    }

    printf("IDs:");
    for (size_t i = 0; i < size; i++)
    {
        printf(" %d", items[i]);
    }
    printf("\nsize=%zu capacity=%zu\n", size, capacity);
    free(items);
    return 0;
}
```

预期输出：

```text
capacity=4
capacity=8
IDs: 7 9 21 4 12
size=5 capacity=8
```

完整追踪：起始 `size=0, capacity=2`，7 和 9 写在索引 0、1；接到 21 时已满，容量变 4，`realloc` 成功后 `items` 更新到返回地址。4 写在索引 3；接到 12 时容量 4 再翻成 8。最后有 5 个有效元素，未用的 3 格不算已存数据。

为什么先用 `grown` 接 `realloc`？成功时可能返回新地址并释放旧块；失败时返回 `NULL`，旧块仍有效。若直接 `items = realloc(items, ...)`，失败会用 `NULL` 覆盖唯一的旧地址，造成泄漏。成功后 `grown` 成为新的唯一拥有者；退出前 `free(items)`。大小乘法还可能溢出，所以示例先检查容量上界。

容量翻倍看似偶尔搬动很多元素，但对连续追加 `n` 个元素，搬移总量是 `1 + 2 + 4 + ...`，小于约 `2n`；把所有追加平均后，每次追加的摊销成本是 `O(1)`。单次扩容仍可能搬 `O(n)` 个元素。若每次只增加一格，就可能第 1 次搬 1 个、第 2 次搬 2 个、一路搬到约 `n` 个，总成本 `O(n^2)`。

## 2. 抽象数据类型：先说操作，再选实现

**抽象数据类型（Abstract Data Type, ADT）**描述“能做哪些操作、操作有什么规则”，不规定底下必须用什么内存结构。例如栈（stack）规定后进先出，队列（queue）规定先进先出。两者都可以用数组或链表节点实现；操作规则与存储方式是两个不同层次。

在 C 中，`struct`（结构体）把多个字段组合成一个记录类型；`typedef` 为类型定义一个更方便的名字。下面的 `typedef struct { ... } Stack;` 定义 `Stack` 类型，`values` 和 `size` 是字段。结构体变量用点号访问字段，例如 `stack.size`；若变量是指向结构体的指针，则用箭头 `stack->size`，它等价于 `(*stack).size`。本节先看到这个语法，链表部分会把它用在节点上。

本章辅助函数声明中的文件作用域 `static` 表示函数名只在当前 `.c` 文件内部可见。这是链接可见性，不是“静态局部变量”；静态局部变量是函数内部另一种用法，会跨调用保留值，本章代码没有使用它。

沿着一条真实调用看字段变化：`main` 中的 `Stack stack = {.size = 0};` 建立一个结构体变量，调用 `push(&stack, 7)` 把它的地址传给参数 `stack`。函数中的 `stack->values[0] = 7` 等价于 `(*stack).values[0] = 7`，`stack->size++` 随后把调用者结构体里的 `size` 改成 1。`push` 返回后，`main` 看到的仍是同一个栈对象，只是两个字段已更新。

本程序用固定数组演示操作，文件名 `stack_queue.c`。固定容量满时拒绝加入，避免越界：

```c
#include <stdbool.h>
#include <stdio.h>

#define CAPACITY 4

typedef struct
{
    int values[CAPACITY];
    int size;
} Stack;

typedef struct
{
    int values[CAPACITY];
    int head;
    int size;
} Queue;

static bool push(Stack *stack, int value)
{
    if (stack->size == CAPACITY)
    {
        return false;
    }
    stack->values[stack->size] = value;
    stack->size++;
    return true;
}

static bool pop(Stack *stack, int *out)
{
    if (stack->size == 0)
    {
        return false;
    }
    stack->size--;
    *out = stack->values[stack->size];
    return true;
}

static bool enqueue(Queue *queue, int value)
{
    if (queue->size == CAPACITY)
    {
        return false;
    }
    int tail = (queue->head + queue->size) % CAPACITY;
    queue->values[tail] = value;
    queue->size++;
    return true;
}

static bool dequeue(Queue *queue, int *out)
{
    if (queue->size == 0)
    {
        return false;
    }
    *out = queue->values[queue->head];
    queue->head = (queue->head + 1) % CAPACITY;
    queue->size--;
    return true;
}

int main(void)
{
    Stack stack = {.size = 0};
    Queue queue = {.head = 0, .size = 0};
    int value;

    push(&stack, 7);
    push(&stack, 9);
    pop(&stack, &value);
    printf("stack pop=%d\n", value);

    enqueue(&queue, 7);
    enqueue(&queue, 9);
    dequeue(&queue, &value);
    printf("queue dequeue=%d\n", value);
    dequeue(&queue, &value);
    printf("queue dequeue=%d\n", value);
    return 0;
}
```

预期输出：

```text
stack pop=9
queue dequeue=7
queue dequeue=9
```

栈操作名称：`push` 把新值放顶端，`pop` 取走顶端；最后进去的 9 先出来。队列的 `enqueue` 加到队尾，`dequeue` 从队首取走；先进来的 7 先离开。`head` 指向队首，`size` 记录占用格数，模数 `% CAPACITY` 让尾端之后绕回数组开头。这是环状队列；若只用“尾端不回绕”的简单数组，取走前方元素后空位可能无法重用。

在这个固定数组实现中，push/pop/enqueue/dequeue 都只做固定次数的索引计算和赋值，时间 `O(1)`，额外空间固定 `O(CAPACITY)`。若改用链表节点，容量可动态增长，但每个值多存一个链接指针，并且每次新增都要处理分配失败和释放。

## 3. 链表：用指针把分散节点串起来

数组元素连续，可按索引直接抵达；中间插入常要搬移后缀。**单向链表（singly linked list）**把值和下一节点地址放在一个节点中：

```text
head -> [7 | next] -> [9 | next] -> [21 | NULL]
```

每个节点不要求相邻；`head` 指向第一个。代价是不能用 `list[2]` 直接拿第三个值，要沿着指针逐节走。

这里的 `typedef struct Node { ... } Node;` 声明了结构体标签 `struct Node`，并用 `typedef` 让后续代码可直接写 `Node`。`next` 字段的类型写成 `struct Node *`，因为结构体定义尚未结束时，别名 `Node` 还没声明完成。节点的 `id` 保存示例文档 ID，`next` 保存下一个节点地址；这里没有 owner 字段。

`push_front` 的参数 `Node **head` 是“指向 `Node *` 变量的指针”。调用者有 `Node *documents = NULL`，传入 `&documents` 后，函数参数 `head` 指向调用者的指针变量；`*head` 读写的就是 `documents` 本身。第一次调用时 `*head` 是 `NULL`，新节点的 `next` 设为 `NULL`，再令 `*head = node`，于是调用者的 `documents` 指向新节点。下一次调用先令新节点的 `next` 指向旧头，再更新 `documents`。按程序调用顺序 21、9、7、4，最终链为 `4 -> 7 -> 9 -> 21`。这就是必须传 `Node **` 而不是只传 `Node *` 的原因：函数要替调用者改“头指针变量”。

下面是完整可执行程序：建立 7、9、21 三个节点，头插入 4，查找 9，逐节印出并释放。文件名 `list.c`：

```c
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct Node
{
    int id;
    struct Node *next;
} Node;

static bool push_front(Node **head, int id)
{
    Node *node = malloc(sizeof(*node));
    if (node == NULL)
    {
        return false;
    }
    node->id = id;
    node->next = *head;
    *head = node;
    return true;
}

static bool contains(const Node *head, int target)
{
    for (const Node *current = head; current != NULL; current = current->next)
    {
        if (current->id == target)
        {
            return true;
        }
    }
    return false;
}

static void print_list(const Node *head)
{
    for (const Node *current = head; current != NULL; current = current->next)
    {
        printf("%d%s", current->id, current->next == NULL ? "\n" : " -> ");
    }
    if (head == NULL)
    {
        printf("(empty)\n");
    }
}

static void free_list(Node *head)
{
    while (head != NULL)
    {
        Node *next = head->next;
        free(head);
        head = next;
    }
}

int main(void)
{
    Node *documents = NULL;
    if (!push_front(&documents, 21) ||
        !push_front(&documents, 9) ||
        !push_front(&documents, 7) ||
        !push_front(&documents, 4))
    {
        fprintf(stderr, "could not allocate list node\n");
        free_list(documents);
        return 1;
    }

    print_list(documents);
    printf("contains 9: %s\n", contains(documents, 9) ? "yes" : "no");
    printf("contains 5: %s\n", contains(documents, 5) ? "yes" : "no");
    free_list(documents);
    return 0;
}
```

预期输出：

```text
4 -> 7 -> 9 -> 21
contains 9: yes
contains 5: no
```

`push_front` 接受 `Node **head`：它要修改调用者的头指针，所以接收头指针变量的地址。分配新节点后先让 `node->next` 指向旧首节点，再令 `*head` 指向新节点；顺序反过来就会丢失旧链表的入口。若分配失败，函数返回 false，已有链表不变。主程序在任一插入失败时释放当前仍可到达的所有节点。

`contains` 从首节点开始逐个比较，最多访问 `n` 个节点，时间 `O(n)`，额外空间 `O(1)`。头插入不用找位置，是 `O(1)`；若要在尾端插入但没有 tail 指针，先走到尾端就要 `O(n)`。若已知某节点地址，插入到它之后可 `O(1)`，但“先找到该地址”的时间仍要算。每节点的 `next` 额外耗内存，并且链表不支援数组式二分搜索：要找中间节点本身就得走过前面的节点。

释放时先把 `head->next` 存进 `next`，再释放 `head`。释放后读取 `head->next` 已经是使用悬空指针，因此不能把保存下一节点放在 `free` 之后。

## 4. 二元搜索树：用大小关系决定往哪走

**树（tree）**是节点之间呈阶层关系的结构；没有父节点的起点叫根。**二元搜索树（Binary Search Tree, BST）**每个节点至多有左、右子节点，并遵守约定：左侧值小于节点，右侧值大于节点。本节不存重复 id，重复插入直接忽略。

插入 `{9, 4, 12, 2, 7}` 的结果：

```text
        9
       / \
      4   12
     / \
    2   7
```

搜索 7：7 < 9，走左；7 > 4，走右；命中。每一步都排除不可能的一侧。这个例子树高很小，但 BST 不会自动平衡。

完整 C 程序 `bst.c`：

```c
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct TreeNode
{
    int id;
    struct TreeNode *left;
    struct TreeNode *right;
} TreeNode;

static TreeNode *insert(TreeNode *root, int id, bool *ok)
{
    if (root == NULL)
    {
        TreeNode *node = malloc(sizeof(*node));
        if (node == NULL)
        {
            *ok = false;
            return NULL;
        }
        node->id = id;
        node->left = NULL;
        node->right = NULL;
        return node;
    }
    if (id < root->id)
    {
        TreeNode *child = insert(root->left, id, ok);
        if (*ok)
        {
            root->left = child;
        }
    }
    else if (id > root->id)
    {
        TreeNode *child = insert(root->right, id, ok);
        if (*ok)
        {
            root->right = child;
        }
    }
    return root;
}

static bool search(const TreeNode *root, int target)
{
    if (root == NULL)
    {
        return false;
    }
    if (target == root->id)
    {
        return true;
    }
    if (target < root->id)
    {
        return search(root->left, target);
    }
    return search(root->right, target);
}

static void print_in_order(const TreeNode *root)
{
    if (root == NULL)
    {
        return;
    }
    print_in_order(root->left);
    printf("%d ", root->id);
    print_in_order(root->right);
}

static void free_tree(TreeNode *root)
{
    if (root == NULL)
    {
        return;
    }
    free_tree(root->left);
    free_tree(root->right);
    free(root);
}

int main(void)
{
    const int ids[] = {9, 4, 12, 2, 7};
    const size_t count = sizeof(ids) / sizeof(ids[0]);
    TreeNode *root = NULL;
    bool ok = true;

    for (size_t i = 0; i < count && ok; i++)
    {
        root = insert(root, ids[i], &ok);
    }
    if (!ok)
    {
        fprintf(stderr, "could not allocate tree node\n");
        free_tree(root);
        return 1;
    }

    print_in_order(root);
    printf("\nsearch 7: %s\n", search(root, 7) ? "yes" : "no");
    printf("search 5: %s\n", search(root, 5) ? "yes" : "no");
    free_tree(root);
    return 0;
}
```

预期输出：

```text
2 4 7 9 12
search 7: yes
search 5: no
```

中序遍历（左、当前、右）会按升序输出，因为它利用 BST 的排序规则。`search` 递归的基例有两个：空指针表示没找到；当前节点命中就成功。其他情况只调用一个子树，问题每次沿一条路径缩小。

若树较平衡，高度约 `log2(n)`，搜索和插入可约 `O(log n)`；若按升序逐个插入 `2,4,7,9,12`，节点 2 是根，后续节点一路成为右孩子。此时搜索 2 会在根立即命中；搜索 12 则沿 `2 -> 4 -> 7 -> 9 -> 12` 走完整条链，最坏需要 `O(n)`，递归调用深度也可达 `O(n)`。BST 的排序性不等于自动平衡。`free_tree` 采用后序释放：先释放左右子树，再释放父节点，避免父节点已释放后还要读取它的子指针。

## 5. 哈希表：先分桶，再处理碰撞

**哈希函数（hash function）**把键转换成桶索引。**哈希表（hash table）**常用数组作为桶，配合每桶的链表处理多个键落在同一位置。若两个不同字符串得到相同索引，就是**碰撞（collision）**，并不代表程序错误；必须在桶中继续比较完整键。

这里用哈希函数把字符串中的每个字母值累加，再对桶数取余；这只是简化的示例函数，不适合密码学，也不保证分布均匀。为展示碰撞，桶数刻意设为 5。**负载因子（load factor）**是键数除以桶数：`alpha = n / m`，其中 `n` 是已存键数、`m` 是桶数。负载高通常意味着每个桶需要检查更多节点；改进哈希函数和扩桶可改善平均表现，但最坏情况仍可能需要 `O(n)` 查找。

完整程序 `hash_table.c`：

```c
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>

#define BUCKET_COUNT 5
#define WORD_SIZE 32

typedef struct Entry
{
    char word[WORD_SIZE];
    struct Entry *next;
} Entry;

static size_t hash_word(const char *word)
{
    unsigned long sum = 0;
    for (size_t i = 0; word[i] != '\0'; i++)
    {
        sum += (unsigned char) word[i];
    }
    return (size_t) (sum % BUCKET_COUNT);
}

static bool insert(Entry *buckets[], const char *word)
{
    size_t length = 0;
    while (word[length] != '\0' && length < WORD_SIZE)
    {
        length++;
    }
    if (length == WORD_SIZE)
    {
        return false;
    }
    if (length == 0)
    {
        return false;
    }

    size_t bucket = hash_word(word);
    for (Entry *current = buckets[bucket]; current != NULL; current = current->next)
    {
        size_t i = 0;
        while (i < length && current->word[i] == word[i])
        {
            i++;
        }
        if (i == length && current->word[i] == '\0')
        {
            return true;
        }
    }

    Entry *entry = malloc(sizeof(*entry));
    if (entry == NULL)
    {
        return false;
    }
    for (size_t i = 0; i <= length; i++)
    {
        entry->word[i] = word[i];
    }
    entry->next = buckets[bucket];
    buckets[bucket] = entry;
    return true;
}

static bool contains(Entry *buckets[], const char *word)
{
    size_t bucket = hash_word(word);
    for (Entry *current = buckets[bucket]; current != NULL; current = current->next)
    {
        size_t i = 0;
        while (current->word[i] != '\0' && word[i] != '\0' &&
               current->word[i] == word[i])
        {
            i++;
        }
        if (current->word[i] == '\0' && word[i] == '\0')
        {
            return true;
        }
    }
    return false;
}

static void free_table(Entry *buckets[])
{
    for (size_t i = 0; i < BUCKET_COUNT; i++)
    {
        Entry *current = buckets[i];
        while (current != NULL)
        {
            Entry *next = current->next;
            free(current);
            current = next;
        }
    }
}

int main(void)
{
    Entry *buckets[BUCKET_COUNT] = {NULL};
    const char *words[] = {"python", "sql", "http", "rag"};
    const size_t count = sizeof(words) / sizeof(words[0]);

    for (size_t i = 0; i < count; i++)
    {
        if (!insert(buckets, words[i]))
        {
            fprintf(stderr, "could not insert word\n");
            free_table(buckets);
            return 1;
        }
        printf("%s -> bucket %zu\n", words[i], hash_word(words[i]));
    }
    printf("contains sql: %s\n", contains(buckets, "sql") ? "yes" : "no");
    printf("contains css: %s\n", contains(buckets, "css") ? "yes" : "no");
    free_table(buckets);
    return 0;
}
```

预期输出：

```text
python -> bucket 4
sql -> bucket 1
http -> bucket 3
rag -> bucket 4
contains sql: yes
contains css: no
```

`python` 和 `rag` 都落在桶 4，形成碰撞；桶 4 的链表保留两条记录。查 `sql` 时先算出桶 1，再沿 `Entry *next` 比较完整字符串，不能因为桶相同就报告命中。程序拒绝空字符串和长度达到 32 的输入，确保复制时有空间放结尾 `\0`。这个示例的字符串比较不用 `strcmp`，是为了让 C 字符串终止条件清楚可见。

平均搜索常描述为 `O(1 + alpha)`，前提是 hash 分布足够均匀；最坏情况所有键都落在一桶，搜索 `O(n)`。本程序固定 5 桶、不会扩容，所以数据多时负载因子变高。真实设计会测量键分布，选择合理桶数，必要时再扩容。哈希函数是把键映射到桶，不是加密，也不是唯一编码：不同键可以有相同桶索引。

## 6. Trie：逐字符共享前缀

**Trie（前缀树）**将字符串拆成字符路径。每个节点保存“下一字符可能在哪里”的指针数组，另用 `is_word` 表示从根走到此节点是否是一个完整词。比如存入 `python` 和 `pytorch`，两者共用路径 `p y t`，之后才分叉：

```text
root -> p -> y -> t
                 / \
                h   o
                |   |
                o   r
                |   |
                n   c
                |   |
             [word] h
                    |
                 [word]
```

下面程序限制只接受小写英文字母。每节点 26 个子指针；空间开销会随前缀节点数增加。文件名 `trie.c`：

```c
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>

#define ALPHABET_SIZE 26

typedef struct TrieNode
{
    struct TrieNode *children[ALPHABET_SIZE];
    bool is_word;
} TrieNode;

static TrieNode *new_node(void)
{
    TrieNode *node = malloc(sizeof(*node));
    if (node == NULL)
    {
        return NULL;
    }
    for (size_t i = 0; i < ALPHABET_SIZE; i++)
    {
        node->children[i] = NULL;
    }
    node->is_word = false;
    return node;
}

static bool valid_word(const char *word)
{
    if (word[0] == '\0')
    {
        return false;
    }
    for (size_t i = 0; word[i] != '\0'; i++)
    {
        if (word[i] < 'a' || word[i] > 'z')
        {
            return false;
        }
    }
    return true;
}

static bool insert(TrieNode *root, const char *word)
{
    if (!valid_word(word))
    {
        return false;
    }
    TrieNode *current = root;
    for (size_t i = 0; word[i] != '\0'; i++)
    {
        size_t index = (size_t) (word[i] - 'a');
        if (current->children[index] == NULL)
        {
            current->children[index] = new_node();
            if (current->children[index] == NULL)
            {
                return false;
            }
        }
        current = current->children[index];
    }
    current->is_word = true;
    return true;
}

static bool contains(const TrieNode *root, const char *word)
{
    if (!valid_word(word))
    {
        return false;
    }
    const TrieNode *current = root;
    for (size_t i = 0; word[i] != '\0'; i++)
    {
        size_t index = (size_t) (word[i] - 'a');
        current = current->children[index];
        if (current == NULL)
        {
            return false;
        }
    }
    return current->is_word;
}

static void free_trie(TrieNode *node)
{
    if (node == NULL)
    {
        return;
    }
    for (size_t i = 0; i < ALPHABET_SIZE; i++)
    {
        free_trie(node->children[i]);
    }
    free(node);
}

int main(void)
{
    TrieNode *root = new_node();
    if (root == NULL)
    {
        fprintf(stderr, "could not allocate trie root\n");
        return 1;
    }
    if (!insert(root, "python") || !insert(root, "pytorch"))
    {
        fprintf(stderr, "could not insert word\n");
        free_trie(root);
        return 1;
    }
    printf("python: %s\n", contains(root, "python") ? "yes" : "no");
    printf("pytorch: %s\n", contains(root, "pytorch") ? "yes" : "no");
    printf("py: %s\n", contains(root, "py") ? "yes" : "no");
    printf("pythonic: %s\n", contains(root, "pythonic") ? "yes" : "no");
    free_trie(root);
    return 0;
}
```

预期输出：

```text
python: yes
pytorch: yes
py: no
pythonic: no
```

逐字符追踪 `insert(root, "python")`：`'p' - 'a'` 得索引 15，没有该子节点就建立；接着在 p 节点以索引 24 建立 y；继续经过 t、h、o、n，最后把 n 节点的 `is_word` 标为真。插入 `pytorch` 时，p、y、t 已存在；下一字符分别是 `python` 的 h 和 `pytorch` 的 o，所以从 t 节点分叉，`pytorch` 的后续路径是 o、r、c、h。查 `py` 可以走到 y，但 `is_word` 是 false，所以“它是某个已存词的前缀”不等于“完整词存在”。查找长度为 `L` 的单词会走 `L` 个字符，时间 `O(L)`；若字母表大小视为固定 26，可描述为相对输入字长线性，不能笼统说所有查询都是常数时间。每个节点固定保存 26 个指针，空间可能比只保存实际存在子节点的表示更大。

## 成本对照：没有一种结构到处最好

| 结构 / 操作 | 读取或查找 | 插入 | 内存与限制 |
| --- | --- | --- | --- |
| 普通数组 | 已知索引 `O(1)`；未排序查找 `O(n)` | 末尾有空容量时 `O(1)`；满容量搬移 `O(n)` | 连续，索引存取快；容量需要管理 |
| 动态数组 | 已知索引 `O(1)` | 追加摊销 `O(1)`，某次扩容 `O(n)` | 额外保留未用容量，必须正确管理 `realloc` |
| 单向链表 | 查找 `O(n)` | 头插 `O(1)`；指定节点后插 `O(1)` | 节点分散且每节点多一个指针，不可随机索引 |
| BST | 平均/平衡形状 `O(log n)`；最坏 `O(n)` | 同查找路径成本 | 不自动平衡；每节点左右指针 |
| 链表法哈希表 | 平均在分布良好时 `O(1 + alpha)`；最坏 `O(n)` | 平均近似常数；碰撞严重时变慢 | 要选 hash、桶数并处理碰撞 |
| Trie | `O(L)`，L 是键长 | `O(L)` | 固定分支表可能耗费较多节点/指针空间 |

复杂度是逐项操作的模型，不是对全部程序的单一评分。例：链表头插是 `O(1)`，但如果产品需求要按索引读第 900 个元素，链表要走过前面节点；数组的索引读更合适。若需要按键快速找到记录，可考虑哈希表，但也要评估键分布、碰撞、负载因子和内存。

1. 把 `grow_array.c` 初始容量由 2 改为 1，预测容量印出次数和最后容量。五笔输入下，最终容量应为 8，且元素顺序不变。

## 常见坑

1. 混淆 `size` 和 `capacity`：未填的容量格不是有效数据。
2. `realloc` 结果直接覆盖原指针：失败可能遗失唯一旧地址；用临时指针。
3. 头插链表时先改 `head` 再连接旧头：会丢失原链表入口。
4. `free(node)` 后才读 `node->next`：读取已释放节点；先保存下一个地址。
5. 认为 BST 一定 `O(log n)`：未平衡的 BST 可能退化成长度为 n 的链。
6. 哈希桶相同便认为键相同：hash 索引可能碰撞，必须比较完整键。
7. 认为 Trie 的任何前缀都是已存在单词：需要终止节点的 `is_word` 标记。
8. 只写成功路径，不处理 `malloc` / `realloc` 失败和清理：错误路径也是程序的一部分。

## 课后压缩

**一句话模型**：数据结构是在存取速度、更新成本与额外内存之间作选择。**最小模板**：节点含值与指针；创建时检查分配，成功后链接，结束时按所有权释放。**边界**：BST 不保证平衡；哈希表不保证无碰撞；Trie 查询成本取决于键长。**自测**：为什么动态数组偶尔搬很多元素，平均追加仍可摊销 `O(1)`？
