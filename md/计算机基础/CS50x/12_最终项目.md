# 12. 最终项目：自己决定做什么，并证明它能工作

> 原课程：David J. Malan 与 CS50 团队，Harvard University，[CS50x Final Project](https://cs50.harvard.edu/x/project/)。enkidu-613 中文改编与实践补充，非官方中文版，按 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/) 分享；[来源与许可](来源与许可.md)。

这一章不是再教一套框架，而是把选择、实现、测试、说明和交付接起来。你要能回答“为什么这样做、数据怎样变化、错了怎样查”，而不只是展示一个成功页面。

前置：完成前面各单元的课堂实验与相应练习。你不必在同一个项目里强行使用所有语言；根据要解决的问题选工具即可。

## 1. 官方要求与本地建议先分开

官方让你设计自己的软件，题材和语言可以选择，也可以在课程环境外开发。个人项目的投入应超过单次问题集；允许按官方规则与一两位同学协作，但贡献与项目规模也应相应增加。具体规则以[项目原页](https://cs50.harvard.edu/x/project/)为准。

**CS50x 不等于 CS50P。** 不要把 CS50P 的 `project.py`、至少三个额外函数与对应测试数量，误当成 CS50x 的统一结构要求。

下文的文档目录题材、功能分期、测试表和文件结构都是本项目的教学建议，不是 Harvard 强制规定。你可以换题材，但仍要有自己的需求与验证证据。

## 2. 先把需求缩到自己能讲清楚

贯穿课堂已经做过：文档记录、查找、SQL 表、网页与 Flask 请求。现在可以将它做成一个更完整的知识文档目录；它不必带大模型，也不需要先买服务器。

先在自己的项目目录创建 `PLAN.md`，用普通中文写下：

```text
使用者：谁会用？
问题：他现在做哪一步很麻烦？
输入：输入哪些字段？哪些输入应被拒绝？
输出：使用者最后能看见什么？
保存：重启后哪些数据必须还在？
失败：查不到、重复、无权限或保存失败时怎么办？
不做：这次明确排除什么？
证明：用哪些操作确认它真的工作？
```

这是计划模板，不是需要原样提交的官方格式。每项写得能对应到程序行为，比写“智能、高效、可扩展”更有帮助。

例子：把“做一个知识平台”缩成“用户能录入标题与摘要、按条件查找、编辑自己的记录，并在重启后继续读取”。暂不做向量搜索、爬虫、多人实时编辑与自动 Agent，就能把主要精力放在你亲自理解的流程上。

## 3. 分三次增加能力

| 阶段 | 新增结果 | 复用知识 | 必须验证的失败情况 |
| --- | --- | --- | --- |
| 先跑通 | 能录入并查询一条文档 | 表、参数化 SQL、函数 | 空标题、错误 ID、找不到记录 |
| 再接界面 | 表单提交后显示结果 | HTML、请求、路由、模板 | 非法表单、重复提交、HTML 转义 |
| 再补边界 | 编辑、归属、重启后重读 | 会话、权限检查、事务、文件库 | 越权、部分写入失败、未提交改动 |

第三阶段涉及身份验证时，不能沿用课堂“随便填个名字就算登录”的演示。正式发布前还需要成熟认证方式、凭据保护、CSRF 防护和部署审查；本轮本地作品可以先明确不开放公网。

如果最后发现功能做不完，先保留一个完整可运行的阶段，不要交付十个只有按钮、没有实现的入口。功能少与缺陷少是两回事，保留功能仍要验收。

## 4. 文件职责怎样分

一个 Python Web 项目可以这样组织；这是可选示意，不要求照搬：

```text
my_project/
  app.py              路由、请求参数、响应与应用启动
  catalog.py          文档规则和数据库操作
  templates/          HTML 模板
  static/             CSS、浏览器 JavaScript
  tests/              自动检查
  requirements.txt    运行所需依赖及可复现版本
  README.md           项目用途、运行和设计说明
```

路由负责接收请求并组织响应；普通业务函数负责判断和计算；数据库层负责查询、事务和连接。不要在路由和测试里各写一份相似但不同的规则。

不是文件越多越专业。两三个函数就能说清楚的项目，不必为了这个示意拆十个空模块；当职责混在一起影响测试和修改时再拆。

## 5. 一次请求要能这样追踪

选你自己实现的“创建文档”，逐步写出真实名称，不使用模糊的“系统自动处理”：

```text
浏览器提交表单
-> 路由取得字段
-> 普通函数验证标题等业务要求
-> 取得当前服务端已验证的用户身份
-> 参数化插入文档，成功提交或失败回滚
-> 路由重定向到结果页
-> 浏览器发出新的 GET
-> 路由查询记录并渲染模板
```

如果你的程序不是这个架构，按实际调用画，不强行让代码迎合流程图。关键是知道每一步由谁调用、读写什么、返回什么，尤其区分重定向响应与后续的新请求。

能解释“创建成功”的路径之后，再追踪非法输入或无权限：在哪一步停止？数据库有没有已经写入？响应有没有泄露不该显示的内容？

## 6. 不只测试成功情况

以下是本地建议的测试范围，不是官方给定的项目评分表：

| 输入或动作 | 应检查的结果 |
| --- | --- |
| 合法创建 | 返回预期状态，能按 ID 查到同一份数据 |
| 标题为空或类型不对 | 明确拒绝，没有留下半条记录 |
| 查询不存在的 ID | 给出约定的未找到结果，不暴露内部异常 |
| 文本包含 HTML 字符 | 显示为文本，不作为脚本执行 |
| 非本人尝试编辑 | 服务端拒绝，不能只隐藏按钮 |
| 第二条相关写入失败 | 第一条按事务约定一并撤销 |
| 关闭并重启 | 已提交的数据仍可读取 |
| 依赖重新安装后启动 | 运行说明没有依赖作者机器上的隐藏文件 |

纯函数适合单元测试；完整请求适合 Flask 测试客户端等集成检查；浏览器行为还要实际操作页面。三者互补，不用一个层面的成功替另一层背书。

先写一个确定会失败的检查，例如断言一个错误标题，再恢复正确预期，证明测试确实进入了目标执行路径。检查测试数量，避免把没有收集到测试当作全部通过。

## 7. README 要让别人能运行

至少说明：用途、功能边界、文件职责、依赖、启动步骤、必要环境变量、初始化数据、测试方法、已知限制和关键取舍。密钥只写变量名，不写真实值。

以下是本地写作提示，不是成品描述：

```text
为什么选择这个题材？
用户怎样完成一次完整操作？
每个主要文件做什么？
数据库为什么这样设计？
哪些失败情况已验证，哪些没有？
如果使用外部代码或 AI，哪些地方使用、如何核对？
```

官方提交还要求项目标题、演示视频 URL 和详细描述，并给出 README 深度与篇幅建议；不要把几行安装命令当成完整说明。提交时核对[How to Submit](https://cs50.harvard.edu/x/project/#how-to-submit)，不靠本地总结猜测当前要求。

## 8. 正式提交前再核对三步

按官方页面，提交包括演示视频和表单、项目源码与 README 的提交，以及进入 Gradebook 确认状态。视频有时长及开头信息要求，README 和代码要对应当前作品；当期提交命令、截止时间和登录方式直接从官方页读取，不在这里写一个可能过时的固定命令。

官方最终项目对外部 AI 工具有单独例外，仍要求工作的本质属于本人，并注明使用。这个例外不适用于其他问题集；不要提交自己不能解释和验证的生成代码。详见[项目说明](https://cs50.harvard.edu/x/project/)与[诚信规则](https://cs50.harvard.edu/x/honesty/)。

本地老师或工具说“通过”不等于课程已经授予证书。注册、正式作业、项目评阅与完成状态由课程官方系统判定。

## 最后一次自查

你能否独立完成并解释以下四项？

1. 需求到实现：说明一个功能为什么需要这些数据和函数。
2. 实现到结果：从输入追踪到保存、响应和显示。
3. 失败到修复：展示一个真实错误及验证修复的方法。
4. 当前到以后：说明一个明确限制，为什么本次没有继续增加复杂度。

做不到的地方回对应单元补，不靠再加一层框架掩盖。做到之后，带着作品和问题回到[原来的 AI 主线](../../README.md)；也可继续上一级[应用基础综合实践](../08_综合实践与入门验收.md)，但不要把相同劳动机械做两遍。
