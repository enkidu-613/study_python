## 本章学什么

本章把前一章“固定数据的 C 程序”推进到可复用的一组值和命令行输入：理解预处理、编译、汇编、链接四阶段；用调试器逐句检查变量；创建数组并遵守下标边界；理解 C 字符串其实是以 `\0` 结尾的 `char` 字节序列；比较字符串、计算长度、安全使用 `<ctype.h>`；从 `argc`/`argv` 读取参数、验证输入、返回退出码；实现一个仅供教学的字母轮转变换。

本章不讲指针算术、动态内存、文件 I/O、Unicode 字符级编辑、生产级密码学。这些边界很重要：C 字符串 API 面向以零字节结束的字节序列，不会自动把 UTF-8 当作“一个汉字一个字符”。

**前置**：会读懂 `main`、函数、循环和条件。本章仍围绕目录的三条记录：`1 Python owner 7`、`2 HTTP owner 7`、`3 SQL owner 9`。示例从命令行读轮转数和一句话，只处理 ASCII 英文字母，不连接或修改任何应用/数据库。

## 1. 完整程序先跑起来

将下面完整代码保存为 `examples/cs50x/02_rotate.c`。程序先打印固定目录 ID 数组，再从命令行接收一个 0–25 的整数和短文本，对 ASCII 字母做 Caesar 轮转，并输出 `strlen` 的字节数。它检查参数数量、数字格式、范围和整数解析溢出。

```c
#include <ctype.h>
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void print_ids(const int ids[], size_t length);
void print_rotated(const char *text, int key);

int main(int argc, char *argv[])
{
    const int catalog_ids[] = {1, 2, 3};
    const size_t catalog_length = sizeof(catalog_ids) / sizeof(catalog_ids[0]);

    printf("Catalog IDs:");
    print_ids(catalog_ids, catalog_length);

    if (argc != 3)
    {
        fprintf(stderr, "Usage: %s KEY TEXT\n", argv[0]);
        return 1;
    }

    errno = 0;
    char *end = NULL;
    long parsed_key = strtol(argv[1], &end, 10);
    if (errno == ERANGE || end == argv[1] || *end != '\0'
        || parsed_key < 0 || parsed_key > 25)
    {
        fprintf(stderr, "KEY must be an integer from 0 to 25\n");
        return 2;
    }

    const char *text = argv[2];
    size_t byte_length = strlen(text);
    printf("Input bytes: %zu\n", byte_length);
    printf("Rotated: ");
    print_rotated(text, (int) parsed_key);
    printf("\n");
    return 0;
}

void print_ids(const int ids[], size_t length)
{
    for (size_t i = 0; i < length; i++)
    {
        printf(" %i", ids[i]);
    }
    printf("\n");
}

void print_rotated(const char *text, int key)
{
    size_t length = strlen(text);
    for (size_t i = 0; i < length; i++)
    {
        unsigned char byte = (unsigned char) text[i];
        if (isalpha(byte))
        {
            int upper = toupper(byte);
            if (upper >= 'A' && upper <= 'Z')
            {
                int offset = (upper - 'A' + key) % 26;
                putchar('A' + offset);
            }
            else
            {
                putchar(byte);
            }
        }
        else
        {
            putchar(byte);
        }
    }
}
```

從仓库根目录编译并运行：

```bash
cd examples/cs50x
cc -std=c11 -Wall -Wextra 02_rotate.c -o 02_rotate
./02_rotate 1 "Hello, world!"
```

预期输出：

```text
Catalog IDs: 1 2 3
Input bytes: 13
Rotated: IFMMP, XPSME!
```

错误输入也要观察：`./02_rotate 26 "Hello"` 应在标准错误输出 `KEY must be an integer from 0 to 25` 并以状态码 2 退出；少传参数应显示用法并以 1 退出。输入 `3x` 不是有效整数，因为 `strtol` 虽能解析前面的 3，但 `end` 指向的 `x` 说明剩余字符没有消费。

## 2. 从源文件到程序：四个构建阶段

编译器工具链不是一个神秘的单按钮。常见构建过程可概括为四阶段：

1. **预处理（preprocessing）**：处理 `#include`、宏等以 `#` 开始的预处理指令。比如让编译器能看到 `printf`、`strtol` 等声明。
2. **编译（compiling）**：把预处理后的 C 翻译成汇编语言，并检查许多语法/类型问题。编译器警告指出可疑代码，但不保证逻辑正确。
3. **汇编（assembling）**：把汇编指令转换成目标文件中的机器指令及相关符号信息。
4. **链接（linking）**：将目标文件和所需库组合，解析 `printf` 等外部符号，产出可执行文件。

`cc -std=c11 -Wall -Wextra source.c -o program` 通常驱动这些步骤。具体工具实现与中间文件格式依平台而异；这四个名字描述常见逻辑阶段，不保证每个编译器必须以四个独立可见进程实现。`-o` 的目标文件是编译产物；`./program` 才启动它。

CS50 页面可能演示 `make hello`、`clang ... -lcs50` 等命令。这套命令依赖其配置环境和库；本课程本机样例用标准库 `cc` 编译，不需要 `cs50.h`。不要在没有安装 CS50 库时把 `-lcs50` 粘贴到本机命令中。

## 3. 调试器：看程序此刻在哪

**调试（debugging）**是定位实际错误的过程；调试器让你暂停程序、观察状态，并逐步执行。VS Code 的界面和调试配置因版本、操作系统不同而异，这里先掌握概念，不假装为某个未核实界面提供逐像素按钮路线。

在本地 C/C++ 调试器中，可按这个流程操作：

1. 使用带调试信息的编译选项构建，例如在支持的 `cc` 上加入 `-g`，同时保留 `-Wall -Wextra`。
2. 在 `main` 的 `if (argc != 3)`、`strtol` 调用和 `if (errno...` 判断上设置**断点（breakpoint）**。断点让程序执行到某行前暂停。
3. 启动程序并传入参数 `1` 和 `Hello, world!`。检查 `argc`、`argv[1]`、`argv[2]`。
4. 用“逐过程（step over）”执行当前行；用“步入（step into）”进入函数调用；用“继续（continue）”运行到下个断点。
5. 在 `for` 循环处观察 `i` 从 0 到 `length-1`，以及 `byte`、`upper`、`offset` 的值。对 `Hello` 的首字母，`byte` 是 H，`upper` 是 H，`offset` 为 8，因此输出 I。
6. 再以 `3x` 启动，观察 `parsed_key` 得到前缀 3、`end` 指向字符 x，条件阻止程序将部分解析当成完整合法输入。

**变量观察**是当前栈帧/暂停位置相关的状态；执行一步后局部变量可能还不存在或已离开作用域。不要把调试器的“变量窗口空白”误判为变量值为 0。

如果当前环境没有图形调试器，不需安装新工具也可先通过可控的 `printf` 日志观察值；临时日志应指出变量名和阶段，并在分析后移除。日志也会改变输出，测试时需区分诊断输出与程序契约。

## 4. 数组：同类型值连续编号

`const int catalog_ids[] = {1, 2, 3};` 创建一个有 3 个 `int` 元素的数组。数组是同类型元素的有序集合，元素通过从 0 开始的下标访问：`catalog_ids[0]` 是 1，`[1]` 是 2，`[2]` 是 3。长度为 `n` 的数组合法下标范围是 `0` 到 `n-1`；`[3]` 已越界。

数组下标越界在 C 中不会自动变成一个安全的错误提示。读写超出数组对象边界会导致未定义行为，可能读到看似合理的垃圾值、损坏别的数据、崩溃或表现不一致。每次访问都要能说明为什么下标在有效范围内。

`sizeof(catalog_ids) / sizeof(catalog_ids[0])` 在数组仍处于声明它的作用域时，用整个数组字节数除以单个元素字节数，得到元素个数。不要把这个写法复制到一个函数的数组形参上：函数参数中的 `int ids[]` 会调整为指针形参，`sizeof(ids)` 得到指针大小，不是原始数组长度。

因此函数同时接收数组和长度：

```text
print_ids(catalog_ids, catalog_length)
```

在完整代码里，形参写作 `const int ids[]` 与接收只读整数序列的意图相符，调用时实际传递数组首元素地址；`length` 单独告诉函数最多读取多少元素。函数通过 `for (i < length)` 保证最后访问的下标为 `length-1`。`const` 限制函数通过该形参修改元素，不会让原数组自动拥有边界检查。

## 5. 字符串：字符数组和结束标记

C 没有内建的 `string` 类型。所谓 C 字符串通常是一串 `char` 字节，末尾以值为零的**空字符（null character，写作 `\0`）**标记结束。例如文字 `cat` 的内存序列概念上是：

```text
'c'  'a'  't'  '\0'
```

若手动声明 `char word[4] = "cat";`，4 个位置分别放 `c`、`a`、`t`、结尾零字节。数组容量必须为可存文字字节数加 1。字符串长度不包括终止 `\0`，而数组容量包括这一个位置。

标准库 `<string.h>` 的 `strlen(s)` 逐字节寻找 `\0`，返回终止符之前的字节数；它不包含终止符。若数组没有合法的 `\0`，`strlen` 会继续越界读取，所以传给它的必须是有效的 C 字符串。

比较字符串要用 `strcmp(a, b)`，不要写 `a == b` 来比较内容。`strcmp` 返回负数、0、正数，分别表示按字节比较小于、相等、大于；只有结果等于 0 才表示字符串相等。`a == b` 比较的是两个指针值是否相同，不是文本是否相同。

本课程此处用 ASCII 文本观察长度。UTF-8 汉字通常由多个 `char` 字节组成，`strlen` 数的是编码字节，不是用户感知的字形或 Unicode 码点个数；截断 UTF-8 字节还可能把字符切坏。对自然语言文本做用户可见字符操作需要专门 Unicode 库和明确语义，超出本章范围。

## 6. `<ctype.h>` 的安全调用

`<ctype.h>` 提供 `isalpha`、`toupper` 等字符分类/转换函数。它们接收 `int`，合法输入应为 `EOF` 或可表示为 `unsigned char` 的值。若普通 `char` 在当前实现是有符号，字节值大于 127 可能成为负数；直接传负 `char` 会触发未定义行为。

因此代码先转换：

```text
unsigned char byte = (unsigned char) text[i];
if (isalpha(byte)) { ... }
int upper = toupper(byte);
```

此模式防止将负 `char` 传给 `ctype`。实际可执行版本已包含完整上下文，见前文 `print_rotated`；这里的文字仅用于突出规则。`ctype` 的分类会受当前 C locale 影响；本教学变换只对转换后的 ASCII `A` 到 `Z` 执行轮转，其他字节原样输出。

## 7. 命令行参数：`argc`、`argv` 和退出状态

入口签名 `int main(int argc, char *argv[])` 接收操作系统传来的命令行参数。`argc` 是参数个数；`argv` 是字符串指针数组。`argv[0]` 通常是程序名，用户给出的第一个参数在 `argv[1]`。因此运行 `./02_rotate 1 "Hello, world!"` 时，`argc` 为 3，`argv[1]` 指向文本 `1`，`argv[2]` 指向整句。引号由 shell 用来把含空格内容作为一个参数；引号本身不属于参数。

`argv[argc]` 是空指针，表示参数列表结束；通常先检查 `argc` 再访问 `argv[1]` 或 `argv[2]`。如果参数个数不足，访问不存在的槽位会越界。C 标准规定 `argv[argc]` 为空指针，但程序不应假设参数文字一定是合法数字。

`strtol` 是 `<stdlib.h>` 的字符串到 `long` 转换函数。代码先将 `errno` 设为 0，然后调用 `strtol(argv[1], &end, 10)`：

先拆开这三个容易混淆的写法：`char *end` 声明一个指针变量 `end`，它保存某个 `char` 的地址；星号在声明里表示“这是指针类型”，不是此处读取字符。`&end` 取得变量 `end` 自己的地址，类型是 `char **`；传给 `strtol` 后，函数可把“解析停止位置的地址”写回 `end`。`*end` 则是在调用返回后沿着 `end` 保存的地址读取那个字符，因此 `*end != '\0'` 可以检查是否还剩未解析字符。这里的 `NULL` 是表示“空指针/不指向有效对象”的宏；`'\0'` 是值为零的字符，用作 C 字符串结束符。两者用途和类型不同，不能互换。

- `10` 指按十进制解析。
- `end` 接收解析停止的位置；若等于原字符串首地址，代表一个字符也没解析。
- `*end != '\0'` 表示有未解析尾随内容，例如 `3x`。
- `errno == ERANGE` 检查超出 `long` 可表示范围的输入。
- 之后再验证业务范围 0 到 25，最后才转换为 `int`。

本代码里的 `size_t` 是标准库用来表示对象大小/长度的无符号整数类型（定义见 `<stddef.h>`，也会由相关标准头文件提供）。`strlen` 返回 `size_t`，`sizeof(expression)` 的结果类型也是 `size_t`；因此完整程序用 `size_t` 保存字节长度和数组长度，并用 `printf` 的 `%zu` 格式输出。不要为了让长度“看起来像 int”就随意窄化转换，超大对象的长度可能装不进 `int`。

强制类型转换（cast）形如 `(目标类型) 表达式`，明确要求把表达式转换成目标类型。示例中的 `(unsigned char) text[i]` 在传入 `isalpha` 前，将可能为负的普通 `char` 值转成 `unsigned char` 的有效范围；`(int) parsed_key` 则只在已验证 0–25 后执行，所以该转换不会丢掉本例需要的值。强制转换不会自动验证输入是否合法，也不能用来掩盖范围错误。

只检查数值范围不够；必须同时检查是否完整解析且无转换溢出。`atoi` 无法可靠区分无效文本与合法的 0，因此本例不使用它。避免把 `scanf("%d", &key)` 当作安全解析模板；输入格式和超范围处理需要显式设计。

程序返回值成为**退出状态（exit status）**：0 通常表示成功，非零表示错误。命令行 shell 中运行 `echo $?` 可查看上一命令的状态；本例对参数数量错误返回 1，对键值错误返回 2。`stderr`（标准错误）用于诊断信息，和正常结果的 `stdout` 分开。

## 8. 逐段追踪 Caesar 字母轮转

令 `KEY=1`，文本为 `Hello, world!`：

1. Shell 将三个参数交给 `main`：程序名、`1`、`Hello, world!`。因此数量检查通过。
2. `strtol` 解析 `1` 得到 `long` 值 1，`end` 指向末尾零字节，范围检查通过。
3. `strlen` 计算输入是 13 个字节：字母 5 + 逗号 1 + 空格 1 + 字母 5 + 感叹号 1，共 13。
4. 循环 `i` 从 0 到 12。每次先把 `text[i]` 转为 `unsigned char`，再处理。
5. `H` 经 `toupper` 得 `H`。`H-'A'` 是 7，加 1 得 8，模 26 仍为 8；`'A'+8` 是 `I`。
6. 小写 `e` 先被 `toupper` 变成 `E`，随后同样计算出 `F`。本例统一输出大写字母。
7. 逗号、空格、感叹号不是 ASCII 字母，原样输出。
8. 每次 `putchar` 写一个字节；循环结束后 `main` 输出换行并返回 0。

完整程序以固定目录 ID 数组作为数据起点，并将 `argc`/`argv` 输入独立处理。它没有把目录写入文件或数据库；那些会引入不同生命周期和错误边界，留待后续章节。

## 9. 加密练习的安全边界

Caesar 变换只是把每个英文字母按固定偏移移动。26 种可能的键很容易穷举，频率模式也保留，因此它**不是现代加密**，不能保护密码、个人资料或网络通信。它只用于练习字符编码、数组遍历和参数解析。

也不要把这里的 `% 26` 当作通用 Unicode 字符处理。字节轮转会损坏 UTF-8 多字节序列；本例对非 ASCII 字节通常只原样写回。对真实安全需求，使用经过审查的密码学库和协议，不能自行发明算法。

## 10. 独立练习：目录 ID 查询

写一个新的完整程序 `03_find_id.c`：固定数组 `{1, 2, 3}` 代表目录 ID；从唯一命令行参数解析要查找的整数；逐个比较；找到输出 `found: ID`，否则输出 `not found`。数组通过函数参数传递时，函数也必须显式接收长度。不要使用 `cs50.h`。

**运行契约**：

```text
./03_find_id 2   -> found: 2，退出状态 0
./03_find_id 8   -> not found，退出状态 0
./03_find_id abc -> 诊断写到 stderr，非零退出状态
./03_find_id     -> 显示用法，非零退出状态
```

**验收**：先检查参数个数，再完整解析整数，再遍历；所有数组访问都必须满足 `0 <= i < length`；比较字符串时不能误用 `==`；用 `echo $?` 检查成功/失败状态。写完后尝试输入特别大的整数，确认不会把解析溢出当作合法 ID。定位提示：把调试器断点放在转换后和循环条件处，观察 `end`、`i` 与 `length`。

## 常见坑

- 数组长度为 3 却访问 `a[3]`。最后合法下标是 2；C 不会替你检查。
- 把数组传入函数后期待函数知道原本长度。数组参数会调整为指针，长度要另传。
- 以为 `sizeof(array)` 在函数数组形参内仍代表整个数组。它通常只会得到指针大小。
- 把 `strlen` 当作字符数。它计算的是 `\0` 前的字节数。
- 忘记字符串结尾的 `\0`，或给 `char` 数组只留了文字字节数，没有额外结尾位置。
- 写 `strcmp(a, b) == 1` 判断“不相等”。非零返回值不保证恰好为 1；用 `!= 0`。
- 把可能为负的 `char` 直接传给 `isalpha`/`toupper`。先转换为 `unsigned char`。
- 只看 `strtol` 返回数字，不检查 `end` 和 `errno`，让 `3x`、巨大数混进业务逻辑。
- 不检查 `argc` 就访问 `argv[1]`，或误以为引号会传进 `argv`。
- 把 Caesar 轮转当成加密保护，或对 UTF-8 字节逐个轮转。

官方 [Problem Set 2](https://cs50.harvard.edu/x/psets/2/) 包括 Scrabble（拼字计分）、Readability（可读性分析）和 Caesar/Substitution（凯撒/替换密码，二选一）。前两题练习字符串遍历、字符处理和计算；密码题将命令行参数、字符转换与输入验证放到一起。具体要求以官方页面为准。本讲义独立目录查询器是自编练习，不是官方题解；不要将 Caesar 演示误认为官方作业的完整实现。

官方讲义：[Lecture 2 Notes](https://cs50.harvard.edu/x/notes/2/)。可参考官方页面的 Debugging、Compiling、Arrays、Strings、String Length、Command-Line Arguments、Exit Status 各节。

## 课后压缩

- 心智模型：数组是有界的同类型槽位；C 字符串是由 `\0` 终止的字节序列；命令行参数也是字符串，必须验证后再使用。
- 关键链路：`argc` 检查 → `strtol` 完整解析 → 溢出/范围检查 → 遍历有效下标 → 输出 → 返回状态码。
- 边界：数组传参不携带长度；`strlen` 数字节；ctype 输入先转 `unsigned char`；Caesar 仅教学。
- 复习问题：`char word[4] = "cat";` 为什么长度是 3、容量是 4？函数拿到 `word` 后为何仍需要另传 `length`？
