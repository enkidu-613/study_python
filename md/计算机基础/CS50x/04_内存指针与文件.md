## 先看完整程序：地址、值与指针

文件名：`pointers.c`。程序地址会因运行和系统而变；本机常见输出为带 `0x` 的十六进制形式，但 `%p` 的具体格式由实现决定，不应期待固定数字。

```c
#include <stdio.h>

static void swap(int *left, int *right)
{
    int temporary = *left;
    *left = *right;
    *right = temporary;
}

int main(void)
{
    int document_id = 7;
    int *id_address = &document_id;
    char title[] = "Python";

    printf("id value: %d\n", document_id);
    printf("id address: %p\n", (void *) id_address);
    printf("value through pointer: %d\n", *id_address);
    printf("title characters:");
    for (size_t i = 0; i < sizeof(title) - 1; i++)
    {
        printf(" %c", title[i]);
    }
    printf("\n");
    printf("pointer walk: ");
    for (char *cursor = title; cursor < title + sizeof(title) - 1; cursor++)
    {
        putchar(*cursor);
    }
    printf("\n");

    int first = 7;
    int second = 9;
    swap(&first, &second);
    printf("after swap: first=%d second=%d\n", first, second);
    return 0;
}
```

预期输出形式（地址会变化；`%p` 的精确格式由 C 实现决定，常见形式是 `0x...`）：

```text
id value: 7
id address: 0x...
value through pointer: 7
title characters: P y t h o n
pointer walk: Python
after swap: first=9 second=7
```

### 按执行顺序追踪

1. `int document_id = 7;` 建立一个整数对象，名字 `document_id` 对应它的值 7。
2. `&document_id` 是“取得这个对象的地址”；`&` 是取地址运算符。地址用十六进制打印，是因为内存位置通常用十六进制表示。十六进制以 16 为底，数字符号为 `0` 到 `9` 和 `A` 到 `F`；`0x` 是常见的十六进制前缀。它只是同一数值的另一种写法，并不代表变量 7 被改成了另一个值。`%p` 负责以具体 C 实现定义的格式打印 `void *` 地址，所以每次运行显示不同地址是正常的。
3. `int *id_address` 声明一个指向 `int` 的指针变量，里面保存刚取得的地址。声明中的星号表示“这个变量是指针”；`*id_address` 在表达式中表示沿地址读取那个 `int`，这叫**解引用（dereference）**。
4. `swap(&first, &second)` 把两个变量的地址传入函数。参数 `left`、`right` 是指针的副本，但副本仍指向原来的两个整数，因此 `*left = *right` 修改的是调用者的 `first`。
5. `temporary` 先保存第一个值，避免第二行覆盖它。执行后 `first=9`、`second=7`。

`cursor++` 是**指针算术（pointer arithmetic）**：因为 `cursor` 指向 `char`，加 1 会前进一个 `char` 元素，而不是任意猜测增加一个字节数。只允许在同一个数组内移动，或移动到“尾后位置”（one past the end）；尾后位置可用于比较范围，但不可解引用。此循环上限排除结尾 `\0`，每次解引用都仍指向 `title` 数组内的一个实际字符。

指针不是“值本身的别名”，而是一个保存地址的对象。只有当指针保存有效且对齐的地址，并指向类型正确、仍在生命周期内的对象时，才能安全解引用。空指针 `NULL` 表示“当前没有可用目标”；解引用 `NULL` 是错误的。

## 字符串、比较与复制

C 没有内置的可变长字符串对象。字符串通常是以空字符 `\0` 结尾的 `char` 数组；例如 `"Python"` 实际包含 7 个字符位置：`P y t h o n \0`。数组声明 `char title[] = "Python";` 会为这 7 个字符提供空间。

数组传给函数时，通常会转换为指向首元素的指针。`char *title` 表示“指向字符的地址”，不会告诉函数缓冲区有多大；所以调用 C 字符串 API 的代码必须另外确保容量和终止符。

比较字符串内容应使用标准库 `<string.h>` 的 `strcmp(a, b)`：返回 0 表示内容相同，小于 0 或大于 0 表示字典序先后。`a == b` 比较的是两个指针是否保存同一地址，不是字符是否相同。复制时，`strcpy(destination, source)` 不知道目标数组的容量，只有在已证明容量足够时才能调用。

下面是完整且容量可证明足够的示例。文件名：`strings.c`。

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char title[16] = "Python";
    const char source[] = "SQL";
    char copy[sizeof(source)];

    if (strcmp(title, "Python") == 0)
    {
        printf("same text\n");
    }
    memcpy(copy, source, sizeof(source));
    printf("copied: %s\n", copy);
    return 0;
}
```

预期输出：

```text
same text
copied: SQL
```

`source` 的 `sizeof` 包含结尾的 `\0`，`copy` 也按这个大小创建；`memcpy` 复制的字节数因此包含终止符。这里 `sizeof` 用于仍在作用域中的数组，而不是已经退化成指针的函数参数。

## 值传递、通过地址修改对象

C 的函数参数采用**值传递（pass by value）**：调用者提供的参数值会复制给形参。普通整数形参拿到整数副本，修改它不会改变调用者的变量。指针形参同样是值传递，只不过副本里保存的是地址；通过地址解引用后，可以修改那个地址指向的对象。这也是上面的 `swap` 能交换调用者变量的原因。

追踪 `swap(&first, &second)`：调用者的 `first` 地址传给局部形参 `left`；`second` 地址传给 `right`。`temporary = *left` 读出 7，`*left = *right` 将调用者的 `first` 改成 9，最后 `*right = temporary` 将 `second` 改成 7。函数返回后，两个局部指针形参消失，两个原整数仍处于 `main` 的生命周期内。

不要返回局部变量的地址。函数返回时，局部自动变量的生命周期结束；留下的地址就悬空了。正确做法可以是由调用者提供输出位置、返回一个值，或明确分配动态内存并约定由谁负责释放。

## 内存位置与对象生命周期

把程序内存想象成许多带地址的格子，有助于理解；但“stack 与 heap 的示意图”不是 C 语言标准保证的实际硬件布局。

- **自动存储期（automatic storage duration）**：函数内局部变量常见的生命周期。执行进入相应代码块时变量存在，离开代码块后生命周期结束。调用嵌套函数时，运行环境通常用调用栈保存每次调用的参数和局部状态。
- **堆（heap）**：教学中对动态分配区域的常见称呼。通过 `malloc` 等函数取得的空间，不会因离开普通代码块而自动释放；程序必须管理它的所有权，并在最后调用 `free`。
- **静态存储期**：例如文件作用域的全局变量，其生命周期通常覆盖整个程序运行。本章不需要使用全局状态。

最重要的规则不是背一张内存地图，而是问：**这个指针当前指向的对象还在生命周期内吗？谁负责让它停止使用？**

## 动态分配与安全释放

当数据大小只有运行时才知道，或数据必须比当前函数代码块存活更久时，可以使用 `malloc`。它声明在 `<stdlib.h>` 中，接收要分配的字节数，成功时返回指向空间起点的 `void *`，失败时返回 `NULL`。不必强制转换返回值；把结果赋给合适类型的指针即可。新空间的内容未初始化，不能直接当作有效数字或字符串使用。

下面的完整程序申请 3 个文档 ID 的整型空间，写入、打印并释放。文件名：`allocate_ids.c`。

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    const size_t count = 3;
    int *ids = malloc(count * sizeof(*ids));
    if (ids == NULL)
    {
        fprintf(stderr, "could not allocate IDs\n");
        return 1;
    }

    ids[0] = 1;
    ids[1] = 2;
    ids[2] = 3;
    for (size_t i = 0; i < count; i++)
    {
        printf("id[%zu]=%d\n", i, ids[i]);
    }

    free(ids);
    ids = NULL;
    return 0;
}
```

预期输出：

```text
id[0]=1
id[1]=2
id[2]=3
```

`sizeof(*ids)` 让分配大小跟随指针实际指向的元素类型。`count` 是 3，因此合法索引为 0、1、2；索引 3 越界。`free(ids)` 将这块内存交还给运行环境；之后把本地指针设为 `NULL`，可降低同一路径误用旧地址的概率。设为 `NULL` 不会“修复”其他指向同一块空间的别名。

几个错误术语要分清：

- **越界（out-of-bounds）**：访问数组或分配区域允许范围之外的位置，行为未定义。
- **未初始化读取（uninitialized read）**：在写入有效值之前读取尚未初始化的分配内容；不能把任意旧位当作数据。
- **悬空指针（dangling pointer）**：对象生命周期结束或空间已释放，指针却仍被当作有效地址使用。
- **内存泄漏（memory leak）**：分配空间失去所有可用的持有者，程序结束前未释放；反复发生会逐渐耗尽可用内存。
- **缓冲区溢出（buffer overflow）**：写入超过缓冲区容量，可能破坏其他状态；不能用“这次刚好没崩”证明安全。
- **栈溢出（stack overflow）**：例如无限递归令调用栈持续增长，超出可用资源；它与写越数组边界的成因不同，但都可能造成严重错误。
- **段错误（segmentation fault）**：操作系统常见的错误报告之一，表示程序尝试了不允许的内存访问；并非所有越界或错误指针都会立刻以段错误呈现。

不要执行这些错误操作来“看看会怎样”；它们属于未定义行为，输出不可靠，也可能破坏程序状态。

## `realloc` 预告与所有权

后续会用 `realloc` 扩容数组。以下规则限定 `new_size > 0`；大小为零有特殊且依标准版本而异的处理方式，本课程示例避免传入零。对于正大小，它可能在原位置扩大，也可能搬到新位置并释放旧位置；如果失败则返回 `NULL`，而原来的内存块仍然有效。正确模式是先用临时指针接收结果，确认非 `NULL` 后再更新唯一持有者。直接写 `items = realloc(items, new_size)` 会在失败时丢失旧地址，造成泄漏。完整扩容程序见[05｜数据结构的实现](05_数据结构的实现.md)。

**所有权（ownership）**是程序设计者对“谁负责释放这个资源”的约定，不是 C 编译器自动管理的概念。创建对象的一方通常要明确把释放责任交给别人，或在所有使用结束后自行释放；同一块内存只能释放一次，释放后不能再读写。

## 文件是字节流

**文件 I/O（file input/output）**是程序从文件读取或写入数据的标准库操作。`fopen(path, mode)` 返回 `FILE *`，打开失败时返回 `NULL`；`fread(buffer, element_size, element_count, file)` 返回实际读到的元素数；`fwrite` 返回实际写出的元素数；`fclose` 返回 0 表示成功，非 0 表示关闭或刷新时发生错误。这些函数声明在 `<stdio.h>` 中。

文件不只有“文本行”这一种形式。二进制模式 `rb` / `wb` 按字节读写，不替你进行文本编码转换。文件内容可能是文本、音频、压缩数据或图像。二进制图像通常有**文件头（header）**描述尺寸、格式等信息，后面才是像素数据；把每个字节都当成图像像素会丢失结构。

### 可运行的二进制复制程序

文件名：`file_bytes.c`。完整程序检查命令行参数、文件打开、读写数量和关闭结果。复制任意原始字节并不理解这些字节代表什么。

```c
#include <stdio.h>

int main(int argc, char *argv[])
{
    if (argc != 3)
    {
        fprintf(stderr, "usage: file_bytes source destination\n");
        return 1;
    }

    FILE *source = fopen(argv[1], "rb");
    if (source == NULL)
    {
        perror("open source");
        return 1;
    }
    FILE *destination = fopen(argv[2], "wbx");
    if (destination == NULL)
    {
        perror("open destination");
        fclose(source);
        return 1;
    }

    unsigned char buffer[256];
    int status = 0;
    size_t bytes_read;
    while ((bytes_read = fread(buffer, 1, sizeof(buffer), source)) > 0)
    {
        size_t bytes_written = fwrite(buffer, 1, bytes_read, destination);
        if (bytes_written != bytes_read)
        {
            perror("write destination");
            status = 1;
            break;
        }
    }
    if (ferror(source))
    {
        perror("read source");
        status = 1;
    }
    if (fclose(destination) != 0)
    {
        perror("close destination");
        status = 1;
    }
    if (fclose(source) != 0)
    {
        perror("close source");
        status = 1;
    }
    if (status == 0)
    {
        printf("copy complete\n");
    }
    return status;
}
```

命令 `./file_bytes "$source_file" copied-01.bin` 成功时预期打印 `copy complete`；目标文件与源文件的字节内容一致。指定不存在的源文件时会报错并以非 0 状态结束。目标模式 `wbx` 是 C11 的二进制写入加独占创建：目标不存在时创建，若已存在则打开失败，不会截断旧文件。重复运行时请换一个未使用过的目标名。它也防止把源路径误作目标路径后先截断源文件，因为已打开的源文件必然存在，而 `x` 模式拒绝打开已有目标。

执行追踪：`argc` 必须为 3；`argv[1]` 是源路径，`argv[2]` 是目标路径。每轮 `fread` 最多把 256 个字节放进 `buffer`；返回的 `bytes_read` 可能小于 256，最后一次尤其如此。`fwrite` 必须报告写出了相同数量。读到 0 可能表示文件结束，也可能是读取错误，所以要再用 `ferror(source)` 区分。最后无论成功与否都尝试关闭已经成功打开的两个文件，并检查返回状态。

### 一个小型自定义图像记录

下面的示例用自定义迷你格式说明“文件头 + 像素字节”，**不是 BMP、PNG 或 CS50 官方图像题的格式/解答**。它把两个尺寸字节 `[2, 1]` 当作宽和高，后面放两个灰度像素 `[30, 220]`。这个自定义格式只为方便直观看清结构；真实格式需要按规范处理字段大小、字节序、压缩和错误输入。

文件名：`tiny_image.c`。程序用 C11 `wbx` 独占创建一个四字节的演示文件，再读回来并验证，最后打印宽、高和像素值。再次运行时请换一个新文件名，避免覆盖已有文件：

```c
#include <stdio.h>

int main(void)
{
    const unsigned char record[] = {2, 1, 30, 220};
    FILE *file = fopen("tiny-image.bin", "wbx");
    if (file == NULL)
    {
        perror("open for write");
        return 1;
    }
    if (fwrite(record, 1, sizeof(record), file) != sizeof(record))
    {
        perror("write image record");
        fclose(file);
        return 1;
    }
    if (fclose(file) != 0)
    {
        perror("close after write");
        return 1;
    }

    unsigned char loaded[sizeof(record)];
    file = fopen("tiny-image.bin", "rb");
    if (file == NULL)
    {
        perror("open for read");
        return 1;
    }
    size_t count = fread(loaded, 1, sizeof(loaded), file);
    int extra = fgetc(file);
    int read_error = ferror(file);
    int close_status = fclose(file);
    if (count != sizeof(loaded) || extra != EOF || read_error || close_status != 0)
    {
        fprintf(stderr, "unexpected image record length or close error\n");
        return 1;
    }
    printf("width=%u height=%u pixels=%u,%u\n",
           (unsigned) loaded[0], (unsigned) loaded[1],
           (unsigned) loaded[2], (unsigned) loaded[3]);
    return 0;
}
```

预期输出：`width=2 height=1 pixels=30,220`。文件头占前两个字节，像素区接在后面。`fread` 读满 4 个字节后，再用 `fgetc` 确认没有多余数据；这不是通用文件解析器，只是在这个固定长度示例中验证约定。

## 修改验证与独立需求

修改 `pointers.c`，把 `swap` 的参数改成普通 `int`，并在函数中交换参数；预测输出仍是 `first=7 second=9`，因为函数只修改副本。恢复指针版本后，把示例字符串从 `"Python"` 改为 `"SQL"`，再次运行并确认字符循环只输出 `S Q L`，指针遍历输出 `SQL`。两个循环都根据 `sizeof(title) - 1` 计算实际字符数，不会继续访问原先固定的第 4、5 个下标；数组容量还包含结尾的 `\0`。

**独立完成**：写一个安全的文件复制工具，输入源和目标两个路径；每次最多读取 128 字节，以二进制模式复制，并检查空参数、打开失败、读写错误和 `fclose` 返回值。允许使用标准 C 库，不依赖第三方包。验收：复制空文件、长度正好为 128 字节和 129 字节的文件；比较源和目标的字节数及内容；使用不存在的源文件，确认程序不会误报成功；确保源文件打开后若目标打开失败，仍会关闭源文件。定位提示：逐个列出“成功取得的资源”，确保每条返回路径都会关闭已经打开的文件。

## 常见问题

1. `&x` 是地址，`*p` 是沿地址读写；声明 `int *p` 中的 `*` 表示指针类型，不是乘法。
2. `char *s = "..."` 指向字符串字面值；不要通过它修改字面值。要修改字符，使用容量足够的字符数组。
3. `==` 比较指针地址；`strcmp` 比较字符串内容，相等时返回 0。
4. `malloc` 不保证内容清零；检查 `NULL`，先初始化再读取。
5. `free` 后继续使用指针、重复 `free`，或返回局部数组的地址都不安全。
6. `fread` 的返回值是读到的元素数；只有 `element_size=1` 时才等于字节数。不要只看“不是 EOF”就假设所有内容都已读完。
7. 忘记 `fclose`：写入可能尚未完整刷新，资源也没有按约定释放。

### 使用 `scanf` 的边界

`scanf` 是 `<stdio.h>` 中的格式化输入函数。读取整数时要把目标地址交给它，并检查成功读取的字段数；如果没有成功读入，变量就不能当作有效输入。读取字符串时，`%s` 会一直读到空白；不限制宽度可能把任意长的输入写进较小的字符数组，造成缓冲区溢出。即使设置最大宽度，也要为结尾的 `\0` 留一个位置，并处理行尾剩余输入。本章不把危险格式写成可运行示例；简单的课程输入可使用官方 CS50 环境中的 `get_int` / `get_string`，标准 C 程序则需要采用有容量约定、能处理失败的输入方案。

## 课后速记

**一句话模型**：指针保存地址；只有目标仍在生命周期内、范围正确且所有权清楚时才能解引用。**最小模板**：`T *p = &value;`，通过 `*p` 读取或修改；动态分配后检查失败，最后 `free`。**边界**：指针参数仍按值传递；文件是字节流，格式解释需要另有规范。**自测**：`fread` 返回 0 时，怎样区分文件结束和读取错误？
