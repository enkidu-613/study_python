## 先看完整程序

文件名：`algorithms.c`。运行后每个排序都从相同的 `{7, 2, 5, 2, 9}` 开始。程序会显示中间轮次，重复元素也会保留。

本程序中的辅助函数写成文件作用域的 `static`，意思是这些函数名只在当前 `.c` 源文件内部可见，避免与其他源文件中的同名函数冲突。它和函数内部的 `static` 局部变量不是一回事；这里的函数没有静态局部变量。

```c
#include <stdbool.h>
#include <stdio.h>

static void print_array(const char *label, const int values[], int length)
{
    printf("%s", label);
    for (int i = 0; i < length; i++)
    {
        printf("%s%d", i == 0 ? "" : " ", values[i]);
    }
    printf("\n");
}

static int linear_search(const int values[], int length, int target)
{
    for (int i = 0; i < length; i++)
    {
        printf("linear: check index %d = %d\n", i, values[i]);
        if (values[i] == target)
        {
            return i;
        }
    }
    return -1;
}

static int binary_search(const int values[], int length, int target)
{
    int low = 0;
    int high = length - 1;
    while (low <= high)
    {
        int middle = low + (high - low) / 2;
        printf("binary: low=%d middle=%d high=%d value=%d\n",
               low, middle, high, values[middle]);
        if (values[middle] == target)
        {
            return middle;
        }
        if (values[middle] < target)
        {
            low = middle + 1;
        }
        else
        {
            high = middle - 1;
        }
    }
    return -1;
}

static void bubble_sort(int values[], int length)
{
    for (int end = length - 1; end > 0; end--)
    {
        bool swapped = false;
        for (int i = 0; i < end; i++)
        {
            if (values[i] > values[i + 1])
            {
                int temporary = values[i];
                values[i] = values[i + 1];
                values[i + 1] = temporary;
                swapped = true;
            }
        }
        print_array("bubble: ", values, length);
        if (!swapped)
        {
            break;
        }
    }
}

static void selection_sort(int values[], int length)
{
    for (int start = 0; start < length - 1; start++)
    {
        int smallest = start;
        for (int i = start + 1; i < length; i++)
        {
            if (values[i] < values[smallest])
            {
                smallest = i;
            }
        }
        int temporary = values[start];
        values[start] = values[smallest];
        values[smallest] = temporary;
        print_array("select: ", values, length);
    }
}

static void merge(int values[], int temporary[], int left, int middle, int right)
{
    int left_index = left;
    int right_index = middle;
    int output_index = left;

    while (left_index < middle && right_index < right)
    {
        if (values[left_index] <= values[right_index])
        {
            temporary[output_index++] = values[left_index++];
        }
        else
        {
            temporary[output_index++] = values[right_index++];
        }
    }
    while (left_index < middle)
    {
        temporary[output_index++] = values[left_index++];
    }
    while (right_index < right)
    {
        temporary[output_index++] = values[right_index++];
    }
    for (int i = left; i < right; i++)
    {
        values[i] = temporary[i];
    }
}

static void merge_sort_range(int values[], int temporary[], int left, int right)
{
    if (right - left <= 1)
    {
        return;
    }
    int middle = left + (right - left) / 2;
    merge_sort_range(values, temporary, left, middle);
    merge_sort_range(values, temporary, middle, right);
    merge(values, temporary, left, middle, right);
}

static void merge_sort(int values[], int temporary[], int length)
{
    merge_sort_range(values, temporary, 0, length);
    print_array("merge:  ", values, length);
}

int main(void)
{
    int documents[] = {7, 2, 5, 2, 9};
    int sorted_documents[] = {2, 2, 5, 7, 9};
    const int length = 5;

    int found = linear_search(documents, length, 9);
    printf("linear result: index=%d\n", found);
    found = binary_search(sorted_documents, length, 7);
    printf("binary result: index=%d\n", found);

    int bubble_values[] = {7, 2, 5, 2, 9};
    int selection_values[] = {7, 2, 5, 2, 9};
    int merge_values[] = {7, 2, 5, 2, 9};
    int merge_scratch[5];
    print_array("start:  ", documents, length);
    bubble_sort(bubble_values, length);
    selection_sort(selection_values, length);
    merge_sort(merge_values, merge_scratch, length);
    return 0;
}
```

预期输出：

```text
linear: check index 0 = 7
linear: check index 1 = 2
linear: check index 2 = 5
linear: check index 3 = 2
linear: check index 4 = 9
linear result: index=4
binary: low=0 middle=2 high=4 value=5
binary: low=3 middle=3 high=4 value=7
binary result: index=3
start:  7 2 5 2 9
bubble: 2 5 2 7 9
bubble: 2 2 5 7 9
bubble: 2 2 5 7 9
select: 2 7 5 2 9
select: 2 2 5 7 9
select: 2 2 5 7 9
select: 2 2 5 7 9
merge:  2 2 5 7 9
```

## 搜索：逐格查，还是缩小范围

**线性查找（linear search，按顺序逐个比较）**不要求数组有序。`linear_search` 从索引 0 开始，检查 `values[i] == target`；找到就返回位置，循环完都没找到就返回 `-1`。上面的 9 在末尾，所以比较 5 次。长度为 `n` 时，最好一次比较、最坏 `n` 次比较；空间额外使用 `O(1)`。

**二分查找（binary search，每次排除一半候选范围）**要求输入已按同一规则排序。它先检查中间元素：目标更大，就把 `low` 移到 `middle + 1`；目标更小，就把 `high` 移到 `middle - 1`。两边都用闭区间，所以当 `low > high` 时没有剩余元素。

追踪程序里的查找 7：起初范围 `[0, 4]`，中点 2 是 5，目标更大，于是范围变成 `[3, 4]`；中点 3 是 7，返回 3。若对未排序的 `{7, 2, 5, 2, 9}` 直接二分，程序可能漏掉存在的值，因为“左侧更小、右侧更大”这个推断不成立。先排序是前提，不是优化选项。

长度为 `n` 时，线性查找最多检查 `n` 个元素；二分查找每次把范围缩约一半，最多约 `log2(n) + 1` 次比较，即 `O(log n)`。中点计算写成 `low + (high - low) / 2`，避免 `low + high` 在极大索引时溢出。

## Struct：把一条记录的字段放在一起

官方 Week 3 也讲 **结构体（`struct`）**。前面若用平行数组保存文档，编号和标题必须依赖“两个数组相同索引永远对应同一条记录”；只交换编号却没交换标题就会串档。`struct` 定义一个由多个字段组成的新类型，让同一条记录的值放在一起。

文件名：`records.c`。`typedef struct { ... } Document;` 定义类型 `Document`；`id` 与 `title` 是字段（成员）。数组 `documents` 里每个元素都是完整 `Document`。点号 `.` 访问结构体变量的字段；箭头 `->` 访问结构体指针所指记录的字段。

先看字段如何流动：当 `i=1` 时，`&documents[i]` 是第二条记录的地址，赋给 `record`；因此 `record->id` 等价于 `documents[1].id`，值为 9，`record->title` 等价于 `documents[1].title`，内容为 `SQL`。箭头不是另一种字段，而是“先沿指针找到记录，再取它的字段”。

```c
#include <stdio.h>

typedef struct
{
    int id;
    const char *title;
} Document;

int main(void)
{
    Document documents[] = {
        {7, "Python"},
        {9, "SQL"},
        {21, "HTTP"}
    };
    const int count = (int) (sizeof(documents) / sizeof(documents[0]));
    const int target_id = 9;

    for (int i = 0; i < count; i++)
    {
        Document *record = &documents[i];
        if (record->id == target_id)
        {
            printf("id=%d title=%s\n", record->id, record->title);
            return 0;
        }
    }
    printf("not found\n");
    return 0;
}
```

预期输出：`id=9 title=SQL`。循环每轮把 `&documents[i]`（当前完整记录的地址）交给 `record`；`record->id` 读到编号，`record->title` 读到同一条记录的标题。`const char *title` 指向字符串字面值，本例只读，不修改。结构体变量可以整体赋值、整体交换，这比维护两列平行数组更不容易把字段对错。`struct` 只定义数据形状，不会自动提供查找或排序；后续章节会用这个概念理解节点。

接下来的排序示例为了让元素比较清楚，仍只排序整数。真实记录排序时，应按 `id` 比较并移动整个 `Document`，不可只移动 `id` 而留下错配的 `title`。

## 排序：三个算法都自己动手

排序的业务动机：文档目录如果要按编号浏览，可以先排成从小到大，之后才能使用二分查找。排序不改变记录所属关系；真实目录中的 id 和标题必须作为一个整体交换，不能分开排两列。下面先用整数数组观察位置变化。

### 冒泡排序

每轮从左向右比较相邻两项。若左边较大就交换；一轮结束时，本轮最大的未归位值“冒”到右端。程序的 `end` 每轮左移，因为右侧已经就位。`swapped` 是提前结束的证据：一轮一次交换都没有，说明相邻项全有序。

以 `{7, 2, 5, 2, 9}` 第一轮为例：比较 7 和 2 后变成 `{2, 7, 5, 2, 9}`；比较 7 和 5 后变成 `{2, 5, 7, 2, 9}`；比较 7 和 2 后变成 `{2, 5, 2, 7, 9}`；7 小于 9，不交换。最大值 9 已在尾端。下一轮把 5 推到倒数第二位。

最坏需要约 `n(n-1)/2` 次元素比较，为 `O(n^2)`；如果数组已经有序，带 `swapped` 的实现一轮就结束，是 `O(n)`。比较相邻值之外，它只保留一个临时整数，额外空间 `O(1)`。不带提前结束条件的传统实现即使已排序仍做二次比较。

### 选择排序

每轮扫描尚未排序的后缀，记下最小值位置，再与后缀第一个元素交换。第一轮从 `{7, 2, 5, 2, 9}` 找到 2（索引 1），交换后为 `{2, 7, 5, 2, 9}`。第二轮从索引 1 开始，最小值仍为 2（索引 3），交换后 `{2, 2, 5, 7, 9}`。

它总是扫描约 `(n-1) + (n-2) + ... + 1` 个元素，和为 `n(n-1)/2`，所以最好、最坏的元素比较量都属于 `Theta(n^2)`。交换次数最多 `n-1`，额外空间 `O(1)`。已排序并不会让它免去扫描后缀。

### 归并排序

**归并排序（merge sort）**先把范围拆成左右两半，分别排好，再合并两个有序范围。`merge_sort_range` 用半开区间 `[left, right)`：`left` 包含，`right` 不包含。长度 0 或 1 已天然有序，所以 `right - left <= 1` 是停止递归的**基例（base case）**。否则递归处理更短的两个区间；合并时分别从两半的当前首项挑较小者写入临时数组，再把结果复制回来。

用 `{7, 2, 5, 2, 9}` 追踪拆分：`[0,5)` 拆成 `[0,2)` 和 `[2,5)`；前者拆成单项 7、2，合并为 `{2,7}`。后者拆成 5、2、9，其中 2 与 9 合并为 `{2,9}`，再和 5 合并为 `{2,5,9}`。最后合并 `{2,7}` 与 `{2,5,9}`，每次都取两个当前首项较小的一个，得到 `{2,2,5,7,9}`。

拆分过程的函数调用栈（call stack，记录尚未完成的函数调用及局部状态的运行时区域）大致是：

```text
merge_sort_range([0,5)) 暂停，等待左右结果
  merge_sort_range([0,2)) 暂停
    merge_sort_range([0,1)) 到达基例并返回
    merge_sort_range([1,2)) 到达基例并返回
  合并 [0,1) 和 [1,2)，然后返回
  merge_sort_range([2,5)) ...
左右完成后，合并 [0,2) 和 [2,5)，返回最外层
```

注意“递归调用”并不是复制一份源代码：每次调用有自己的 `left`、`middle`、`right` 等参数；子调用结束后，程序回到父调用尚未完成的位置继续执行。归并排序的递归层数约 `log2(n)`。每一层合并总共处理 `n` 个元素，故最好、最坏的元素比较量都是 `Theta(n log n)`；临时数组需要 `O(n)` 额外空间，调用栈深度 `O(log n)`。本程序由调用者创建 `merge_scratch[length]`，并将它传给 `merge_sort`；因此 scratch 容量明确等于待排序元素数。长度为 6 的独立练习要创建 6 格 scratch，不能复用只为 5 项演示准备的数组。若改成运行时输入的任意长度，则应动态分配 scratch 并检查分配失败。

## 复杂度符号：上下界不等于最好/最坏

**渐近记号（asymptotic notation）**描述输入规模 `n` 增大时，操作量的增长级别；不是秒数，也不承诺某台机器的具体时长。课堂先用“元素比较次数”作为工作单位，暂不计打印、内存分配和不同硬件速度。

- `O(g(n))` 是渐近上界：当 `n` 足够大，成本不会比某个常数倍的 `g(n)` 增长得更快。分析最坏情形时常报告这样的上界，但 `O` 本身不等于“最坏情况”。
- `Omega(g(n))` 是渐近下界：成本至少按某个常数倍的 `g(n)` 增长。分析最好情形时常报告下界，但 `Omega` 本身不等于“最好情况”。
- `Theta(g(n))` 表示同时有同阶上界和下界，也就是增长级别被夹在常数倍的 `g(n)` 之间。

因此“最好/最坏”说的是对哪些输入情况取成本；`O / Omega / Theta` 说的是数学上的界。二分查找：最好恰好中点命中，`Theta(1)`；最坏不断缩半，`Theta(log n)`，也可说最坏成本属于 `O(log n)`。若概括所有输入的最坏成本，通常写 `O(log n)`。排序对比（元素比较量）：

| 算法 | 最好 | 最坏 | 额外空间 |
| --- | --- | --- | --- |
| 冒泡（带无交换提前结束） | `Theta(n)` | `Theta(n^2)` | `O(1)` |
| 选择 | `Theta(n^2)` | `Theta(n^2)` | `O(1)` |
| 归并 | `Theta(n log n)` | `Theta(n log n)` | `O(n)` |

`n log n` 比 `n^2` 增长慢，所以大输入通常更适合归并排序；但小数组、额外内存受限等场景仍要看完整约束，不能只背一个“最快算法”。

## 改动验证与独立需求

先预测，再改动 `main` 中要查的编号为 8：线性查找应打印所有五次比较并返回 `-1`；二分查找在有序数组上应缩小范围后返回 `-1`。再把所有排序的输入改成已排序 `{2, 2, 5, 7, 9}`：冒泡只显示一轮，选择仍扫描后缀，归并仍拆分和合并。若结果不符，先检查循环边界与 `high` 是否包含在搜索范围内。

**独立做（不要照抄上面实现）**：写一个程序，输入固定的文档编号 `{12, 4, 21, 4, 18, 3}`，分别用线性查找查询 21、用二分查找查询 18，并用你选的一种排序把编号升序排列。当前范围内只使用 C 数组、循环、函数；不能调用库排序，也不要用 Python `sorted`。输入输出约定：每次查询打印找到的索引或 `not found`，随后打印升序数组；要测试存在值、不存在值、重复值、只有一个值的数组。验收：先确认二分输入确实有序；结果中每个原编号出现次数不变；数组长度为 1 时没有越界。定位提示：从纸上列出每次 `low / middle / high`，以及每轮排序后已经就位的部分。

## 常见坑

1. 未排序数组直接二分：算法不是“偶尔慢”，而是正确性前提不成立。
2. 用 `low < high` 代替 `low <= high`：会漏掉只剩一个候选元素的情况。
3. 右边界约定混用：本章二分使用闭区间，归并使用半开区间；先写清约定再推导边界。
4. 递归只写递归调用、不写基例，或递归输入没有变小：调用无法停止。
5. 把 `O` 直接翻译成“最坏”：记号是上界；最坏是输入情形，二者有关但不是同义词。
6. 把排序后的两项数组列分别排序：真实数据必须按记录整体移动；本章前面的 `struct` 示例已将编号和标题放在同一条记录中。

## 课后压缩

**一句话模型**：搜索决定怎样缩小候选；排序让数据满足更强的搜索前提；递归把大范围交给更小范围，最后由基例停下。**最小模板**：二分每轮检查中点并丢弃一半；归并先排两半再合并。**边界**：二分必须有序；`O / Omega / Theta` 是增长界，不是最好/最坏的别名。**自测**：长度翻倍时，二分大约多做几次比较？归并为何需要额外数组？
