# 00｜计算思维与 Scratch

> 原课程讲师：David J. Malan / CS50 团队，Harvard University。本文是非官方中文改编，不代表 Harvard University 或 CS50。来源与许可说明见本目录[来源与许可.md](来源与许可.md)；本改编按 CC BY-NC-SA 4.0 分享。

## 本章学什么

本章把“计算机科学”落到几件可观察的事：把问题拆成输入、处理、输出；把数、文字、颜色和声音表示成位；把解决步骤写成算法；用 Scratch 亲手搭建事件、变量、条件、循环、自定义积木和广播。

本章不要求先会数学证明，也不学 C 语法、二分查找的正确性证明、机器学习内部原理或 Scratch 的所有扩展。Scratch 的“线程”在这里指多个脚本可交错运行，不保证多个 CPU 核心并行。

**前置**：会使用浏览器和键盘即可。课程主线项目是一个小型知识文档目录：`id=1` 是 Python、`id=2` 是 HTTP，前两条记录的 `owner=7`；`id=3` 是 SQL，`owner=9`。这章先用 Scratch 做一个“查找目录”的小交互，不改真实应用或数据库。

## 1. 计算思维：先描述问题

假设需求是“输入一个编号，显示对应知识主题”。还没写代码时，先明确：

- **输入**：一个编号，例如 `2`。
- **处理**：在目录里逐条比较编号。
- **输出**：找到时显示 `HTTP`；找不到时显示“未找到”。

这三个词不是特定语言的语法，而是分析程序的办法。若输入可能是空值、文字或负数，就要决定它们如何处理；否则“写对了代码”也可能只是解决了自己脑中一个更窄的问题。

### 算法与伪代码

**算法（algorithm，解决问题的一组有限且明确步骤）**可以先用自然语言或伪代码描述。伪代码不是能直接交给 C 编译器的代码，它用接近人话的形式暴露顺序和分支：

```text
询问用户编号
对目录中的每条记录：
    如果记录编号等于用户编号：
        显示记录主题
        结束查找
如果没有任何记录匹配：
    显示“未找到”
```

**分解**是把较大的目标拆为可检查的小问题；**抽象（abstraction）**是只保留当前决策需要的信息。查目录时先只看 `id` 与 `topic`，无需把 HTTP 的协议细节也放进这个搜索问题。抽象不是“把问题说得玄”，而是明确暂时忽略什么，以及之后何时需要补回来。

### 运行时间：用输入规模描述工作量

设目录有 `n` 条记录。逐条找编号时，最好情况第一条就命中，只比较 1 次；最坏情况目标在最后，或根本不存在，要比较 `n` 次。若每次比较大致花同样时间，工作量随记录数线性增长。

CS50 使用渐近记号帮助描述增长趋势：`O(n)` 读作“大 O 的 n”，表达上界增长等级；`Ω(n)`（大 Omega）表达下界；`Θ(n)`（大 Theta）表示上下界同阶。此处只需要直观理解，不做形式化证明，也不把它误读成某台机器上的秒数。实际耗时还取决于硬件、数据布局和操作成本。

若目录已经按编号排序，可以从中间比较，每次排除一半，比较次数大约随 `log2(n)` 增长。例如 8 条记录，约 3 次减半后最多剩 1 条候选，最坏还要再比较这条记录；16 条约 4 次减半后最多剩 1 条候选。具体比较次数会受区间边界写法影响。这个办法有前提：数据必须有序，而且访问中间位置要便宜。当前目录若只是随手排列，就不能直接使用它。

**检查点**：有 100 条未排序记录，最坏逐条查找需比较多少条？最多 100 条。1000 条呢？最多 1000 条。输入扩大 10 倍，最坏比较次数也扩大 10 倍。

## 2. 计算机如何表示信息

电子设备最终处理的是有限状态。抽象地把两种状态记为 `0` 和 `1`，每个二进制位叫 **bit（位）**；8 个 bit 组成一个 **byte（字节）**。位是表示方式，不意味着所有计算机内部物理上都只有两种电压。

### 十进制与二进制

日常十进制每一位的权重是 1、10、100……；二进制每一位的权重是 1、2、4、8……。因此二进制 `1011` 表示：

```text
位：    1   0   1   1
权重：  8   4   2   1
计算：  8 + 0 + 2 + 1 = 11
```

反过来把十进制 13 变成二进制：13 可拆成 `8 + 4 + 1`，所以对应权重位写为 `1101`。一个 byte 有 8 位；若把它们当无符号整数，最小为 `00000000`（0），最大为 `11111111`（255）。

还有一种更简单但很浪费空间的表示叫一元（unary）：用重复标记表示数量，例如 `|||` 表示 3。它适合数少量物件的直觉演示，却要用 100 个标记表示 100，空间随数值本身增长；二进制则用位权组合表示数值。

不要把“某个 8 位模式”和“整数”混为一谈：位模式要经过约定才有含义。`01000001` 可按 ASCII 解读为字母 A，也可按无符号整数解读为 65。

### 文本：字符、码点与 UTF-8 字节

**字符集/字符编码**回答的是文字如何对应到数字和字节。ASCII 是早期常见约定，给英文字母、数字和控制符分配数值；例如大写 `A` 的 ASCII 数值是十进制 65，即二进制 `01000001`。ASCII 不能表示完整中文。

Unicode 为全球文字中的字符分配码点（code point），例如 `A` 是 `U+0041`，汉字“中”是 `U+4E2D`。码点不是“每个字符固定一个字节”。UTF-8 是把 Unicode 码点编码成字节序列的方式：ASCII 范围内仍为一个字节；许多汉字在 UTF-8 中占三个字节。一个用户眼里的字形也可能由多个 Unicode 码点组成，所以“字符数量”和“字节数量”不可直接当成同一个数。

### 图像：像素与 RGB

**像素（pixel）**是栅格图像的一个采样点。每个像素可用红、绿、蓝三个通道记录颜色。常见 24 位 RGB 每通道 8 位，取值 0–255；例如 `(255, 0, 0)` 是最大红、无绿、无蓝。一个 100×50 的未压缩 RGB 图像约有 5000 个像素、15000 字节像素数据，尚未计算文件头等开销。

同一批字节若按像素排列就可能表示图像；排列顺序、通道数、色彩配置都要约定。JPEG 等压缩格式会用更复杂编码缩小文件，并可能有损；压缩后并不是简单地“每像素三个原始数字”。

### 声音与视频

声音随时间变化。数字音频会按固定时间间隔采样波形，并把每次测量量化成有限位数。采样率表示每秒取样次数，位深表示每个采样值可用的精细程度；提高两者通常增加数据量，但采样并不保证完整还原人耳听到的所有声音。

视频可视作按时间排列的一帧帧图像，另可包含音轨、时间戳、字幕和压缩信息。分辨率影响每帧像素数，帧率影响每秒帧数，编码器可利用连续帧之间的相似性压缩。一个文件的扩展名并不足以揭示其完整内部表示。

**小实验**：算一张 1920×1080、每像素 24 位 RGB 的单帧原始像素数据有多少字节：`1920 × 1080 × 3 = 6,220,800` 字节（约 5.93 MiB，按 1 MiB=1,048,576 字节）。真实图片通常采用压缩，也有额外元数据。

## 3. Scratch：把步骤变成积木

Scratch 是 MIT 开发的积木式编程环境。积木仍然表达程序结构，只是编辑器替你检查括号、分号等文本语法。入口：[scratch.mit.edu/projects/editor](https://scratch.mit.edu/projects/editor)。以下是可照做的搭建清单，不是只看视频的导学。

### 实际搭建：文档目录查询器

打开编辑器，新建项目。舞台右侧是运行结果，左边是积木分类，中间是脚本区；选中角色后，给默认猫角色改名 `目录助手`。角色对话框用于显示查询结果。

在“变量”中创建 `查询编号`、`匹配数` 两个变量，并选择“适用于所有角色”或仅当前角色均可，因为本项目只有一个角色。Scratch 的变量积木负责保存可读写的值；点击绿旗后要重置它们，不能假定上次运行留下的值已清除。

在“自制积木”点击“制作一个积木”，建立带一个数字输入参数的积木：`查询 (编号)`。参数是调用者传入的一份值；在自制积木的定义内部，用参数积木读取本次收到的编号。它类似可重复调用的命名步骤，但它通过角色脚本执行，对话框/变量变化是可观察效果，不必返回一个值。

Scratch 还有会提供**返回值**的 reporter（报告器）积木：例如把“连接 `目录编号：` 和 `回答`”的椭圆形积木嵌入“说”积木的输入槽，它计算并交出一段新文本，外层“说”再显示它。这里返回值是给调用者继续使用的数据；它和“说”直接改变舞台的副作用不同。本章自制积木是命令型积木，不返回值；需要结果时可用 reporter，或像本实验一样显式更新变量。

先搭建下面这段主脚本。积木名称用文字记录，尖括号表示六边形条件积木，圆括号表示值输入槽：

```text
当绿旗被点击
将 [匹配数] 设为 (0)
询问 [查目录：请输入编号 1、2 或 3] 并等待
将 [查询编号] 设为 (回答)
查询 (查询编号)
```

然后搭建 `查询 (编号)` 的定义脚本。`如果…那么…否则`来自“控制”，`= / 或`来自“运算”，`说…`来自“外观”。每个匹配分支把计数加一：

```text
定义 查询 (编号)
如果 <(编号) = (1)> 那么
    将 [匹配数] 增加 (1)
    说 [id 1：Python，owner 7] (2) 秒
否则
    如果 <(编号) = (2)> 那么
        将 [匹配数] 增加 (1)
        说 [id 2：HTTP，owner 7] (2) 秒
    否则
        如果 <(编号) = (3)> 那么
            将 [匹配数] 增加 (1)
            说 [id 3：SQL，owner 9] (2) 秒
        否则
            说 [没有这个编号] (2) 秒
```

`回答`通常是文本；Scratch 的比较积木会按其规则比较输入。此实验只支持输入 1、2、3，复杂的输入验证留给后续语言章节。实现完后绿旗运行，输入 `2`，应显示 `id 2：HTTP，owner 7`，变量 `匹配数` 为 1；输入 `8` 应显示“没有这个编号”。

### 加上循环：遍历三个槽位

上面重复了三次 `如果编号等于…`。若目录扩大，这些分支难维护。现在用列表存放主题会更接近真实数据，但这个小实验先用数字槽位理解循环：新建变量 `序号`，在查询脚本里把查询过程替换为如下结构。每轮序号前进 1，循环结束后若没有匹配才报告未找到：

```text
将 [匹配数] 设为 (0)
将 [序号] 设为 (1)
重复执行 (3) 次
    如果 <(编号) = (序号)> 那么
        将 [匹配数] 增加 (1)
        如果 <(序号) = (1)> 那么
            说 [Python，owner 7] (2) 秒
        否则
            如果 <(序号) = (2)> 那么
                说 [HTTP，owner 7] (2) 秒
            否则
                说 [SQL，owner 9] (2) 秒
    将 [序号] 增加 (1)
如果 <(匹配数) = (0)> 那么
    说 [没有这个编号] (2) 秒
```

这段仍用条件把编号映射为主题，重点是循环次数可见：序号先 1，三轮分别处理 1、2、3。实际知识文档数据库中会有“记录”结构和查询操作；我们不在 Scratch 里伪装成数据库。

### 事件、广播与多个脚本

事件帽积木（例如“当绿旗被点击”“当收到消息”）是脚本开始执行的入口。右键绿旗脚本区域可复制脚本或新建另一组独立脚本。为了观察脚本交错执行，创建广播消息 `查询完成`：

```text
查询脚本最后：广播消息 [查询完成]

当收到 [查询完成]
说 [查询结束] (1) 秒
```

广播像在舞台上发出事件通知：发送者不必直接调用每一个接收者；所有匹配的接收脚本都可以开始运行。不同脚本的执行可能交错，动画/事件响应由此形成“并发式”体验；不能据此承诺同时执行或共享变量自动安全。若多个脚本同时修改同一变量，观察结果会受时序影响，这叫共享状态竞争；避免让查询脚本与动画脚本同时修改 `序号` 或 `匹配数`。

### Scratch 验收表

依次点击绿旗、输入 `1`、`2`、`3`、`8`，逐项确认：

| 输入 | 预期角色反馈 | `匹配数` |
|---|---|---:|
| 1 | Python，owner 7 | 1 |
| 2 | HTTP，owner 7 | 1 |
| 3 | SQL，owner 9 | 1 |
| 8 | 没有这个编号 | 0 |

之后点绿旗重跑 `2`，确认 `匹配数` 先重置再变成 1。改为 4 条记录时，循环次数和条件要一致地更新；此观察说明“硬编码的 3”是一个维护点，而不是数据库自动知道行数。

## 4. 看代码时追踪什么

运行 `查询 (2)` 时，按时间顺序追踪：

1. 绿旗事件启动主脚本；`匹配数` 变为 0。
2. `询问并等待` 暂停当前脚本，用户输入 `2` 后，`回答` 保存输入。
3. `查询` 被调用，参数槽 `编号` 在这次调用中取值 2。
4. 循环 `序号=1`：比较 `2=1` 为假；序号变为 2。
5. 循环 `序号=2`：比较为真，匹配数从 0 变 1，显示 HTTP；序号变为 3。
6. 第三轮 `2=3` 为假；循环结束。匹配数非 0，因此不显示未找到。
7. 广播 `查询完成` 后，接收脚本说“查询结束”。

每一步都能回答“谁启动了谁、输入值在哪、变量何时改变、用户看到什么”。之后读 C/Python 时继续用同样方法，只是积木会变成语句。

## 5. 独立练习：目录筛选提示

**需求**：保持三条目录记录不变，用户输入编号后，如果是 `1` 或 `3`，除主题外还提示“这是编程/数据库主题”；编号 `2` 提示“这是网络主题”；其它输入显示未找到。

**契约**：输入 `1` → `Python；编程主题`；输入 `2` → `HTTP；网络主题`；输入 `3` → `SQL；数据库主题`；输入 `0` → 未找到。每次绿旗都从计数 0 开始。

**边界**：需要考虑运行第二次时旧计数不能残留；一个编号只命中一次；不要把 owner 7 当成主题编号。先在纸上写伪代码，再搭积木。验收时四个输入都试一次，并尝试输入空字符串，明确当前实现如何反馈。

## 常见坑

- 把 `1011` 当成十进制 1011，而不是二进制 11。数制要写清楚。
- 认为所有字符一个字符恰好一个字节。Unicode 码点和 UTF-8 字节序列是两个层次。
- 以为“RGB 24 位”就是整个图片文件只占 3 字节。那是每个像素的数据量，还没乘像素数，也没计文件开销。
- 用二分查找未排序的数据。二分每次排除一半的依据是顺序关系。
- 忘记在每次绿旗启动时重置变量，导致第二次结果叠加。
- 认为广播意味着同步调用完成，或 Scratch 脚本真的同时在多个处理器上执行。它提供事件响应和交错调度，不是并行安全保证。

## 课后压缩

- 心智模型：程序把输入按明确步骤转换成输出；计算机用约定的位模式表示信息。
- 关键链路：绿旗事件 → 初始化 → 读取回答 → 调用查询积木并传参 → 循环比较 → 更新变量/输出 → 广播完成。
- 边界：UTF-8 是编码，不等于字符数；二分查找要求有序；Scratch 的事件交错不等于多核并行。
- 复习问题：1000 条无序目录记录，最坏线性查找比较几次？为什么不能直接二分？
