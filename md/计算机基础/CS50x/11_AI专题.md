## 先看完整程序

~~~python
WIN_LINES = (
    (0, 1, 2), (3, 4, 5), (6, 7, 8),
    (0, 3, 6), (1, 4, 7), (2, 5, 8),
    (0, 4, 8), (2, 4, 6),
)


def winner(board):
    for first, second, third in WIN_LINES:
        mark = board[first]
        if mark != "." and mark == board[second] == board[third]:
            return mark
    return None


def minimax(board, player, alpha, beta):
    result = winner(board)
    if result == "X":
        return 1
    if result == "O":
        return -1
    if "." not in board:
        return 0

    if player == "X":
        best_score = -2
        for position, cell in enumerate(board):
            if cell == ".":
                board[position] = "X"
                score = minimax(board, "O", alpha, beta)
                board[position] = "."
                best_score = max(best_score, score)
                alpha = max(alpha, best_score)
                if beta <= alpha:
                    break
        return best_score

    best_score = 2
    for position, cell in enumerate(board):
        if cell == ".":
            board[position] = "O"
            score = minimax(board, "X", alpha, beta)
            board[position] = "."
            best_score = min(best_score, score)
            beta = min(beta, best_score)
            if beta <= alpha:
                break
    return best_score


def choose_move(board, player="X"):
    if len(board) != 9 or any(cell not in {"X", "O", "."} for cell in board):
        raise ValueError("棋盘必须由 9 个 X、O 或 . 组成")
    if player not in {"X", "O"}:
        raise ValueError("player 必须是 X 或 O")
    if winner(board) is not None or "." not in board:
        raise ValueError("终局棋盘没有可选走法")

    best_position = None
    best_score = -2 if player == "X" else 2
    for position, cell in enumerate(board):
        if cell == ".":
            board[position] = player
            next_player = "O" if player == "X" else "X"
            score = minimax(board, next_player, -2, 2)
            board[position] = "."

            if player == "X" and score > best_score:
                best_position, best_score = position, score
            elif player == "O" and score < best_score:
                best_position, best_score = position, score

    return best_position, best_score


def main():
    board = ["."] * 9
    original_board = board.copy()
    move, score = choose_move(board, player="X")
    assert move == 0
    assert score == 0
    assert board == original_board

    print("起始棋盘：.........")
    print(f"X 选择位置：{move}（从 0 开始）")
    print(f"双方都最优时的结果分数：{score}（平局）")
    print("验证：棋盘输入未被函数修改")


if __name__ == "__main__":
    main()
~~~

预期输出：

~~~text
起始棋盘：.........
X 选择位置：0（从 0 开始）
双方都最优时的结果分数：0（平局）
验证：棋盘输入未被函数修改
~~~

棋盘使用一维 9 项列表，按从左到右、从上到下编号 0 到 8。点号表示空格。获胜组合存在 WIN_LINES 常量中；winner 依次检查每组三格是否为同一非空标记。

## 从决策树到 minimax

### 决策树：列出“如果这样，再会怎样”

决策树（decision tree）是把选择和后续结果画成分支结构。对于游戏，当前棋盘是一个状态；每个合法空格对应一个候选动作；落子后得到新的状态；再轮到对手继续选。叶节点是游戏结束的结果。

更简单的规则决策树可以是：

~~~text
如果当前有一步能获胜：
    走那一步
否则如果对手下一步能获胜：
    堵住对手
否则：
    走第一个空格
~~~

这是一套手写规则，不会搜索所有未来局面。“规则算法”不是坏东西：输入边界明确且规则足够时，它容易解释、运行快。若规则越来越多且互相冲突，决策树搜索或学习方法可能更适合。

### minimax：假设对手也会认真下

minimax（极小化极大）搜索零和、轮流行动游戏的后续局面。设 X 是最大化者、O 是最小化者：X 希望拿到尽可能大的分数，O 会选择让 X 分数尽可能低的动作。终局评分为 X 胜 +1、平局 0、O 胜 -1。

计算过程不是“预测对手一定这么走”，而是采用保守假设：每一方都会选对自己最有利的后续动作。它因此能在小型确定性游戏里找到最优动作，但树会随可选动作数和搜索深度迅速增长；更大的游戏需要剪枝、启发式、近似或学习方法。

代码里的 minimax(board, player, alpha, beta) 是普通 Python 函数。调用者传入当前棋盘和轮到谁；递归调用模拟一个候选动作，再把棋盘恢复原样。叶子返回分值，父调用取 max 或 min，最后把分值送回根节点。

### alpha-beta 剪枝

alpha-beta pruning（α-β 剪枝）是在 minimax 搜索过程中跳过不可能改变既有决策的分支。alpha 是最大化方已经能保证的下界，beta 是最小化方已经能保证的上界。当 beta 小于或等于 alpha，继续探索该分支无法改变祖先已经拥有的更好选择，于是 break。

剪枝改变搜索访问的节点数量，不改变完整 minimax 的最优分值。它不代表机器学习，也不是随机猜测。行动顺序会影响能剪掉多少分支，但在本例的小棋盘上无论如何都可搜索完。

## 追踪一次函数调用

调用入口：main 创建 9 个点号的列表，复制一份作为输入未修改的检查，然后调用 choose_move。

1. choose_move 检查长度、字符、当前棋盘不是终局。
2. 遍历位置 0 到 8。对候选位置 0，先把 board[0] 临时改成 X。
3. 递归调用 minimax，轮到 O。O 会遍历其空位，把点号暂时改成 O 并继续递归。
4. 遇到三连线时 winner 返回 X 或 O；棋盘已满无赢家时返回平局分数 0。
5. 递归每层撤销自己的临时落子，保证同一个候选分支不会污染另一个分支。
6. X 层取 max，O 层取 min；alpha/beta 界限更新后可能跳过分支。
7. 根节点比较每个合法位置得到的分数。空棋盘多个开局都能确保平局，按位置升序且只在严格更优时替换，因此稳定选中位置 0。
8. 最后 assert 检查选择、分数与原始列表；输出一局双方最优都能保持平局，而不是声称 X 必胜。

函数中修改 board 后必须恢复，是本例最容易漏的生命周期细节。列表是可变对象；递归调用接收的是同一个列表引用。若不撤销落子，兄弟分支就会继承错误状态。也可在每层复制列表，但复制成本会增加，并需要明确采用哪种方式。

## 改动与验证

- 把棋盘改为 X 在 0、1、6，O 在 3、4、8 的合法局面，轮到 X。双方棋子数相同且没有已完成连线；预期 X 在位置 2 立即获胜。
- 把棋盘改为 O 在 0、1，X 在 3、4、8，轮到 O。预期 O 选 2 立即获胜。
- 把一个输入字符改成问号：choose_move 应抛 ValueError，而不是继续把非法状态当作空格。
- 把断言 assert board == original_board 暂时改为 assert board != original_board：程序应失败。这证明断言确实检查“输入未被修改”，不是无条件通过。
- 可以加一个小函数逐行打印棋盘，观察每次模拟前后状态；打印须放在落子与撤销周围，避免把递归日志当作最终棋局。

本程序没有检查棋子数是否符合真实轮次，也不接收用户棋盘或联网对弈；它限制在合法示例状态，不是生产游戏引擎。错误棋盘的完整合法性验证属于另一个需求，不伪装成已实现。

## 从规则程序到机器学习

AI 是一个宽泛领域。手写规则、搜索、统计学习、神经网络都可能用于 AI 系统；并非所有 AI 都会学习。

机器学习（machine learning）让程序从数据或交互经验中调整预测/策略，而不是由人逐条编写每条判断。监督学习（supervised learning）用带标签示例学习映射，例如垃圾邮件与非垃圾邮件；无监督学习（unsupervised learning）在缺少人工标签时寻找数据结构或模式；强化学习（reinforcement learning）让策略通过动作、环境反馈和奖励信号改进。

强化学习里的 agent 是采取动作的学习程序；environment 返回新状态/奖励；policy 规定状态下选什么动作；reward 表达某个结果的价值。探索（exploration）尝试未充分了解的动作，利用（exploitation）选择当前估值最高的动作。只利用可能错过更好的策略；探索太多又会浪费尝试。CS50 讲义用 epsilon 表示随机探索的概率；这只是方法示意，探索机制还有其他设计。

机器学习不保证找到因果关系，也不保证训练样本代表未来用户。数据标签错、样本偏、奖励设计错误，都可能让模型学到有害或无用的行为。minimax 的结果来自显式搜索和人工定义规则，不会因为运行一局就改变参数。

## 神经网络与深度学习

神经网络（neural network）是可训练的参数化函数，由层和连接组成，把输入数字变换为输出分数/预测。这里的“节点”是数学计算单元，不是人脑细胞的数字复制品。训练会根据样本、损失函数和优化步骤调整参数，使模型在训练目标上更合适。

深度学习（deep learning）通常指使用多层神经网络学习复杂表示。图片分类可把像素转换成“属于某类”的分数；语言任务则把 token 转成向量表示并逐层计算。多层结构能力强，但也增加数据、计算资源、评估和偏差控制成本。

训练（training）阶段利用大量样本与优化过程更新模型参数，常需要 GPU、时间和数据。推理（inference）阶段把已训练参数固定，对新输入计算输出。调用在线模型 API 通常是在请求已有模型推理，不等于你把模型重新训练或改写了它的权重。

## 大型语言模型、token 和 attention

大型语言模型（Large Language Model，LLM）是在大量文本上训练的神经网络，常通过预测下一个 token 学习语言中的统计关联。token（词元）是模型处理文本的离散单位，可能是一个常见词、词的一部分、标点或其他子词片段；它与中文汉字、英文单词并非一一对应。输入长度、费用和上下文窗口常按 token 数量计量。

模型把 token 映射为 embedding（嵌入向量）：一串数字表示供网络计算的特征。相似上下文中的表示可能出现统计关联，但向量相近不自动意味着两个概念在事实、因果或道德上相同。

Attention（注意力机制）让 Transformer 在处理一个位置时，根据当前计算对输入中其他位置分配不同权重，从而建模上下文关联。Transformer 是一种神经网络架构；它不是“会查互联网”的同义词。模型回答仍取决于训练、上下文、解码策略和接入的工具。

生成时，模型根据已有上下文计算下一个 token 的概率分布，选择一个 token 后把它接到上下文，再继续预测，直到停止条件。它的直接优化目标是生成符合学习分布的序列，不是为每句话附带一个事实核查证明。

幻觉（hallucination）指生成式模型给出流畅但错误、虚构或缺乏依据的内容。模型可能编造引文、混淆版本、遗漏条件或把推断说成事实。高风险信息应回到官方文档、真实数据、测试或有资格的人验证；“听起来很自信”不是证据。

## 提示工程：改变输入，不等于改权重

Prompt（提示）是当前请求里给模型的指令和上下文。System prompt（系统提示）通常由应用设定更高层的行为约束，user prompt（用户提示）来自当前用户输入；实际优先级与处理方式取决于具体模型 API。

清晰提示通常说明任务、背景、允许使用的资料、输出格式和不确定时应如何回答。示例：“只根据下方三条课程笔记回答；先列出处编号；找不到证据时写‘资料不足’，不要猜。”它减少歧义，但不能保证模型总遵守，也不会因此更新模型参数。

Prompt engineering 是设计模型输入；fine-tuning（微调）通过继续训练更新部分或全部参数；RAG 则在生成前检索外部资料并把检索内容放进上下文。三者作用不同：改 prompt 不等于改权重；接入 RAG 不代表模型自动验证引文；微调也不保证事实永远最新。

## 本地玩具和真实模型的边界

刚才的 Python minimax 程序：

- 有完全明确的规则、合法动作和终局评分。
- 搜索有限棋盘的动作树，依据人工指定的分数选出动作。
- 每次运行不会训练参数，也不会理解自然语言。
- 不需要网络、GPU、模型权重或 API key。

LLM 则由训练好的大量参数根据 token 上下文产生概率续写。两者都能输出“选择”，但决策依据完全不同。用 minimax 演示决策树很合适；声称它是本地 AI 聊天机器人或小型 LLM 就是错误描述。

若要在机器学习课程中进一步做小实验，可以先用手写少量带标签记录比较简单规则与分类器，再观察训练集与测试集差异。本章不把一段随机规则包装成“模型训练”，也不以几条样本宣称具备泛化能力。
