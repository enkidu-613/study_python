# 08. 把基础接成一个小程序

前置：完成本系列 02–07 的实验，能够解释关键调用。现在把它们组合成自己的“知识文档目录”，不是再换一个业务，也不是复制一段完整服务器就算完成。

本章给需求、文件职责和验收条件，不预先给综合项目的成品答案。下面的文件实验只补一个前置问题：SQLite 文件关闭再打开后，数据是否还在。

## 1. 先补清内存库与文件库的差别

07 章使用 `:memory:`，没有生成磁盘数据库。要验证普通关闭、重新打开之后还能读取，数据库必须使用文件路径，并且成功提交。

Language: Python · Why: 复用本课程的 sqlite3、pathlib 与 tempfile，不引入新语言或数据库服务。

下面是自含实验，保存为 `08_reopen_database.py`，从练习目录运行 `poetry run python 08_reopen_database.py`：

```python
import sqlite3
from pathlib import Path
from tempfile import TemporaryDirectory


with TemporaryDirectory() as folder:
    database_path = Path(folder) / "catalog.db"
    connection = sqlite3.connect(database_path)
    try:
        connection.execute("CREATE TABLE documents (id INTEGER PRIMARY KEY, title TEXT)")
        connection.execute("INSERT INTO documents VALUES (?, ?)", (1, "Python"))
        connection.commit()
    finally:
        connection.close()

    reopened = sqlite3.connect(database_path)
    try:
        row = reopened.execute(
            "SELECT title FROM documents WHERE id = ?", (1,)
        ).fetchone()
        print(row)
    finally:
        reopened.close()
```

预期输出：

```text
('Python',)
```

这段没有新框架：`connect(database_path)` 打开文件库；`commit()` 是连接对象的方法，提交当前事务；`close()` 关闭连接。新的连接打开同一文件，读取已经提交的数据。外层临时目录在两次连接都关闭后才清理。

[改] 在原程序中只移除 `connection.commit()` 再运行。默认事务控制下，这次插入没有提交，关闭连接不会替你成功提交；重新打开后查不到这行，`fetchone()` 返回 `None`。本例不是显式 `isolation_level=None` 模式，不要与 07 章手写 `BEGIN/COMMIT` 的模式混用。

这个实验只验证普通关闭后重读，不证明断电恢复、备份、跨进程并发或网络数据库部署。讲义选择临时目录，所以实验结束后不会永久保留该文件。

## 2. 综合项目的输入与职责

在 `examples/cs-foundations/` 编写自己的文件，不修改现有 `app/` 服务：

```text
catalog.py          文档数据检查、数据库初始化和按 ID 读取
catalog_http.py     本地 HTTP 路径、状态码、JSON 与服务器关闭
test_catalog.py     正常、缺失、重复和回滚等测试
PRACTICE.md         运行步骤、调用过程、设计理由和一条排错记录
documents.json     已提供的三条练习数据
```

文件名不是框架魔法。`catalog_http.py` 用普通 `import` 导入 `catalog.py` 的函数；测试导入同一个函数，避免测试与实际服务各写一份查询逻辑。

业务输入仍是三条记录：ID 1 / Python / owner 7，ID 2 / HTTP / owner 7，ID 3 / SQL / owner 9。综合项目的 ID 为正整数、标题为非空字符串、owner ID 为正整数；重复 ID 应被拒绝，不静默覆盖。布尔值不当作文档 ID 接受，检查整数类型时注意 Python 的 `bool` 与 `int` 的关系。

本项目允许不同文档同名：**唯一的是 ID，不是标题。** 07 章标题唯一只是为了稳定制造事务冲突，这里请按业务约定改表结构；回滚测试可用重复主键触发冲突。

允许使用 Python 标准库和已学过的 pytest；不引入 FastAPI、ORM、向量库、大模型或 Docker。目的只是让你自己完成一次输入到结果的调用过程。

## 3. 分三次完成，不一次写整个服务

### 第一次：只做数据与查询

先实现读入 JSON、检查字段和建立文档表，写一个按 ID 查询的普通函数。参数是整数 ID，返回记录或 `None`；不存在不是崩溃，非法参数则明确拒绝。

先不启动 HTTP。用函数调用和测试确认：1 返回 Python，999 返回 `None`；重复 ID、空标题和错误类型会被拒绝。

如果从 07 章搬来数据库代码，不要照搬 `title UNIQUE`。也不要用文件读取成功代替字段校验成功：JSON 能解析，只说明格式有效，不保证它符合业务约定。

### 第二次：把查询接到 HTTP

复用 06 章的本地服务器方法，只监听 `127.0.0.1`，端口让操作系统分配。服务器启动后向当前终端显示实际 URL；用你自己的客户端代码完成请求，再正常关闭服务。

把“解析路径”“查记录”“构造响应”分开。处理器调用第一步中的查询函数，不在 `do_GET()` 里重复塞入另一份数据。

SQLite 连接不能随意跨线程使用：06 章线程服务器的请求会在不同线程处理，而默认连接会检查创建线程。可选择每次查询在当前请求线程打开同一个练习文件库，用完关闭；不要只设置 `check_same_thread=False` 就宣称并发安全。数据库初始化在请求前完成，本次仅提供只读接口。

数据库文件放在你明确指定的练习临时目录中；主程序在服务关闭之后才清理它。这样请求线程才能读到同一个文件，又不会碰到真实业务库。

| 请求 | 状态 | JSON 结果要求 |
| --- | --- | --- |
| `GET /health` | 200 | `{"status": "ok"}` |
| `GET /documents/1` | 200 | `id=1`、`title="Python"`、`owner_id=7` |
| `GET /documents/999` | 404 | `{"error": "document_not_found"}` |
| `GET /documents/nope` | 400 | `{"error": "invalid_document_id"}` |
| `GET /unknown` | 404 | `{"error": "route_not_found"}` |

本章为非法 ID 单独规定 400，与 06 章“所有不匹配都 404”的课堂演示不同。不是协议自动规定了你的路径分支，而是你现在明确了更细的接口约定。

这里没有实现登录。`owner_id` 是归属数据，不是授权机制；也不能把客户端自己填的 owner ID 当作已验证身份。若将来复用到项目，必须接入已有的服务端认证与权限检查，不能直接公开此教学服务。

### 第三次：验证失败和恢复

用数据库事务一次插入两条测试记录，第二条故意使用已有 ID。捕获约束错误后回滚，确认第一条也没有留下。测试使用自己的临时数据库，不更改服务运行时的数据。

这个测试解释的是原子性，不代表服务已经具备所有并发、备份和故障恢复能力。成功路径与失败路径都应检查实际查询结果，而不是只断言“没有抛异常”。

## 4. 测试至少覆盖哪些情况

先测试普通函数，再测试 HTTP，失败更容易定位。以下是验收条件，不是需要背诵的题目：

| 情况 | 应验证什么 |
| --- | --- |
| 正常 ID | 返回正确文档，字段类型符合约定 |
| 不存在的 ID | 普通函数返回 `None`，HTTP 转成 404 |
| 错误类型与空标题 | 数据检查明确失败，不接受布尔 ID |
| 重复 ID | 初始化拒绝；不会覆盖第一条 |
| 相同标题、不同 ID | 两条都保留，按各自 ID 可查询 |
| 事务第二次写入冲突 | 第一次新写入也被回滚 |
| 连接关闭再打开 | 同一练习文件库中已提交记录可读取 |
| 正常与失败的 HTTP 请求 | 状态与 JSON 正文都检查，不能只看 200 |
| 程序结束 | 服务器线程结束，连接与响应关闭，临时目录可清理 |

如果使用 pytest，在练习目录运行：

```bash
poetry run python -m pytest test_catalog.py -q
```

这个命令需要你先创建 `test_catalog.py`；目录初始并不附综合项目答案或现成测试。再执行自己的 `catalog_http.py`，核对一次完整请求，避免函数测试全通过但入口没有接通。

至少故意改错一项预期结果，确认测试会失败，再恢复。不要将“执行了命令但收集到 0 个测试”当作验证通过。

## 5. 怎样解释自己的程序

在 `PRACTICE.md` 里用自己的措辞写一遍：

```text
客户端给出方法和路径
-> 处理器检查路径与文档 ID
-> 普通查询函数打开练习数据库并执行参数化查询
-> 返回记录或 None，关闭连接
-> 处理器选择 HTTP 状态和 JSON 正文
-> 客户端读取字节、解码、解析、核对结果
```

再回答四个选择：为什么原始输入用列表、按唯一 ID 查找如何组织、为什么 HTTP 与查询分开、为什么两条相关写入需要事务。最后记录一个实际错误：现象、证据、原因、修复及如何证明修复有效。

不能解释的地方就回对应章节补，不要求靠术语堆砌把文档写长。
