# 03. 数据结构：文档怎么存、怎么找

> **一句话理解：数据结构是组织数据的方式；选法要看接下来最常做的操作。**

## 本章范围

本章沿用已学过的 Python 列表、字典、集合、循环、函数和条件判断；重点补上它们分别适合什么问题、引用别名会怎样影响修改，以及栈和队列的标准实现。

学：`list`、`dict`、`set`、浅拷贝与引用别名；用 `list` 表示栈、用 `collections.deque` 表示队列；用字典 `children` 表示目录树；为知识文档规定并检查数据契约。

不学：哈希表内部实现、树的递归遍历、平衡树、数据库索引、查询性能计算和复杂度证明。平均查找时间的细节留给第 04 章；本章只建立有边界的选择直觉。

贯穿数据固定为三份文档：

```python
documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]
```

每份记录必须是含 `id`、`title`、`owner_id` 三个字段的字典；`id` 必须是整数且不可重复，`title` 是字符串，`owner_id` 是整数。结构用来表达业务约定，但 Python 不会因为我们写了这段说明，就自动检查所有输入。后面的程序会明确检查重复 ID 并拒绝它，不会默默覆盖旧文档。

## 问题现场：展示、定位、去重

应用收到三份知识文档后，可能要按顺序展示全部标题、按 ID 找一份、判断一个标题是否已经看过。它们看起来都在“处理一批数据”，实际需要的动作不同：

| 需求 | 需要的动作 | 合适起点 |
| --- | --- | --- |
| 保持文档顺序并逐份展示 | 按顺序保存、遍历 | `list` |
| 给定 ID 找对应记录 | 用唯一标识定位一项 | `dict`，把 ID 映射到文档 |
| 只判断某标题是否出现过 | 检查成员是否存在，不关心顺序或重复次数 | `set` |

不要为了“查找快”把所有数据都塞进一个字典。原始列表仍然适合保留输入顺序；可以从它建立一个按 ID 查找的索引。索引是从原数据派生的结构，必须有规则处理重复键，否则会丢数据。

## 主实验：保留顺序，再建立索引

以下是完整、自含程序。它只在内存里处理给定数据，不读写业务文件、不联网、不连数据库。保存为 `examples/cs-foundations/03_document_structures.py`。

```python
from collections import deque


documents = [
    {"id": 1, "title": "Python", "owner_id": 7},
    {"id": 2, "title": "HTTP", "owner_id": 7},
    {"id": 3, "title": "SQL", "owner_id": 9},
]

documents_by_id = {}
for document in documents:
    document_id = document["id"]
    if document_id in documents_by_id:
        raise ValueError(f"重复文档 id: {document_id}")
    documents_by_id[document_id] = document

print("标题顺序:", [document["title"] for document in documents])
print("id=2:", documents_by_id[2]["title"])

seen_titles = {document["title"] for document in documents}
print("是否有 HTTP:", "HTTP" in seen_titles)
print("不同标题数:", len(seen_titles))

stack = []
stack.append("打开 Python 文档")
stack.append("打开 HTTP 文档")
print("栈顶:", stack[-1])
print("后退:", stack.pop())
print("后退后栈顶:", stack[-1])

waiting = deque(["请求 A", "请求 B"])
waiting.append("请求 C")
print("先处理:", waiting.popleft())
print("仍在等待:", list(waiting))
```

从仓库根目录运行：

```bash
cd /Users/enkidu/PyCharmMiscProject/examples/cs-foundations
poetry run python 03_document_structures.py
```

已激活独立 Python 环境时，在同一目录也可以运行 `python 03_document_structures.py`。精确输出：

```text
标题顺序: ['Python', 'HTTP', 'SQL']
id=2: HTTP
是否有 HTTP: True
不同标题数: 3
栈顶: 打开 HTTP 文档
后退: 打开 HTTP 文档
后退后栈顶: 打开 Python 文档
先处理: 请求 A
仍在等待: ['请求 B', '请求 C']
```

## 追踪每种结构在做什么

### `list`：有顺序的一串项目

`documents` 是 Python 内置 `list` 的实例，创建者是列表字面量 `[...]`。程序用循环按原顺序读每份字典，也可用下标取位置；它保留顺序并允许重复项。这里列表是原始展示顺序的来源，不要求它同时承担按 ID 定位的职责。

标题列表推导式是已学 Python 语法：逐个读取 `documents` 中的 `document`，取 `title`，并组成新列表。它不会修改原来的 `documents`。

### `dict`：从唯一键映射到对应值

`documents_by_id = {}` 创建一个空字典。后续每次 `documents_by_id[document_id] = document` 都把整数 ID 映射到对应文档。字典的键必须唯一：再次给同一个键赋值会替换原值，而不是自动保存两条同键记录。

因此主实验先执行 `if document_id in documents_by_id`。如果已存在就抛出 `ValueError`，阻止数据静默丢失。程序创建者是我们自己的循环，键检查者也是本程序；并非 `dict` 自动替我们验证“ID 不重复”。

文档记录中 `id`、`title`、`owner_id` 是三个字段名。访问 `documents_by_id[2]["title"]` 先用外层字典的键 `2` 找到文档字典，再用字段名 `"title"` 取标题。若键不存在，方括号访问会抛出 `KeyError`；本章不把错误伪装成空结果。

常见说法“字典查找永远是 O(1)”不准确。Python 字典通常在平均情形下提供快速的键查找，但这不是任何输入和运行条件下都保证固定耗时；最坏情形会更慢。精确讨论平均与最坏情形、增长量级和测量方法留给第 04 章。

### `set`：只关心“有没有”，不保留重复项

花括号集合推导式创建 Python 内置 `set` 的实例。这里它从标题列表取得所有不同标题，调用者是当前脚本；集合只保留唯一成员，因此 `len(seen_titles)` 得到不同标题数，而不是原数据行数。

`"HTTP" in seen_titles` 询问集合里是否有该成员，结果是布尔值 `True` 或 `False`。集合不适合需要原顺序或重复次数的需求；如果还需保留重复与先后，先保留列表。

### 栈：最后放入的先取出

栈（stack）是一种“后进先出”的访问规则：最后放入的项目先取出。它不是必须使用独立的 Python 类；本例直接用 `list`，`append` 把项目放到末尾，`pop` 取走末尾项目。创建者是脚本，调用者也是脚本。查看 `stack[-1]` 只读栈顶，不会移除它。

这与浏览器后退、撤销操作的历史记录相似；当只在末尾添加和移除时，`list` 是直观选择。不要把 `pop(0)` 当成队列的默认实现，本章后面会说明原因。

### 队列：先放入的先取出

队列（queue）是一种“先进先出”的访问规则。Python 标准库 `collections` 模块提供 `deque` 类，名称来自 double-ended queue（双端队列）。`from collections import deque` 导入类；`deque([...])` 调用类创建一个 deque 实例。当前脚本创建它，再用 `append` 从右端加入，用 `popleft` 从左端取出最早等待的项目。

deque 适合两端加入/取出，例如待处理请求。用 `list.pop(0)` 也能取第一个元素，但它通常需要移动后续元素；`deque.popleft()` 专门支持从左端取出。这里认识并会用 `deque`、`append`、`popleft` 即可，不要求学习它的内部实现。若只在列表末尾操作，仍然用 `list` 更简单。

## 引用别名与浅拷贝

变量名指向对象；把一个列表赋给另一个变量，并不会自动复制列表。下面是单独的完整示例，可接在练习里运行：

```python
original = [{"id": 1, "title": "Python"}]
alias = original
shallow_copy = original.copy()

alias.append({"id": 2, "title": "HTTP"})
shallow_copy[0]["title"] = "Python 入门"

print("原列表:", original)
print("别名看到相同列表:", alias)
print("浅拷贝的新外层列表:", shallow_copy)
print("外层是否同一个对象:", original is alias, original is shallow_copy)
```

精确输出：

```text
原列表: [{'id': 1, 'title': 'Python 入门'}, {'id': 2, 'title': 'HTTP'}]
别名看到相同列表: [{'id': 1, 'title': 'Python 入门'}, {'id': 2, 'title': 'HTTP'}]
浅拷贝的新外层列表: [{'id': 1, 'title': 'Python 入门'}]
外层是否同一个对象: True False
```

`alias = original` 让两个名字指向同一个列表对象，因此通过 `alias.append(...)` 添加项目，`original` 也看得到。`original.copy()` 创建新外层列表，所以后来添加元素不会进入 `shallow_copy`。

但这个列表中的元素本身是字典；浅拷贝只复制外层容器，没有递归复制其中的字典。两个外层列表仍指向同一个第一条文档字典，所以改它的 `title`，两边都看见变化。深层复制会继续复制嵌套对象，但可能有代价或不适合某些对象；需要时可检查标准库 `copy.deepcopy` 的适用边界，而不是默认深拷贝所有数据。

## 数据契约：重复 ID 必须明确处理

数据契约（data contract）是程序对输入形状和字段含义的约定。本章的契约是：每项是字典、包含三个要求字段、字段值类型符合约定、ID 唯一。它描述“什么数据可接受”；不是 Python 新语法，也不等于自动验证器。

主实验已演示重复检查。请把输入改为以下两条记录，注意它们的 `id` 都是 `1`：

```text
documents = [{"id": 1, "title": "Python", "owner_id": 7},
             {"id": 1, "title": "HTTP", "owner_id": 7}]
```

再次运行完整主实验时，应在建立索引阶段因 `ValueError: 重复文档 id: 1` 停止；后续标题、栈、队列输出不会出现。这就是本章的**失败/边界实验**：程序拒绝含重复键的数据，而不是让后一个 HTTP 覆盖先前的 Python。练完后恢复固定三条数据。

主实验依赖每条记录都包含 `id`；缺少它时，`document["id"]` 会得到 `KeyError`。那是输入违反字段约定导致的失败，不是字典查找“找不到就自动忽略”。此处不实现通用校验器，避免把范围扩成另一章。

## 目录树：先看结构，不写递归

文件夹可以包含子文件夹；子文件夹也可以继续包含子文件夹。树（tree）就是有层级的组织结构。这里用“目录名到子目录列表”的字典表达它，不实现遍历算法：

```python
folders = {
    "知识文档": ["Python", "Web", "数据库"],
    "Web": ["HTTP", "FastAPI"],
    "数据库": ["SQL"],
}
```

手动追踪：从 `folders["知识文档"]` 得到 `Python`、`Web`、`数据库`；要查看 `Web` 的下一层，再取 `folders["Web"]`，得到 `HTTP`、`FastAPI`。`数据库` 的下一层是 `SQL`。这一例子只显示父子关系；真实文件系统还要处理文件、权限和不存在的路径，不是这份字典自动提供的能力。

后续可以用程序逐层遍历目录树，但需要学习停止条件和递归等内容；本章只要求能读懂父节点与子节点的关系。树如何支持查询、查询代价如何随数据增长变化，留给后续章节。

## 跟写：加一份文档并保持规则

在主实验的固定列表末尾增加 `{"id": 4, "title": "FastAPI", "owner_id": 9}`，再运行。观察：标题顺序增加一项；按 ID 建立的字典能访问 `documents_by_id[4]["title"]`；不同标题数变成 `4`；栈与队列部分不变。

接着把新增记录的 ID 改成 `3`。运行时应看到重复 ID 的 `ValueError`，而不是继续打印索引结果。最后把 ID 恢复为 `4`。这个改动同时验证了数据契约与重复检查确实处于程序执行路径中。

## 本章小结

- `list` 保存有序项目；`dict` 用键映射值；`set` 适合只关心唯一成员是否出现。
- 字典重复赋值会覆盖旧值，所以唯一 ID 要由程序明确检查并拒绝重复。
- 赋值可能创建引用别名；浅拷贝复制外层容器，但不复制嵌套字典。
- 栈可用 `list.append/pop`；队列可用标准库 `deque.append/popleft`。目录树先读父子结构，不在本章写遍历程序。
- 下一章会拿 `documents` 和 `documents_by_id` 讨论查找与增长规模的代价；本章没有证明字典永远固定时间。
