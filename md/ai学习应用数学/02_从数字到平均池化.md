# 02. 从数字到平均池化：一步一步看懂 20×768

> 这是一篇数学桥接文档，连接“向量与余弦相似度”和第 32 章 Hugging Face Embedding。目标不是学习完整线性代数，而是看懂 Mean Pooling 的形状和除数。

## 本篇学到哪里

本篇只学习：

- 数字、向量、矩阵的关系；
- 行和列分别代表什么；
- 平均数如何应用到向量和矩阵；
- `20 × 768` 的隐藏状态如何通过逐列平均变成 768 维句向量。

本篇暂不学习：矩阵乘法、特征值、Attention 矩阵、Transformer 的训练过程和反向传播。

## 一句话心智模型

```text
数字组成向量
→ 多条向量组成矩阵
→ 每一列分别求平均
→ 多个 token 向量变成一条文本向量
```

## 1. 数字

最基础的数据是单个数字：

```text
1、2、3、4、5、6
```

数字可以进行加法和除法：

```text
1 + 3 + 5 = 9
9 / 3 = 3
```

平均数的规则是：

```text
平均数 = 所有数的总和 / 数的个数
```

## 2. 向量：一排有顺序的数字

把多个有顺序的数字放在一起，就是一个向量：

```text
[1, 2]
```

它有两个位置，因此是一个 2 维向量：

```text
第 1 个维度 = 1
第 2 个维度 = 2
```

向量相加时，相同位置相加：

```text
[1, 2] + [3, 4]
= [1 + 3, 2 + 4]
= [4, 6]
```

向量除以一个数字时，每个位置都除：

```text
[9, 12] / 3
= [9 / 3, 12 / 3]
= [3, 4]
```

因此，多条向量也可以这样求平均：

```text
([1, 2] + [3, 4] + [5, 6]) / 3
= [9, 12] / 3
= [3, 4]
```

## 3. 矩阵：多条向量上下排列

把 3 条 2 维向量上下排列：

```text
H = [
    [1, 2],
    [3, 4],
    [5, 6],
]
```

这个矩阵的形状是：

```text
3 行 × 2 列
```

按行看：

```text
第 1 行：[1, 2]
第 2 行：[3, 4]
第 3 行：[5, 6]
```

按列看：

```text
第 1 列：[1, 3, 5]
第 2 列：[2, 4, 6]
```

在 Embedding 场景中，通常约定：

```text
每一行 = 一个 token 的隐藏向量
每一列 = 一个隐藏特征维度
```

## 4. 逐列求平均

“逐列求平均”不是把所有数字混在一起求一个平均数，而是每一列单独计算：

```text
第 1 列：(1 + 3 + 5) / 3 = 3
第 2 列：(2 + 4 + 6) / 3 = 4
```

因此：

```text
3 × 2
  ↓ 每一列除以行数 3
1 × 2
```

结果是：

```text
[3, 4]
```

### 为什么除以行数，不是列数

因为每一列里面有 3 个数字：

```text
第 1 列：[1, 3, 5]  → 有 3 个数字 → 除以 3
第 2 列：[2, 4, 6]  → 有 3 个数字 → 除以 3
```

列数只是结果向量的维度。

例如 `20 × 768`：

```text
20 行  = 20 个 token
768 列 = 每个 token 的 768 个特征维度
```

逐列平均时：

```text
第 1 列：20 个数字相加 / 20 → 结果的第 1 个维度
第 2 列：20 个数字相加 / 20 → 结果的第 2 个维度
...
第 768 列：20 个数字相加 / 20 → 结果的第 768 个维度
```

最终形状是：

```text
20 × 768
  ↓ 沿 token 方向平均
1 × 768
```

## 5. 接回 Transformer

完整链路可以写成：

```text
20 个 token
  ↓ Tokenizer
20 个 token ID
  ↓ Embedding Lookup + Transformer
20 条 768 维隐藏向量
  ↓ Mean Pooling
1 条 768 维句向量
```

更准确地说，token ID 不是直接通过加减法变成语义向量。模型先根据 token ID 查找初始向量，再经过 Transformer 的上下文计算，才得到每个位置的隐藏向量。

数学形状可以记为：

```text
H ∈ R^(n × d)
```

这里先把它读成：

```text
H 是 n 行 d 列的数字矩阵
```

平均池化后的第 `j` 个维度是：

```text
v[j] = (H[1][j] + H[2][j] + ... + H[n][j]) / n
```

其中：

- `n` 是 token 数量，也是除数；
- `d` 是隐藏维度，也是最终向量长度；
- `j` 从第 1 个特征维度遍历到第 `d` 个特征维度。

## 6. 填充 token 的例外

如果短文本为了和长文本对齐而加入了填充 token，就不能把填充位置一起平均。模型会用 `attention_mask` 标记哪些位置有效：

```text
真实 token：mask = 1
填充 token：mask = 0
```

带掩码的平均可以理解为：

```text
只把 mask 为 1 的 token 向量相加
再除以真实 token 的数量
```

因此，核心规则仍然是：

> 沿 token 维度平均，保留隐藏维度；平均池化除以真实 token 数量，不除以特征列数。

## 7. 四条理解检查

1. `20 × 768` 中，20 和 768 分别代表什么？
2. 为什么逐列求平均时除以 20？
3. 为什么结果仍然是 768 维，而不是 20 维或一个数字？
4. Token ID、隐藏向量和句向量分别处于哪一步？
