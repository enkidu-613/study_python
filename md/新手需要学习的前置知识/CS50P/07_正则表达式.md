## 1. 从字符串条件走到模式

`validate.py` 第一版，先故意保留宽松判断：

```python
email = input("What's your email? ").strip()
if "@" in email and "." in email:
    print("Valid")
else:
    print("Invalid")
```

调用者是顶层程序；`input` 返回字符串，`strip` 返回去除首尾空白的新字符串，条件决定输出。
输入 `@.` 也会得到 `Valid`：两个符号存在，不等于存在用户名与域名。
官方接着用 `username, domain = email.split("@")` 拆分，再检查用户名和 `.edu` 后缀。
这里有两个局限：没有或有多个 `@` 时解包会抛出 `ValueError`；`malan@.edu` 仍可能通过粗略后缀检查。
如果只问是否有前缀，`startswith` 就够了；当规则涉及位置、字符类别、重复次数，再引入正则。

替换为第二版：

```python
import re

email = input("What's your email? ").strip()
matches = re.search(r".+@.+", email)
print("Valid" if matches else "Invalid")
```

`re.search` 是模块函数；程序传入模式字符串和待查字符串，它扫描寻找第一处匹配。
成功返回 `re.Match` 匹配对象，失败返回 `None`，不是直接返回布尔值。
`if matches` 利用对象真值分支；此时还没有要求从开头匹配，也没有要求匹配覆盖全部输入。
`pattern` 是给正则引擎读的规则；`email` 才是被检查的数据，二者不要交换。

## 2. 量词：前一个单位重复多少次

先运行一个不依赖键盘输入的实验：

```python
import re

for pattern in [r".*@.*", r".+@.+"]:
    for text in ["@", "malan@", "malan@harvard.edu"]:
        print(pattern, repr(text), bool(re.fullmatch(pattern, text)))
```

第一个模式会接受 `@`，第二个不会；`bool` 是转换布尔值的内置类调用，`repr` 是返回可读表示的内置函数，让空白或转义字符可见。
本例先使用 `fullmatch` 隔离重复次数：它要求整个字符串都符合模式，下节比较搜索范围。

| 写法 | 匹配含义 | 局部例子 |
| --- | --- | --- |
| `.` | 默认匹配一个非换行字符 | `a.b` 可匹配 `a?b` |
| `*` | 前一个单位出现零次或多次 | `ab*` 可匹配 `a`、`abb` |
| `+` | 前一个单位出现一次或多次 | `ab+` 不接受单独的 `a` |
| `?` | 前一个单位出现零次或一次 | `https?` 接受 `http`、`https` |
| `{m}` | 恰好重复 m 次 | `[0-9]{3}` 是三个数字 |
| `{m,n}` | 重复 m 到 n 次，含两端 | `[0-9]{2,4}` 是二到四个数字 |

量词约束紧挨在前面的字符、字符集或分组，不自动约束整个左侧表达式。
`ab+` 是一个 `a` 后面若干 `b`；`(ab)+` 才是整个 `ab` 重复。
官方状态机图帮助追踪“匹配字符、重复、进入下一部分”；不必把图误认为 Python 引擎实现源码。
普通量词默认贪婪，会尽量多匹配并在需要时回退，所以 `.+` 也可能吞进空格、逗号甚至额外的 `@`。

## 3. 转义、原始字符串与锚点

```python
import re

pattern = r"^.+@.+\.edu$"
for email in ["malan@harvard.edu", "malan@harvard?edu", "malan@harvard.edu.extra"]:
    print(email, bool(re.search(pattern, email)))
print(bool(re.search(r"edu$", "edu\n")))
print(bool(re.fullmatch(r"edu", "edu\n")))
```

前三行结果依次是 `True`、`False`、`False`；最后两行是 `True`、`False`。
`\.` 是正则转义，表示字面点号；单独 `.` 是通配符，不能拿来要求域名分隔点。
`r"..."` 是 Python 原始字符串字面量，减少 Python 这一层对反斜杠的处理；正则引擎仍解释其中的 `\.`。
普通字符串 `"\n"` 包含一个换行；原始字符串 `r"\n"` 包含反斜杠和字母 n，但作为正则时仍可匹配换行。
原始字符串不是“关闭正则语法”，也不能以单个未配对反斜杠结束。

`^` 是开头锚点；`$` 是结尾或末尾换行之前的锚点，二者匹配位置而非消耗字符。
加锚点能防止只匹配中间的一小段，却不会自动禁止模式内部允许的空格和多个 `@`。
上面的 `^.+@.+\.edu$` 仍会接受 `My email is malan@harvard.edu`，因为 `.+` 过于宽松。
校验完整输入时通常优先 `fullmatch`，不要把 `search` 配 `$` 当作完全相同的操作。

```python
import re

text = "email: malan@harvard.edu"
pattern = r"\w+@\w+\.edu"
print(bool(re.search(pattern, text)))
print(bool(re.match(pattern, text)))
print(bool(re.fullmatch(pattern, text)))
```

结果是 `True`、`False`、`False`：`search` 扫描任意位置，`match` 只尝试字符串开头，`fullmatch` 要求整串。
三者成功时都返回匹配对象，失败时都返回 `None`；`match` 成功也可能留下未匹配的结尾。

## 4. 字符集、缩写与选择

```python
import re

for email in ["malan@harvard.edu", "malan@@harvard.edu", "m alan@harvard.edu"]:
    print(email, bool(re.fullmatch(r"[^@]+@[^@]+\.edu", email)))
print(bool(re.fullmatch(r"\w+", "中文_123")))
print(bool(re.fullmatch(r"\w+", "中文_123", flags=re.ASCII)))
```

`[^@]+` 禁止该段出现 `@`，因此多个 `@` 被拒绝，但带空格的那一项仍会通过。
字符集 `[...]` 表示在其中选一个字符，后接量词再决定数量；`[^...]` 在集合内部表示取反。
`^` 在集合开头是取反，放在集合外面才是开头锚点，这两个位置要分清。

| 写法 | 含义与边界 |
| --- | --- |
| `[a-zA-Z0-9_]` | 一个明确限定为这些 ASCII 范围的字符 |
| `\w`、`\W` | Unicode 字母数字或下划线；以及它的反集 |
| `\d`、`\D` | Unicode 十进制数字；以及非此类字符 |
| `\s`、`\S` | 空白字符；以及非空白字符，空白不只空格 |
| `A|B` | A 或 B 两个备选模式 |
| `(A|B)` | 分组，并记录匹配的内容 |
| `(?:A|B)` | 分组但不记录内容，即非捕获组 |

最后两行实验是 `True`、`False`：默认 Unicode 下，`\w` 不等同于 `[a-zA-Z0-9_]`。
要严格限定 ASCII 数字，直接用 `[0-9]`；要改变缩写类别的匹配范围，可指定 `re.ASCII`。
在字符集中 `.` 通常表示字面点号；`-` 常表示范围，需要字面连字符时留意位置或转义。
备选项记得分组：`^(com|edu)$` 限定整个值，`^com|edu$` 则是两个不同的锚定分支。

## 5. 大小写标志与可选子域名

完整的课堂版 `validate.py`，仍然只是一个有限格式练习：

```python
import re

email = input("What's your email? ").strip()
pattern = r"\w+@(?:\w+\.)?\w+\.(?:com|edu|gov|net|org)"
matches = re.fullmatch(pattern, email, flags=re.IGNORECASE | re.ASCII)
print("Valid" if matches else "Invalid")
```

`(?:\w+\.)?` 把“子域名和点号”作为一个可选单位；因此可接受 `malan@cs50.harvard.edu`。
它最多容纳这一层可选子域，用户名也不允许 `+`、连字符和点号，不能宣称识别了全部合法邮箱。
非捕获组保留分组和量词的功能，只是不占后文 `group` 的编号。
`re.IGNORECASE` 是标准库提供的标志值，不是函数；`flags=` 把它传给匹配函数。
`|` 在这里是 Python 按位或，用于合并标志；模式字符串里的 `|` 才表示正则备选。

```python
import re

text = "first\nsecond"
print(bool(re.search(r"^second$", text, flags=re.MULTILINE)))
print(bool(re.fullmatch(r"first.second", text, flags=re.DOTALL)))
```

两行都是 `True`：`MULTILINE` 让 `^/$` 也识别逐行边界，`DOTALL` 才让点号跨越换行。
忽略大小写不会自动启用这两种行为，也不应在不知道输入契约时把所有标志一起打开。
完整邮箱语法还有更多规则；复杂正则也不能证明域名存在、收件箱可投递或输入者拥有邮箱。
真实系统应按需求选成熟校验库，并用确认邮件验证所有权；不是越长的模式就越可靠。

## 6. 清理姓名：从 split 到捕获组

`format.py` 先处理官方的 `Malan, David` 场景，也允许逗号后没有空格：

```python
import re

name = input("What's your name? ").strip()
matches = re.search(r"^([^,]+), *([^,]+)$", name)
if matches:
    last, first = matches.groups()
    name = f"{first.strip()} {last.strip()}"
print(f"hello, {name}")
```

直接 `split(", ")` 会把“逗号加一个空格”当作固定分隔符，处理不了 `Malan,David`。
这里 ` *` 是零到多个普通空格，`[^,]+` 让每段都非空且不能再包含逗号，刻意拒绝多逗号结构。
`matches.groups()` 是匹配对象的方法，返回全部捕获组组成的元组；解包后第一组是姓，第二组是名。
`matches.group(0)` 返回整个匹配；`group(1)`、`group(2)` 分别取得第一、第二捕获组。
不是用下标 0 获取第一捕获组；也不能对 `None` 调用 `groups()`，所以必须先判断成功。
输入 `Malan,David` 应输出 `hello, David Malan`；输入 `David Malan` 不匹配，保留原来的顺序。
这里只清理约定格式，不能推断全世界姓名结构；`strip` 清理后只含空白的字段也应按业务需求另行拒绝。

再运行使用赋值表达式的同一思路：

```python
import re

name = input("What's your name? ").strip()
if matches := re.search(r"^([^,]+), *([^,]+)$", name):
    name = f"{matches.group(2).strip()} {matches.group(1).strip()}"
print(f"hello, {name}")
```

`:=` 是赋值表达式：先调用 `search`，将返回对象绑定给 `matches`，再用该对象决定是否进入分支。
它不是相等比较 `==`，也不把匹配结果强制变成布尔值存进去；这里不用另一次搜索。
这是 Python 3.8 起支持的语法；读不清时保留两行写法完全正确。

## 7. 提取网址：替换不等于校验

官方以 Twitter 网址为课堂字符串；这里只处理字符串，不请求网站，不承诺平台当前账户规则。
`replace` 会替换所有符合的字面片段；`removeprefix` 只移除开头的固定片段，支持 Python 3.9 及以上。
当协议和 `www` 都可能变化时，看看 `twitter.py` 的正则替换版：

```python
import re

url = input("URL: ").strip()
username = re.sub(r"^(https?://)?(www\.)?twitter\.com/", "", url)
print(f"Username: {username}")
```

`re.sub(pattern, repl, string)` 是模块函数，返回替换后的新字符串；不原地修改 `url`。
`repl` 是本例的空字符串；默认替换所有不重叠匹配，`count=1` 可限定最多一次。
这个模式从开头去掉可选协议、可选 `www.` 和固定域名，但 `evil.com/name` 没有匹配时会原样返回。
所以有输出不代表验证成功，必须先匹配并明确提取所需组：

```python
import re

url = input("URL: ").strip()
pattern = r"https?://(?:www\.)?twitter\.com/([a-z0-9_]+)/?"
if matches := re.fullmatch(pattern, url, flags=re.IGNORECASE | re.ASCII):
    print(f"Username: {matches.group(1)}")
else:
    print("Invalid URL")
```

`https://twitter.com/davidjmalan` 会提取 `davidjmalan`；缺用户名或多出 `/status/1` 会被本例拒绝。
协议在这一版是必需的，末尾斜杠可选；这和上个替换版的输入范围不同，是显式的课堂约定。
`(?:www\.)?` 不捕获，所以用户名是 `group(1)`；如果换成捕获组，用户名编号就变成 2。
实际解析复杂 URL 应使用专门解析工具；不要把一个教学模式当作所有 URL 的安全验证器。

## 8. 周主题补齐：split 与 findall

```python
import re

print(re.split(r"[,;]\s*", "Harry, Hermione; Ron"))
print(re.findall(r"[0-9]+", "Room 12, floor 3"))
print(re.findall(r"([a-z]+)=([0-9]+)", "x=12 y=3"))
```

依次得到 `['Harry', 'Hermione', 'Ron']`、`['12', '3']` 和 `[('x', '12'), ('y', '3')]`。
`re.split` 按模式分隔并返回列表；分隔模式带捕获组时，捕获内容也进入结果，必要时用非捕获组。
`findall` 返回所有不重叠匹配：没有捕获组时是完整匹配字符串，有一个时是组字符串，有多个时是元组。
它不像 `search` 返回一个匹配对象；不要对 `findall` 得到的列表调用 `.group()`。
