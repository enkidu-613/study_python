# 03. 异常

> 心智模型：正常路径继续算结果，可预期的失败路径交给明确的处理代码；修复程序错误不等于吞掉所有错误。

## 起点、环境与边界

先会 `int(input(...))`、`while True`、`break`、`return`，能说明输入校验循环何时结束。
本章沿官方的整数输入程序，学习语法错误、运行时异常、捕获、成功分支、重试与辅助函数。
周页列出但笔记未专节展开的 `raise`，也在本章用完整代码说明。
本章不要求自定义异常类、异常链、上下文管理器或 `finally` 的完整资源清理机制。
每个 Python 代码块都是可单独解析的完整程序；故意写错语法的展示只放在 `text` 块中。
在已经激活的 Python 环境内，把相应版本存成 `number.py`，在所在目录运行：

```bash
python number.py
```

无需安装任何第三方库。不同版本分别运行，不要把同名函数和输入循环直接拼接。
交互测试的输入序列表示每次输入一行并按回车；结果是验收预期，不代表你已完成本机验证。

## 1. 语法错误与运行时异常不是一回事

先运行正确的程序：

```python
print("hello, world")
```

下面是故意错误的源代码展示，不是可运行模板：

```text
print("hello, world)
```

结束引号缺失，解析器无法把文件理解成合法语句，因此产生 `SyntaxError`。
这种同一文件内的语法错误通常会阻止文件开始执行；不要指望在文件里包一层 `try` 就能补好引号。
提示箭头指出发现问题的位置，实际缺失的符号也可能在它前面，甚至上一行。
先修引号、括号、冒号和缩进，再重跑；语法正确只是能够执行的前提，不保证结果正确。

```python
x = int(input("What's x? "))
print(f"x is {x}")
```

输入 `50` 得到 `x is 50`；输入 `cat`，程序会因 `ValueError` 中断。
代码的语法没有问题，失败发生在真正执行 `int("cat")` 时，所以是运行时异常。
异常是一种改变正常控制流的信号，包含类型和说明信息；未被处理时通常显示 traceback 并终止程序。
`ValueError` 是内置异常类，表示参数值不合适；这里字符串无法表示整数。
`NameError` 也是内置异常类，表示名字查找失败；它不是“输入不是数字”的另一种说法。
二者不需要导入，也不是需要你自己定义的普通函数。

## 2. try / except：先尝试，再按类型处理

```python
try:
    x = int(input("What's x? "))
    print(f"x is {x}")
except ValueError:
    print("x is not an integer")
```

输入 `cat` 时预期显示提示，不再出现未处理的转换异常；输入 `50` 正常显示值。
`try` 和 `except` 是语法关键字，不是校验函数。
进入 `try` 后正常执行；一旦出现匹配的异常，立即跳过 `try` 剩余部分，转到处理块。
`except ValueError` 指定要接住的异常类型，不是“什么错误都忽略”。
处理块结束后，本次 `try` 语句结束；不会自动回到刚刚失败的 `int` 重试。
若发生未匹配的异常，就向外层调用者寻找处理代码；没有处理者才终止程序。
这是失败发生之后的处理，不是解释器提前保证输入合法。

## 3. try 尽量小，但不要忘记成功前提

下面的程序语法完整，但故意保留一个运行时设计错误：

```python
try:
    x = int(input("What's x? "))
except ValueError:
    print("x is not an integer")
print(f"x is {x}")
```

输入 `cat` 后先打印错误提示，随后访问 `x` 时还会产生 `NameError`。
先计算赋值右侧，`int` 失败导致赋值根本没有完成；不是先创建了一个“空整数”。
此例顶层没有更早的 `x` 绑定，所以最后一行找不到名字。
在有旧变量的更大程序中，也可能误读到旧值；因此“预先塞个零”并不是通用修复。
关键不是把整个程序重新塞回 `try`，而是只让真正成功时才能执行依赖结果的代码。

## 4. else：明确的成功路径

```python
try:
    x = int(input("What's x? "))
except ValueError:
    print("x is not an integer")
else:
    print(f"x is {x}")
```

`else` 与 `try` 对齐，只有 `try` 正常执行完，没有异常时才进入。
它不是 `if` 的 `else`，也不是“异常处理完之后总会运行”的区域。
转换出错时只走 `except`，成功时只走 `else`；两条路径在本例互斥。
`else` 块自己发生的异常，不会被同一条语句前面的 `except` 接住。
把需要捕获的转换放进小范围 `try`，把成功后的业务放进 `else`，可以避免掩盖其他错误。

| 输入 | `int` 的结果 | 是否绑定 `x` | 随后路径 |
| --- | --- | --- | --- |
| `50` | 整数 50 | 是 | `else` 显示结果 |
| `cat` | 抛出 `ValueError` | 否 | `except` 提示失败 |
| 空行 | 抛出 `ValueError` | 否 | `except` 提示失败 |
| `3.5` | 抛出 `ValueError` | 否 | 不自动截断小数文本 |

## 5. 用循环重试，不让一次失败结束对话

```python
while True:
    try:
        x = int(input("What's x? "))
    except ValueError:
        print("x is not an integer")
    else:
        break
print(f"x is {x}")
```

依次输入 `cat`、空行、`50`：前两次提示并重新询问，最后只输出一次成功结果。
失败时没有 `break`，走到循环体末尾自然进入下一轮；不是 `except` 本身有重试能力。
成功时 `break` 退出最近一层 `while`，之后才打印 `x`。
这次可以在循环外使用 `x`，因为唯一的正常离开路径是在赋值成功之后。
输入 `-5` 也能成功转换：本例要求的是任意整数，不是严格正整数。
“类型转换成功”与“符合业务范围”是两层不同要求，后面会把它们组合。

## 6. 提取辅助函数，把重试封装起来

```python
def main():
    x = get_int()
    print(f"x is {x}")


def get_int():
    while True:
        try:
            x = int(input("What's x? "))
        except ValueError:
            print("x is not an integer")
        else:
            return x


if __name__ == "__main__":
    main()
```

`get_int` 是我们用 `def` 创建的辅助函数，不是 Python 内置函数。
`main` 调用它；它向用户要输入，必要时重复；成功后把整数返回给 `main` 的局部 `x`。
两个函数都写了 `x`，却是不同的局部名字，靠返回值交接，不共享局部作用域。
`return x` 既结束循环，也结束当前函数调用，不需要再补一个 `break`。
如果只在成功时 `break`，还需要在循环外写 `return x`，否则函数默认返回 `None`。
函数让调用者表达“我要一个整数”，不必在每次调用处重复输入恢复逻辑。

## 7. 直接返回表达式，与 pass

```python
def get_int(prompt):
    while True:
        try:
            return int(input(prompt))
        except ValueError:
            pass


number = get_int("What's x? ")
print(f"x is {number}")
```

调用者传入提示字符串；`prompt` 让函数不再硬编码只问 `x`，别处可用同一函数询问其他整数。
`return` 也要先计算右侧：转换成功才返回；转换抛异常则进入 `except`，不会返回半个结果。
`pass` 是空操作语句，为必须有语句的代码块占位；它不返回、不退出、不自行跳到下一轮。
这里重试是因为处理块结束后，外层 `while` 自然再次运行。
如果需要告诉用户为什么失败，就把 `pass` 换成清晰提示；安静重问并不总是更友好。
不要把 `pass` 和 `continue` 混淆：后者明确跳过本轮后续代码；空操作没有这种跳转效果。
不要用空 `except:` 配 `pass`：那可能隐藏拼写错误，甚至吞掉用户的中断请求。
本章只接住预期的 `ValueError`，`Ctrl+C` 和输入流结束不在此函数的恢复契约内。

## 8. raise：主动拒绝不合约定的值

```python
def require_positive(n):
    if n <= 0:
        raise ValueError("number must be positive")
    return n


try:
    count = require_positive(0)
except ValueError as error:
    print(f"Rejected: {error}")
else:
    print(f"Accepted: {count}")
```

`raise` 是抛出异常的语句。这里调用内置异常类 `ValueError` 创建异常对象，再把它抛出。
`require_positive` 接收已经得到的整数；它只负责范围，不负责读取或转换用户输入。
调用者传入 0，函数不会执行后面的 `return n`，而是把失败传播给调用处的处理块。
`except ValueError as error` 把捕获的异常对象绑定到局部名字，供提示读取，不是另建异常类型。
预期显示 `Rejected: number must be positive`；改成 `require_positive(2)` 后显示 `Accepted: 2`。
它与 `return "error"` 不同：异常打断正常返回链，调用者必须处理或让它继续传播。
不要为正常的二选一显示滥用异常；不能履行函数约定时，`raise` 才能明确表达拒绝。
这是周页 `raise` 主题的机制补充；不要求本章自己定义异常类。

## 9. 组合转换失败与范围失败

```python
def require_positive(n):
    if n <= 0:
        raise ValueError("number must be positive")
    return n


def get_positive_int(prompt):
    while True:
        try:
            n = int(input(prompt))
            n = require_positive(n)
        except ValueError as error:
            print(f"Try again: {error}")
        else:
            return n


count = get_positive_int("How many times? ")
for _ in range(count):
    print("meow")
```

现在输入 `cat`、`0`、`2`：前者在转换处失败，第二个在范围校验处失败，最后重复输出两次。
这个 `try` 中的两步都有明确的预期失败理由；仍没有把后面的打印循环笼统包进去。
这是上一章的输入校验加上异常恢复，不是换一个项目或引入第三方框架。
若只想拒绝非正数后重问，用上一章的 `if` 也可以；这里用 `raise` 演示函数如何报告契约失败。

## 10. 读 traceback：从原因回到调用链

把下面完整程序作为单独的 `traceback_demo.py` 运行，它故意不捕获异常：

```python
def get_int(prompt):
    return int(input(prompt))


def main():
    number = get_int("What's x? ")
    print(number)


main()
```

输入 `cat`，异常显示通常包含这些信息，具体箭头样式和绝对路径随 Python 版本而变：

```text
Traceback (most recent call last):
  File "traceback_demo.py", line 10, in <module>
    main()
  File "traceback_demo.py", line 6, in main
    number = get_int("What's x? ")
  File "traceback_demo.py", line 2, in get_int
    return int(input(prompt))
ValueError: invalid literal for int() with base 10: 'cat'
```

先看最后一行：异常类型是什么，说明中提到什么值；再找最后一个自己的文件和行号。
由下往上还原调用：第 2 行转换失败，由第 6 行调用，再由第 10 行启动。
traceback 是调用路径，不表示每一层都写错；最外层 `main()` 常只是入口。
不要只删掉报错那一行；先判断应该修程序、校验参数，还是在合适的调用边界捕获预期失败。
可以保留完整报错用于排查，但公开分享前应检查其中是否包含私人路径或敏感输入。

## 三遍自测与边界

以下是讲义自测，不是官方作业，不包含官方题目答案。
1. 读懂：解释转换失败为何导致赋值未完成，再指出 `else` 如何避免错误读取。
2. 跟写：重写 `get_int(prompt)`，输入 `hello`、空行、`-3`，确认最终返回整数 `-3`。
3. 独立写：写 `require_nonnegative(n)`，负数抛 `ValueError`，零和正数原样返回；由调用者捕获并提示。
4. 对照：分别输入 `abc`、`0`、`2` 到正整数读取程序，指出异常产生的确切一行。

常见坑：以为 `except` 会重试；异常后访问未赋值变量；把 `pass` 当返回；捕获范围太大。
四条理解检查：异常怎样改变执行路径？解决哪种失败？何时用普通条件即可？怎样从调用者追到抛出点？
现在能写可靠的输入辅助函数；下一章学习模块，把函数放进可导入、复用的文件。
