# 2026-07-29 学习记录

## Multi-Agent Handoff 调用链、Zed Copilot 额度与 DeepSeek V4 Flash 配置

- **第31章与知识边界**：将教学顺序整理为先运行 Subagent，再理解 Router/Handoff 和完整调用链，随后讲 ToolRuntime、Command、middleware 与 handler，最后集中处理类型错误和常见排错。明确本章主要属于 LangChain 的 Multi-Agent 应用层，同时依赖 LangGraph 的 State、运行时状态和检查点能力。
- **Handoff 调用链**：用户请求进入 Agent，模型产生 `transfer_to_support` 工具调用；工具返回 `Command(update=...)`，框架把 `ToolMessage` 和 `active_agent` 写回共享 State。下一轮模型请求前，middleware 读取 State，通过 `request.override(...)` 切换 system prompt 和 tools，再调用 `handler(updated_request)` 继续 Agent 流程。
- **middleware 参数**：在 `@wrap_model_call` 中，`request` 和 `handler` 由框架注入；`select_prompt` 等选择逻辑由开发者编写并由 middleware 主动调用。`handler` 接收被修改后的模型请求，返回下一步的模型响应。
- **Zed 编辑预测**：排查日志发现 Copilot completions endpoint 返回 `402 quota exceeded`，同时出现 `Completions limit reached`。GitHub 网页上的 Chat/Agent 状态正常，不等于 Zed 实时编辑预测额度仍可用；编辑预测与 Agent/chat 通道可能是不同的能力和额度。
- **DeepSeek V4 Flash**：确认更适合配置为 Zed 的 Agent/chat 模型；编辑器的幽灵文本预测仍可继续使用 Zed AI 或专门的编辑预测提供商。模型配置应区分 Agent 请求和 edit prediction 请求，不把两种能力混为一谈。

## 对话 90: macOS 音量控制工具搜索、BlueLM 部署、Agent 概念复习

- **macOS 独立音量控制**：使用 `trae-remote-official:github` 插件搜索 GitHub，找到 FineTune（⭐ 8366）、vorssaint-utils（⭐ 3319）、fader、MacMix 等候选。安装 FineTune 后菜单栏图标不显示，卸载后明确了"需要 GUI 窗口界面而非纯菜单栏 App"的硬性条件。
- **BlueLM-7B-Base 部署**：查询 vivo 官方模型，7B 参数，BF16 需约 16GB 显存，INT4 仅需约 6GB。端侧支持骁龙 8 Gen2/8 Gen3 等平台，有官方 4bits 量化版本。
- **InMemorySaver 复习**：LangGraph 内存检查点保存器，按 `thread_id` 保存 State 快照，只在当前进程内存中存活，重启丢失。
- **Ruff**：用 Rust 写的 Python linter + formatter，比 Flake8 快 10-100 倍，替代 Flake8 + isort + Black 的组合。
- **handler 与依赖注入区别**：handler 是中间件模式的"继续调用"函数，框架调用你、你再去调 handler；依赖注入是框架给你准备好值，你用值做事。前者控制调用链走向，后者提供资源。
- **handler 执行后**：框架回到 LLM 调用 → 可能产生 tool call → 执行工具 → 写回 State → Agent 循环再次触发 middleware → 直到无 tool call 结束。
- **Agent 含义**：给 LLM 装上"手脚和脑子"，让它能自己调用工具、多轮循环决策，而不仅是输出文字。
- **"框架调用你，你再去调它"**：用快递中转站比喻框架把 request 扔给 middleware，middleware 改完包裹后通过 handler 交还给框架继续配送。

## 学习结果

对第 31 章的 middleware/handler/Agent 循环链路理解加深，能区分中间件模式与依赖注入的本质差异；macOS 工具链实践中确认了 GUI 窗口 vs 菜单栏 App 的需求差异。
